# 判决书深度分析

围绕一份判决书，回答“法院认定了什么、依据是什么、推理怎样连接到结果、哪些地方值得进一步核实”。保留 `litigation-analysis` 调用名；每次完成一个判决文书节点，不扩展为全案研判。

## 输入与职责边界

必要输入是一份可读判决书。用户目标、关注争点、被代表方和读者为可选上下文；未指定立场时中性分析，不默认原告就是我方。判决自身可独立分析，无需为了启动而索要起诉状、证据原件或整套卷宗。

- 扫描件先由当前可用的文档读取/OCR 工具转成可定位文本，保留页码。处理同一文件不构成多材料研判。
- 用户给出多份判决并要求分别解读时逐份独立输出；要求跨文书比较或与其他证据综合判断时，交由 `legal-case-analysis` 主导。
- 判决与附件一并提供但仅要求解读判决时，只读取目标判决。目标判决不明确时先确定目标，不自动扫描同目录其他文件。
- 输入只有起诉状、证据或庭审笔录时，说明应转综合研判；若目标 Skill 不可用，给出适用入口和交接信息，不伪称已调用。
- 只有“本院认为”或主文节选时，完成可见部分分析并标记“部分分析”；缺失章节不能写成无争议或无遗漏。

## 处理流程

### 1. 建立文书定位与来源层级

记录文件、案号、法院、案由、审级、裁判日期及可读范围。以页码/段号定位；没有页码时用章节和短引文定位，不虚构行号。

全程区分：当事人主张、法院认定、判决转述的证据、分析者推断、未提及事项。文内称“原告提交合同”不等于已核阅合同原件；二审转述一审不等于已读一审原判。

按需要加载：

- 一审判决：读取 [一审抽取规则](references/judgment-first-instance-extraction.md)。
- 二审判决：读取 [二审抽取规则](references/judgment-second-instance-extraction.md)。
- 其他审级判决：沿用本流程，依原文角色、程序和主文分析，不套民事一审字段。
- 知识产权等相关判决：按争点读取 [领域阅读问题](references/domains/01-ip-case-dimensions.md)。它只帮助读懂文内论证，不提供独立的现行法结论。

### 2. 逐争点重建裁判论证

逐一对应请求/抗辩、关键事实、判决所载证据、采信理由、法院援引规则、适用过程和结论。保留对结果有影响的金额、计算口径、时间条件、证明责任分配、未采纳观点及理由。

若法院未显式归纳争点，可由分析者归纳并标注。解释决定性认定如何影响其他争点；不能只复述结论或把当事人陈述升级为事实。

### 3. 做有边界的深度评析

检查文内事实与理由是否衔接、证据取舍是否交代理由、对关键抗辩是否回应、计算是否自洽、理由与主文是否一致。每个疑点写出原文位置、观察、可能的反向解释、影响及还需核实什么。

- 可以指出文本内部的矛盾、未展开说理与潜在争议；“判决未写明”不等于“法院未审查”。
- 引用法条、司法解释或案例只转录判决实际载明内容，标注“判决援引，未作外部核验”。文中没有条文全文时不按记忆补齐；判决援引本身不证明现行有效或适用正确。
- 本节点不主动联网检索、不搜集卷宗，不给改判概率、是否上诉/再审的完整决策、报价或办案计划。需要外部法源核验或综合救济判断时，把问题交接给 `legal-case-analysis`；纯检索目标可交给当前可用的法律检索 Skill。
- 技能不执行提交、发送、签章或案件状态写回。仅在用户要求文件交付时写入指定输出位置，保留原判决。

### 4. 解释主文与告知事项

逐项解释主文、义务主体、金额、履行条件、诉讼费用及文内救济告知。复述判决记载的期限及起算条件，不以裁判日期替代送达日期，也不将模板里的固定天数作为本案期限。缺少起算事实时标记“无法据此计算具体截止日”。

### 5. 按目标交付并停在本节点

默认交付一份 [判决深度分析](templates/template-internal.md)。用户只要求客户解读或研究问题时，完成必要的文内分析后直接交付对应版本，不强制生成三份文件：

- [客户解读](templates/template-client.md)：通俗解释判决结果和理由，保留不确定性。
- [待核研究问题](templates/template-research.md)：列出文内疑点及检索命题，不冒充已经完成检索。
- [可视化](references/visualization.md)：仅在有助理解时使用，不为凑图补信息。

对外内容隐去无关的身份证号、银行账号与私密联系方式；公开教学/演示按用户用途去标识化。涉及真实个案救济或对外交付的内容保留律师复核提示。

## 交接给综合研判

需要继续处理时，附一段“判决分析交接”，无需另造完整案件报告：

| 字段 | 内容 |
|---|---|
| 来源 | 判决文件、案号、审级、原文定位方式及可读范围 |
| 已完成 | 主文摘要、决定性争点、法院认定与文内依据 |
| 待核问题 | 疑点、可能反向解释、影响及所需卷宗/检索依据 |
| 尚未核实 | 未读附件、原证据真实性、外部法源效力、送达/生效状态 |
| 后续目标 | 用户要求的综合判断及立场；未指定则如实标注 |

下游不具备时仍可完成本节点并交付上述内容；不得把“建议交接”写成“已完成检索/研判”。综合研判已有可回溯结论时复用，不重复分析整案。

## 完成检查

- 重要认定、引文、金额和疑点均能定位到判决原文；缺失处已标明。
- 各项主文及决定性争点已覆盖；当事人主张、法院认定与分析意见分开。
- 二审引用一审和判决转述证据的来源限制仍在；未作法源现行性保证。
- 未生成无来源胜率、期限、费用或综合诉讼决策；研究问题未冒充检索结果。
- 交付符合用户要求的版本；读到的是节选时不宣称整份判决分析完成。

## 依赖

可读文本分析无需脚本或第三方包。扫描判决的转换依赖当前可用的读取/OCR 工具；工具不可用时说明缺口。独立判决分析不依赖其他 Skill 安装；综合研判、检索是后续按需入口。

## 维护说明

新增领域阅读问题时遵循 [领域扩展边界](references/domains/00-HOW-TO-ADD-NEW-DOMAIN.md)，不要把新的综合业务流程塞回本节点。
