# 共享设计原则

先读取调用项目规则。画幅、内外圆角、主色、背景、内联方式和归档位置由项目或本次需求决定，不把任何个人偏好当成公开默认值。

## 内容与版式

每张图围绕一个阅读问题组织对象，可包含解释该问题所需的多个状态。用图形关系、空间位置和对象变化承载信息，文字说明必要条件和结果。数量、元素个数、标题字数不设固定指标。

优先让对象的移动、聚合、分流、数量或形态变化承担解释；标题、标签只保留识别对象、必要条件与结果。把正文再抄进图里，或用长段文字轮流显隐，不等于完成图形叙事。按读者需要看懂的任务删去重复解释，再决定是否换行；不能只把冗余句子缩小塞进画面。

前景、背景和状态变化要在实际手机宽度下可辨。用明度、色相、边界或形态建立层次，选中/未选中、变化前/后不能仅靠两种近似浅色区分；并查文字对比和非颜色线索。前后场景可通过明显的背景变化提示切换，但不规定固定色值或每张图必换颜色。图号只有在正文交叉引用、步骤导航等场景才有功能，无此用途不额外加角标占据视觉焦点。

画幅根据内容和展示宽度选择，可从横向 800×450 或方形开始。画布大小与字号一起规划；相同源字号缩到 375px 时实际字高会不同。不要把样本画幅当成通用标准。

容器用来表达归属、范围、操作区域或状态，可以嵌套。背景、渐变、圆角及阴影按表达和平台实测选择；纯白、直角、静态箭头均可使用。未测的 filter/字体/渐变组合不作兼容性保证；当前 CLI 支持范围另见工具参考。

## 文字与空间

长中文和中英混排先按语义分行，可用 `<text>` 内的 `<tspan x="…" dy="…">` 明确换行。标签需要保留原义，不能默认截断；必要时重排、扩大画幅、减少同屏信息或拆成两张图。不要用统一缩小 5% 或无限减字号修补拥挤。

在真正浏览器里等待字体就绪后测 `getBBox()`、`getBoundingClientRect()`、`getComputedTextLength()` 和 `getScreenCTM()`。字符数只能辅助初稿规划，不能证明没有重叠。检查实际缩放后的 CSS 字号及截图，记录字体栈；`document.fonts.ready` 不证明指定字体安装或跨设备一致。

减字不等于图标堆砌。减少说明后，仍用对象关系、视觉层级和留白组织画面，让读者能识别主体与变化。审图同时检查文字与文字、图形与文字、图形与图形的间距，覆盖标签、边框、连线、指针及运动中间态。存在实际覆盖时，用该时点截图说明容器包含、连接或有意遮挡的作用；解释不清或妨碍识别时，调整位置、路径或同屏对象数量，不能只凭文字没有相交就判整图通过。

边距与间隔随图形和字号安排，不强制固定 60px。文字、箭头端点和运动对象不能被意外裁切。容器内文字也要核内边距与线高，不能因边界刚好相接就算阅读舒适。

## 状态与时间

动态有明确初态、变化和结果；关键结果留可读停留，循环复位不制造错误因果。可把长过程拆成独立图，而不让读者等待整段长卷才看到主题。静态对照可更适合同时阅读的内容。

运动路径也占空间。检查移动中段、交叉点、状态交接和跨循环时点；相同位置的互斥文字需要验证其中一层实际隐藏。背景覆盖、弹窗和指针相交可有意出现，但应有测量或截图解释，不能直接忽略碰撞候选。详见 [布局验收](layout-verification.md)。

## 文件与嵌入

按项目要求输出内联 SVG 或独立文件。内联可保留 SMIL 源码，但 Markdown 渲染器或富文本格式化可能清洗它；回读最终内容再验。单篇多个内联 SVG 使用图级唯一 ID 前缀，局部 `url(#id)` 与 `aria-labelledby` 同步替换，避免同页引用串图。

需要归档时沿调用项目的既有目录；未约定可使用用户指定的输出目录。保留骨架、时码和最终 SVG。既有 `scripts/archive.sh` 是旧的逐行 Markdown 提取器，仅适合多行、每行独立起止标签的内容，不用于压缩成一行或嵌套 SVG；这些情况直接保存已核对的 SVG 源文件，避免归档器漏图。
