# 内容驱动的视觉设计

“更精致、更有设计感”是对表达质量的要求，不能直接翻译成网页、手机、仪表盘或圆角卡片。先理解内容，再选择图形语言；参考作品提供的是层次、空间和动作组织方法，不是每篇文章的外壳。

## 先确定图要说什么

在配图计划中补一句视觉主句：读者将看见哪些对象、它们有什么关系或发生什么变化。再确定主次、构图与动态/静态选择；不要从某个漂亮模板反推文章。

以下是选择线索，可混合，不是强制分类或固定模板：

| 内容要解释的事 | 可考虑的图形语言 |
|---|---|
| 概念、取舍、前后差异 | 编辑插画、大小/位置/形态对照、清楚的焦点与留白 |
| 机制、条件、聚合或分流 | 对象连续移动、重组、数量/形态变化；让去向和结果可追踪 |
| 资料、证据、来源与产物 | 材料本身的形态、层叠、标记和可回查关系，而非一律包装为应用面板 |
| 数据、比例、趋势 | 准确的尺度、标记、图例与重点；动画用于揭示变化，不扭曲数值 |
| 软件操作、界面或控件状态 | 对应产品的界面层次与操作反馈，按需使用 [UI 参考](ui-interaction.md) |
| 不需要时间顺序的关系 | 静态构图，让读者同时看到重要信息 |

如果去掉窗口标题、导航、按钮或鼠标后内容仍然成立，检查这些元素是否真的增加理解。没有作用的外壳可以直接省略。真实产品操作以来源为准；原创概念界面要在正文、图注或可见说明中表明是示意，不能虚构现有功能。

## 把精致度落实到画面

- **主体与层级**：一张图先有主视觉。重要对象通过面积、位置、明度或形态被识别；其余对象承担上下文，不让每个小图标、边框和标题等量争焦点。
- **空间与节奏**：安排对齐、内外间距、疏密与负空间。容器须表达归属、范围或状态；线须表达连接、边界或结构，不能只因“这里空”就加框和箭头。
- **对象质感**：通过实心轮廓、少量色阶、局部细节、层叠或剖面表达材料与对象。纸张、零件、数据点和界面控件可以有不同形态；不要全变成同一类卡片。描边、阴影、渐变、圆角各有用途，不是精致度的必选项。
- **视觉一致性**：同一作品的字形、图标复杂度、线宽和强调方式协调。配色与字体沿调用项目约定；样例中的色值与画幅只是该样例的选择，不复制成全局品牌配置。
- **动作与内容**：运动要说明操作、原因、数量、位置或状态的变化。能用对象变化表达的内容不反复抄成文字；关键结果留足观看时间。连续转场可保持主体身份，循环复位不捏造逆向因果。

丰富不等于细节堆砌。缩到实际阅读宽度后，主体应更容易看懂；细节可以辅助质感，不能承载读者必须读懂却看不清的信息。

## 对照与复核

关键停留帧同时审内容准确、构图、对象关系和视觉完成度，不能只看文字没有相交。动态再检查中段、触发前后、复位与连续循环；测量和未验边界沿 [布局验收](layout-verification.md)。

本 Skill 提供两种可编译的表达示例：

- [材料骨架](../assets/materials-demo.skeleton.svg) + [秒数时间轴](../assets/materials-demo.timeline.json)：实体材料的归拢与成册，无界面或鼠标。
- [界面骨架](../assets/ui-demo.skeleton.svg) + [秒数时间轴](../assets/ui-demo.timeline.json)：任务选择界面的组件和交互反馈。只在内容适用时借用。

二者都由同一个编译器生成原生 SVG/SMIL。它们不是默认风格或必交组合，也不限定配图数量、时长、配色或对象个数。不要因为例子有鼠标或纸张，就在无关内容中补同样的道具。
