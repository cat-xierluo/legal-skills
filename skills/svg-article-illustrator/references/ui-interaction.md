# UI 与微交互（条件参考）

仅在内容涉及界面、控件状态或软件操作，且 UI 有助于解释时读取。概念、机制、数据和材料可直接表现对象，先按 [视觉设计](visual-design.md) 选择表达。即使采用 UI，也不必有鼠标：只需看状态时，让组件本身变化即可；需要讲“点哪里”时再加入指针。

## 界面层次与组件

围绕内容组织画布、工作区、组件与状态。背景、内容面和选中态要在实际缩放后可辨；容器的填充、细分隔、统一的图标与字形、合理内边距比给所有对象加粗框更有作用。导航或工具栏只有存在实际任务时才保留，不为“像软件”补空白窗体。

按钮看起来可操作，计数/状态看起来像信息。未选、悬停、按下、选中、完成或等待只制作任务需要的状态，不能全屏同时闪动。真实操作按真实产品反馈；原创概念界面在正文、图注或可见说明中标明示意，`desc` 可补充，但不能仅靠不可见描述消除误解。

## 按因果编排微交互

涉及点击时，将指针与目标控件放在同一时间轴中核对：

1. 移入目标并短暂停留，目标产生需要的悬停反馈。
2. 按下时指针或目标产生轻量响应，如指针收缩、按钮下沉；不要每个控件都叠满缩放、光环和弹跳。
3. 松开时恢复按压形态。以释放为提交时点的操作在此之后更新结果；若真实产品在按下或拖动中生效，则沿真实语义编排，不强制所有交互都等 mouseup。
4. 结果在对应控件或工作区出现，保留可读停留；复位时让选择和计数一致。

示例数值是演示参数，不是所有作品的固定秒数、位移、缩放比或节奏。微交互的强度应能被看到又不盖住主要内容；触摸、键盘或无指针的状态变化也可成立。

## 变换与可运行示例

`assets/ui-demo.skeleton.svg` + `ui-demo.timeline.json` 保留静态骨架和秒数编排。它演示一组工具的选择，不表示真实产品或安装后自动运行：

```bash
python3 scripts/svg_motion.py compile assets/ui-demo.skeleton.svg assets/ui-demo.timeline.json -o /tmp/ui-demo.svg
python3 scripts/svg_motion.py validate /tmp/ui-demo.svg
python3 scripts/svg_motion.py preview /tmp/ui-demo.svg -o /tmp/ui-demo.html
python3 scripts/svg_motion.py publish /tmp/ui-demo.svg -o /tmp/ui-demo.publish.svg
```

- 指针形状的尖端在局部 `(0,0)`，缩放围绕尖端，避免按压时跳离目标。
- 同 cue 的 translate 轨先写、scale 轨后写；现有编译器从外到内分层，位移不会被缩放倍率再次放大。坐标规则见 [动态 SVG](dynamic-svg.md)。
- 按钮背景、标签、图标和需要随动的状态须在实际运动组内，不能只给尚未可见的选中层加下沉。以局部 translate 做轻压反馈时不改变布局锚点；若采用 scale，先确定缩放中心。
- 指针与点击目标相交可能有意；文字被无关对象或运动路径遮住则应修正，不能以“鼠标本来就会遮挡”忽略阅读问题。

检查移入、down、up、结果、计数和复位，确认指向与反馈一致；状态说明与真实秒数一致。编译、源码审查、静帧和用户审美认可各有边界，不能替代实际播放、DOM测量或公众号保存/真机验证。沿 [布局验收](layout-verification.md) 记录当前候选与 `NOT_VERIFIED`。
