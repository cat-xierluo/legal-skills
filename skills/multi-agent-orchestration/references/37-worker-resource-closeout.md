# Worker 运行资源收尾

本合同约束 PM 的派发、巡检和收尾动作；不新增常驻清扫器，不宣称既有脚本已自动执行下述所有检查。Git 删除继续使用 `14-pm-orchestrate.md` 的严格门禁；supervised 身份与逻辑结算沿 `23-runtime-settlement.md`，不以操作系统观察替代 Delivery。

## 1. 三种完成分别记账

1. **业务交付**：产物/head 已固定，完成协议已交付，PM 仍可待验或要求返修。
2. **运行资源收尾**：专属 CLI、辅助进程、测试进程、临时服务与端口已退出，或有明确的限时保留合同。
3. **Git 归档**：PR/集成已完成，满足原有条件后才删除分支/worktree。

业务待验、不允许 push、存在未提交修改、保留分支，均不要求一个已结束回合的 CLI 一直运行。先保存现场和续接标识，再收回可归属的运行资源；关闭进程不代表业务任务完成。`long-lived` 是分支生命周期，不是无限保活进程的许可。

## 2. 派发时建立最小资源清单

写入已有任务卡或绑定 Session Context，不另建平行任务权威。PM 记录：

- owner/执行主机、任务与 session、工作目录；supervised 另绑定原 runtime/Run/Task/Dispatch、terminal handle/incarnation。
- CLI 的 PID、开始时间、PPID/PGID、可执行文件和与终端的绑定；收尾前捕获全部后代的同类身份，避免父进程退出后失去归属。
- worker 新建的服务、监听地址/端口、测试/watch/build、浏览器任务空间与辅助进程；标明专属还是共享。后台脱离进程树的资源也必须主动登记。
- 既有用户服务/共享宿主基线、原生 session/恢复标识、产物与日志位置。只保存必要命令摘要，不记录完整环境变量、认证参数、能力凭证或任务私密正文。
- 运行资源处置 owner 与预算；显式保留须写理由、用途和复查时间。只有任务合同授权的 PM 才可处置；用户接管或 ownership 转移后重新核权。

PID、PPID=1、目录名、旧 session 名都不能单独证明归属。对缺失清单的历史资源，现场核宿主库存、进程树、cwd/启动时间、任务输出与服务日志；不能补造旧的启动证明。

## 3. 巡检判据

每次 PM 巡检同时看业务进展与运行资源。下表的时长用于触发核查，不直接授权杀进程。

| 现场状态 | PM 动作 |
| --- | --- |
| 已交付/明确完成，终端仍存活 | 核当前回合没有后续输入/调用，保存产物与恢复标识，处理 Delivery 后按原生命周期释放；待审文件保留 |
| 认证失效、取消、崩溃或明确失败，原生回合已结束 | 记录真实失败与未完成范围；在任务授权内停止/结算并释放专属资源，保留检查点，不伪造 worker_done 或业务成功 |
| deadline 到期或长时间无业务进展，但仍标记 working | 先核原生回合、工具/子进程、文件变化与后续输入；只有任务合同已授权取消或用户明确要求清理且确认已停止执行，才收尾；否则交 owner 处置 |
| TUI idle、CPU 高、spinner 刷新、无网络、旧时间戳 | 都只是线索。模型可能远端推理、等待输入或进行本地计算；不能单凭其中一项停止 |
| 用户接管、共享服务、归属不明 | 保留并列出确切对象与缺证；禁止通过原启动 ownership、进程名或旧 PID 强行认领 |
| shell 空闲且占用接近零 | 低优先级；优先回收确认结束却持续占 CPU/内存的 CLI 及其遗留资源 |

已完成且无具名后续工作的 worker 默认当轮释放，不为“可能还要问一句”长期 retain。确有即时复用需求时记录具名下一任务；显式保留运行资源须记录 owner、理由和复查时间，通常不晚于下一巡检（默认 10 分钟内）。用户明确保留期限优先；到期重新核状态，不自动杀掉已经重新工作的会话。

PM 结束当前 turn 前必须完成本轮可执行收尾，或在原任务卡记录 `CLEANUP_PENDING`、原因、owner 与下一动作。没有已经验证的实际监测器时，不能仅写“十分钟后再检查”便声称会自动执行；持续运行的接续按 `33-pm-continuation-readiness.md`。

## 4. 关闭顺序与独立后验

1. **紧邻操作重新读取身份和状态**：确认原主机/runtime、terminal incarnation、当前回合与 owner 未变，没有排队的新输入或在飞业务调用；固定 CLI 与全部已知后代的 PID+开始时间、cwd/程序、专属端口。身份或状态漂移立即停止处置。
2. **保存交接**：真实产物、未完成范围、当前 head/未提交修改、失败原因与恢复标识留在原任务中。不得为收尾强制 commit、reset、删除目录或把 failed 改为 done。
3. **使用原宿主通道**：supervised 按当前 Orca 指南处理精确 Run/Dispatch 的完成、release/stop 及 Delivery；保留现有先资源处置再 ack 的协议。external terminal 的 release 若留下 retained 状态，核当前 external owner 后再关闭精确 terminal。terminal-managed 用其精确终端；tmux 只关闭归属明确的 pane/session。GUI 只收口本任务会话或浏览器任务空间，不退出共享桌面应用。
4. **不要越过生命周期失败**：supervised 前置分页/身份查询失败时保持原有 fail-closed；release/stop 结果不明先重读同一对象，不切到原始 kill 绕过。现有 `settle` 的死进程门禁仍有效，不用 `--force` 冒充存活 worker 已死。恢复继续沿原 Task/session。
5. **正常退出优先**：已核归属的 terminal-managed/脱离终端测试残留优先正常退出或精确 PID 的 TERM，给出有界等待；仍存活时再次核开始时间及业务状态。仅对明确授权且确认失效的同一专属进程升级 KILL。禁止 `killall node`、按名称 `pkill`、猜测 PGID 后整组杀；只有完整核清进程组成员且全部为本任务专属才可作用于进程组。
6. **操作后查真实后态**：宿主库存确认精确 terminal/resource 已释放；OS 检查关闭前记录的 CLI 和全部后代身份已消失；端口不再由原进程监听。发现已重新挂到 PID 1 的同一后代仍活着，继续按原绑定处置。若端口已被别人接管，记录所有者变化，不能杀新进程。查询失败或缺少后代基线写 `NOT_VERIFIED`，不能把命令失败当作空集合。
7. **复测与写回**：记录退出回执、进程/端口结果、剩余资源与保留理由；按既有合同释放精确 provider lease，更新原任务卡。业务、资源、Git 三个维度分别报告，清理债务不得靠重跑 push/merge 消除。

`ptyKilled=true`、窗口消失、release 命令退出 0、父 PID 不见，都不是“所有子进程已经退出”的充分证据。原生 PID 不可见的远程环境，只能报告宿主已释放、OS 后态 `NOT_VERIFIED`；不能由本机列表推断远机无残留。

## 5. 负载盘点与下一波准入

- 按 owner/task 汇总资源，而不是用 `node`/`node_repl` 总数估算 Worker 数。一个共享宿主可能托管许多仍需恢复的辅助进程；没有精确映射时报告归属未知，先用宿主库存建立映射；仅对已核归属与授权的专属会话调用关闭/重置能力，无法映射则保留共享宿主及其辅助进程。
- 至少取间隔采样，记录 CPU、RSS、运行时长、进程树、系统内存压力及正在执行的验证/编译。进程 CPU 的 100% 通常表示一个逻辑核，系统负载均值不是 CPU 百分比；按当前 OS 口径解释，不把旧 load average 当实时效果。
- 每次扩波前先处理本 PM 已证可释放的遗留资源，重新运行现有内存/验证准入。负载仍高且原因未明时暂缓新派发，沿已有会话核查；不以减少在册 Worker 数代替实际资源检查。
- 不为探测负载再启动模型 Worker、全量测试或多重扫描器。本地清理不影响尚在运行的合法任务；需要暂停它们时按其任务授权或用户指令处理。

## 6. 前向核验场景

在无旧上下文的评估中，只给本合同和以下场景，要求说明动作、保留对象与缺证；这是语义评估，不能替代 OS 实测。

1. worker 已完成、PR 待审且 worktree 脏、CLI 持续高 CPU：先保存现场，核无后续工作并按生命周期回收运行资源，保留代码；不得等 merge 才收尾。
2. terminal close 成功，但关闭前记录的测试孙进程已挂 PID 1、端口仍开：继续核精确身份并处置，资源状态保持 pending；不得只报 ptyKilled=true。
3. 两小时无新日志，但工具仍在编译：保留，不能由时间推定过期；按预算与授权向 owner 处置。
4. credential expired 且回合已失败：保存未完成任务，原身份结算并回收；不得标业务完成或新造任务掩盖失败。
5. 长期分支、用户接管、共享 app-server：长期分支本身不要求 CLI 保活；用户接管/共享服务另核授权，不能按名字杀。
6. 旧 PID 已复用或 runtime/incarnation 改变：停止该对象处置，重新观察；不得把先前批准套到新进程。

生产自动化、所有 backend 的真实进程树回收和多轮稳定性须分别验证；本次规则补充不签发这些能力已实现的结论。
