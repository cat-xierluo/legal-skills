## 使用原则

本文件提供“操作”，不提供可直接套用的“个人风格句库”。固定替代表达使用几次后也会成为模板。

所有操作都限定在既有标题框架内。段落功能、临时分组和风险归类是内部分析工具，不是成稿目录；不得为了消除隐藏列表而新增、删除、改名、升降级或重排 Markdown 标题。

改写顺序：

1. 判断原句承担事实、定义、判断、例子、边界、过渡还是小结；
2. 判断问题来自内容不足、信息次序还是语言表面；
3. 选择删除、合并、直接陈述、补足对象、恢复显式结构或基于作者材料重建；
4. 回读上下两段，确认没有制造新的口癖和节奏配方。

## 六种有效操作

### 1. 删除姿态层

适用于句子只在宣布重要、提醒读者、评价自己或制造力度的情况。

```text
原：值得注意的是，这个条款非常关键。
改：这个条款会决定争议发生后由哪家法院审理。
```

若删掉前缀后只剩空话，说明原句缺少信息，应补对象和后果，不要换成“关键在于”。

### 2. 合并重复判断

适用于连续短段、同义循环和多次总结同一结论。

```text
原：入口变得顺滑。门槛也降下来了。所有人都能先动起来。
改：AI 很快就能生成一份可供讨论的初稿，起草不再需要从空白文档开始。
```

合并时保留信息量最高的一句，不追求短句点睛。

### 3. 直接陈述机制

适用于比喻、黑话和抽象评价遮住因果关系的情况。

```text
原：入口顺滑，会让人误以为整件事都变简单了。
改：初稿来得太快，使用者容易把“写得像”误认为“判断得对”。
```

不要把一个隐喻换成另一个隐喻。优先写清谁在什么条件下发生了什么误判。

### 4. 补足对象、条件和后果

适用于“很重要、很危险、很容易、通常、往往”等模糊评价。

```text
原：管辖条款最容易被略过。
改：AI 草稿里的管辖条款通常只有一行，诉讼成本和地方裁判差异要到争议发生后才显出来。
```

“通常”是否保留取决于作者有没有观察或资料支持。没有依据时改成条件句或明确为作者判断。

### 5. 恢复显式结构

适用于内容本来就是分类、步骤、责任分配或检查清单，却被上一轮去 AI 改写打散的情况。

```text
坏修复：违约责任最典型。管辖最容易略过。知识产权也容易出事。
恢复：这里先看三处：违约责任、管辖与争议解决、知识产权归属。
```

后文需要逐项展开时，可以在正文中直接使用“一是、二是、三是”或“第一层、第二层”。诚实的列举优于伪装后的排比，但不得把这些项自动升级为新的二级或三级标题。

### 6. 基于作者证据重建

适用于目标段落需要经验感，但原稿只有抽象结论的情况。

先读取作者证据卡，再决定是否加入时间、场景、立场变化或未决问题。没有材料时停止在一般分析层，不得编造：

```text
没有材料：保留“这类条款需要结合交易结构判断”。
有材料：只写用户明确提供的审查经历、触发事实和判断变化。
```

## 功能性列举、分析型例证与伪装排比

### 应保留的功能性列举

满足以下任一条件时，默认保留显式编号和必要的平行结构：

- 标题或引导句已经承诺“N 层、N 种、N 步”；
- 各项是互斥或并列的分类；
- 各项需要读者逐项执行、核对或追踪；
- 平行句式用于清楚分配主体、责任或输入输出；
- 法条、合同条款或操作清单要求格式一致。

功能性列举可以工整。检查重点是类别是否成立、粒度是否一致、顺序是否有理由。

### 不应逐项扩写的分析型例证

多个合同风险、现象或例子可能只是共同证明一个判断，并不要求读者逐项执行。出现下列特征时，不要因为项目多就恢复成连续编号段：

- 删除一项只会少一个论据，不会破坏分类、步骤或核对任务；
- 每一项都在重复“工具给出文本—材料不足—需要人判断”的同一结论；
- 项目本来有相互作用，改写后却被拆成彼此孤立的等长说明；
- 每段都先点名一个项目，再解释一遍风险，最后回到同一句能力边界。

处理这类例证时增加一层真实关系。关系只能来自源稿或作者材料，常见形式包括：

- **条件**：几个问题由同一个缺失输入触发；
- **相互作用**：付款与验收、违约与退出等安排彼此影响；
- **冲突**：一项保护会挤压另一方的使用或救济空间；
- **时间**：问题在履行、退出、争议等不同阶段显现；
- **审查与责任**：哪些信息要补、由谁复核、谁承担采用结果。

关系层不是新分类，更不能升级成小标题。若源稿没有足够材料，只把例子紧凑地放在一个句群中，明确它们只是例子；不要为了打散排比虚构一段谈判、案件或作者经历。

#### 关系证据卡

每组关系在写入正文前先在候选外填写：

```text
拟写关系：A 与 B 怎样关联？
A 的源稿锚点：原句或可定位短片段
B 的源稿锚点：原句或可定位短片段
关系本身的源稿锚点：同一处原文怎样同时提到 A、B 或共同具体变量？
关系依据：源稿明示 / 不增加新变量的必要推论 / 外部常识 / 新增分析
判断强度：源稿是可能、条件判断还是确定结论？改稿是否变强？
处理：写入 / 降强度后写入 / 压缩列举 / AUTHOR_MATERIAL_NEEDED
```

只有关系本身存在源稿锚点时才可以写入。A 与 B 各自有材料，不证明 A 与 B 的关系有材料；“必要推论”只允许复述已存在的关系，不能新建时间顺序、程序路径或共同目标。法律常识即使正确，也不能在纯润色任务中自动变成作者的材料。例如，源稿分别讨论违约金与管辖，不能自行补成“违约发生后进入诉讼，再由管辖影响程序”；源稿分别讨论知识产权对合作继续的影响与解除条件的松紧，也不能自动合成共同的“继续／退出”关系。源稿只说付款节奏反映信任与议价能力，不能自行补成里程碑付款；源稿只说保密期限受关系影响，不能自行推出经营限制或技术使用后果。

关系证据卡是防止“去清单化”变成内容幻觉的停止闸门。卡片无法填写时压缩，不靠专业常识把段落撑长。

卡片结论不能被解释给读者。不要在成稿中写“源稿没有足够材料支持相连”“仍按源稿导航”或“这些不是逐项检查任务”。前两句泄漏编辑过程，后一句是在回应改写指令。正确处理是：没有关系就让例子各自成立，能压缩就压缩；补料需求只在报告中标记。

共同上位词也不能替代证据。“两项都属于合同风险”“都要结合具体合作”“都在合作偏离或履行时暴露”“都需要专业判断”，只是把例子重新装进一个更大的词，不说明两端如何作用。只有源稿明确让同一个具体变量同时约束两端，或一端改变另一端的解释、效果、顺序，才算关系。一组关系通过就用一组，其余例子可以在同一段各自成立。

### 应处理的伪装排比

以下情况说明 Agent 只是把序号藏了起来：

- 连续段落分别以“最典型、最容易、也容易、类似的还有”开头；
- 没有证据支持“最”字排名，只为避免相同句式而制造等级；
- 各段承担同一话语功能，却故意使用不同口语标签；
- 删除“一是、二是、三是”后，项目数和展开顺序完全没变；
- 每段结尾都补一条短句，假装形成不同节奏。

处理时二选一：恢复明确列举，或改变信息组织方式，例如围绕一个真实场景按因果或时间推进。禁止只改段首词。

对分析型例证组，“改变信息组织方式”的具体落点是：让各段讲**不同的机制或错法**（例如量级、时点、默认选项本身偏），把共同的结论、能力边界或“AI 给得出措辞给不出判断”这类收束集中到段末只说一次；段首句式也应错开。仅去掉“最典型／最容易／也容易”但保留“点名 → 解释风险 → 落到同一判断”的同壳走三遍，仍属潜在排比，会被用户识别为只换措辞的伪修复。

“改变信息组织方式”只指标题之下的正文推进，不包括改造标题体系。如果原稿只有一个小节，就在这个小节内部重组；不要把分析得到的四类问题变成四个新标题。

## 常见无效修复

| 技术负债 | 无效修复 | 为什么仍像 AI | 正确方向 |
|---|---|---|---|
| 禁词替换 | “窄”换“局限” | 句子功能没变 | 直接说明遗漏了什么 |
| 否定模板绕行 | “不是 X 而是 Y”换成“与 X 不同，Y 更重要” | 对比骨架仍在 | 写定义、条件或后果 |
| 显式列表去序号 | “一是/二是/三是”换成三个评价性段首 | 形成隐藏列表和假排名 | 恢复序号或重组场景 |
| 分析例证逐项扩写 | 每个风险点都写成“名称—解释—仍需判断” | 论据被伪装成清单，段落只换对象 | 按真实关系合并；没有关系材料时压缩成一句或一段 |
| 去假排名但同壳仍在（潜在排比） | 去掉“最典型／最容易／也容易”但保留“点名 → 解释风险 → 落到同一判断”同一壳走 N 遍 | 段首词换了，但三段的骨架、信息组织、判断落点完全相同；属只换措辞的伪修复 | 让各段讲不同的机制／错法（量级、时点、默认选项偏…），把共同结论／能力边界集中到收束句只说一次，段首句式也错开 |
| 语义骨架换词 | “能做 X 但不能 Y”改成“可以 X，却仍需 Y” | 逻辑功能没有变化，只换连接词 | 后文改写条件、过程、相互作用或后果 |
| 关系层补料 | 为连起两个例子新增审查因素、时间顺序、共同目标或后果链 | 文本更顺，但作者没有提供这层连接 | 填关系证据卡；没有“关系本身的源稿锚点”就各自说明 |
| 判断强度升级 | “我仍有保留”改成“这个判断下得太早” | Voice 匹配变成替作者提高声量 | 保持源稿的确定性、频率和适用边界 |
| 证据卡泄漏 | “源稿材料不足，所以两项不再相连” | 把候选外合规过程写给读者，形成报告腔 | 直接保留两个独立判断；原因只写报告 |
| 宽泛伪关系 | “两项都属于风险，都要结合具体合作” | 只有上位标签，没有相互作用或共享具体变量 | 各自说明；仅连接源稿明确支持的一组 |
| 金句压缩逃逸 | “工具退场，留下判断与责任” | 重复功能没有消失，只被压短并口号化 | 删除回声；保留一个完整结论 |
| 强加口语 | 增加“说实话、搞清楚、反咬一口” | 作者没有说话，只多了表演 | 保留原语域，补具体对象 |
| 强加比喻 | 为每个抽象概念配生活化比喻 | 比喻密度变成人设模板 | 只有解释确实更清楚时使用 |
| 强加第一人称 | 把一般判断改成“我发现” | 虚构认识来源 | 需要作者材料，否则保持一般分析 |
| 节奏配方 | 每两段加一句短句金句 | 段落开始服务节拍 | 让句长服从信息需要 |
| 弹性词配额 | 机械加入“往往、可能、某种程度” | 不确定性没有对象 | 写清未知事实和适用边界 |
| 同义词分散 | 同一对象轮换叫系统、平台、工具、方案 | 指代不稳，像自动改写 | 使用最准确的同一名称 |

## 交付前反向检查

不要只问“旧问题删掉了吗”，还要问“改写制造了什么”：

- 是否把清楚的分类改成了含混的自然段？
- 是否把只用于举证的一组例子扩成了整齐的编号段？
- 是否至少有一处由例子之间的真实关系推动，而不是逐项从零启动？
- 每组新增关系是否都有两端源稿锚点？是否偷用了模型自身的专业常识？
- 是否出现没有依据的“最典型、最容易、最重要”？
- 是否增加源稿中不存在的经历、感受、立场或亲密语气？
- 是否从禁词表逃到另一组固定替代表达？
- 是否为了长短句变化拆坏了一个完整判断？
- 是否把专业表述降格成网络口语或过度比喻？
- 是否复制了 voice anchor 的原句、标题或独有意象？
- 是否跨章节反复使用“工具能力—转折—人的判断／责任”骨架，只改变了词面？
- 是否把源稿的保留、可能性和未知写成了更强的裁断或必然后果？
- 是否把内部归纳出的组别写成新标题，或改动了源稿标题行？
- 是否把源稿、导航保护、证据卡、材料不足、扫描或交付状态写进了读者正文？
- 是否用“都属于风险／都需判断／同在某阶段”等上位词冒充真实关系？
- 是否把重复判断压成短句、对比金句或口号，而不是删除重复功能？
- 去除“最典型／最容易／也容易”等假排名后，三段是否仍走“点名 → 解释风险 → 落到同一结论”的同壳？若是，应改结构为不同机制驱动，而不是只换段首词。

任一项为“是”，回到句子功能和作者证据重新处理，不得仅做第二轮同义替换。
