## 节奏从哪里来

自然节奏来自信息变化，不来自预设的长短句序列。不要使用“长句—长句—短句点睛—长句—短句收尾”之类配方，也不要规定每段必须 3—6 句。

句子长度应服从功能：

- 定义需要完整边界，可能较长；
- 条件和例外应与结论保持可见联系，不宜随意拆开；
- 分类和步骤可以保持平行，便于核对；
- 转折只有真的改变方向时才值得独立成句；
- 短句只在信息本身需要停顿时使用，不能承担“制造人味”的任务。

## 句子层检查

### 1. 一个句子承担多少任务

标出主语、动作、对象、条件和结果。出现三层以上嵌套时，检查是否存在两个独立判断；存在才拆分。不要按字数机械拆句。

### 2. 短句是否有独立信息

下列短句常只是姿态：

- “这件事。”
- “答案很清楚。”
- “问题也出在这里。”
- “这才是关键。”
- “值得停下来想想。”

如果短句不能独立回答“发生了什么、作者判断什么或边界在哪里”，合并或删除。

### 3. 标点是否表达真实关系

- 逗号：同一判断内部的停顿；不要在短动宾后随意加逗号。
- 分号：并列项内部已有逗号，或需要保留清楚的平行关系。
- 破折号：补充、转向或解释；不要把它当成“高级感”标点。
- 冒号：前文确实承诺解释、列举或定义时使用。

### 4. 口语是否属于作者

“咬你一口、埋雷、漏水、跑起来、入口顺滑”并不会自动增加人味。检查这些词是否来自作者样本、是否让机制更清楚、是否适合目标语域。三个条件不能同时满足时，改回直接表达。

## 段落层检查

### 1. 每段先标功能

使用以下标签之一。标签只用于分析，不能变成交付正文里的标题、编号或导航：

- `FACT`：事实或材料；
- `EXPERIENCE`：用户提供的经历或观察；
- `JUDGMENT`：作者判断；
- `MECHANISM`：因果、条件或运行机制；
- `EXAMPLE`：具体例子；
- `BOUNDARY`：适用范围、未知或例外；
- `TRANSITION`：承接前文并引出新问题；
- `SUMMARY`：回收本节已经证明的内容。

连续三段都是 `TRANSITION` 或 `SUMMARY`，通常说明文章在靠姿态推进。连续三段功能相同且段首换着说“最典型、最容易、也容易”，属于潜在列表。

连续例子段也要区分用途：读者需要逐项核对时，平行结构帮助使用；例子只用于说明一个判断时，连续三段以上都采用“点名对象—解释风险—回到同一结论”的节拍，属于编辑制造的同构。此时先检查例子之间的条件、相互作用、冲突、时间或责任关系，不要只调整长短句。每组关系必须先有双端源稿锚点；模型自身的专业常识不能用来填满段落。

### 2. 检查段落动力

自然承接常见于：

- 复用上一段的核心对象；
- 回答上一段留下的问题；
- 补充条件、例外或后果；
- 沿时间、因果或任务顺序推进。

弱承接常见于：

- “下面来看”“回到开头”“你会发现”；
- 每节都先评价问题重要，再进入内容；
- 用短句金句结束上一段，再从零启动下一段；
- 用“更重要、真正、最危险”制造没有证据的层级。

### 3. 段落长度不设配额

一段一句可以成立，前提是该句承担明确的转向或结论，并且全文没有连续复制这种效果。长段也可以成立，前提是所有句子围绕同一判断展开，读者能追踪条件和对象。

## 重复何时应保留

重复不是天然的 AI 痕迹。以下情况可保留：

- 定义中的关键词需要保持一致；
- 法律主体、术语和责任名称不宜轮换同义词；
- “第一层、第二层、第三层”等帮助读者追踪分类；
- 步骤、检查清单和合同条款需要格式一致；
- 有意重复用于建立清楚的对照，且次数有限、语义递进真实。

以下情况应处理：

- 重复只为制造气势；
- 每项信息粒度不同，却被强行写成同构句；
- 连续段落开头承担同一评价功能；
- 句子反复总结已说过的观点；
- 为避开字面重复而轮换同义词，导致指代漂移。
- 不同章节反复采用“AI／工具能做某项表层任务，但人的判断、经验或责任仍不可替代”的关系骨架，后文没有增加新的机制。

## 修复顺序

1. 先确定段落功能和信息次序。
2. 判定多项目结构是功能性列举还是分析型例证；前者保留，后者检查关系层。
3. 对分析型例证，优先按真实条件、相互作用、冲突、时间或责任重组；材料不足时压缩，不虚构关系。
4. 合并没有独立信息的短句和段落。
5. 拆分确实包含两个独立判断的长句。
6. 删除姿态性过渡和无依据的排名词。
7. 最后才调整标点与局部语序。
8. 从头朗读，检查是否出现新的固定节拍或换词后的重复语义骨架。

以上修复全部在原有标题框架内完成。不要用新增小标题来代替段落承接，也不要为了看起来更清楚而把正文分析标签写进成稿。

不要为了“长短错落”而逆转上述顺序。

## 交付清单

- [ ] 句长由信息功能决定，没有固定序列。
- [ ] 连续短段都具有独立信息，不只是强调和转场。
- [ ] 定义、分类、步骤和责任分配的平行结构得到保护。
- [ ] 分析型例证没有被逐项扩成同功能、同节拍的编号段。
- [ ] 例子之间的关系来自源稿或作者材料；材料不足时没有虚构场景。
- [ ] 每组关系都有两端源稿锚点，没有新增审查变量、因果后果或判断强度。
- [ ] 没有把显式列表改成假排名或隐藏列表。
- [ ] 没有为了口语感强加比喻、网络词或第一人称。
- [ ] 段落之间通过对象、因果、时间或问题承接。
- [ ] 同一“能力—限制—人的判断／责任”语义骨架没有跨节反复承担相同功能。
- [ ] 专业术语和同一对象没有被同义词轮换破坏。
- [ ] 标点表达真实语法关系，图片行和 Protected Spans 未变。
- [ ] 二级、三级及其他 Markdown 标题行的文字、层级、编号和顺序未变，也没有新增分析型标题。
