# 总览文档生成提示词

基于课程大纲、manifest 的 `source_authority` 与 `overview` 分配生成课程总览，帮助学习者快速了解课程全貌。总览是读者成品，不显示 source refs、素材编号或生成审计信息。

输出文件必须使用已经确定的真实课程名称，例如 `00 法律人 Agent 与 Skill 办案实务 - 总览.md`；说明字段所用的 `[课程名称]`、`TBD`、`TODO` 不得原样进入文件名或正文。

## 核心要求

1. **段落式写作**：以段落形式为主，避免把总览写成提纲堆砌
2. **全面覆盖**：涵盖课程概述、学习目标、课程结构、学习路径
3. **段落式展开**：每个部分都以段落形式详细阐述
4. **客观陈述但不抹去证据边界**：禁止模糊的"讲者/讲师/主讲人"指代，以及"原文中/根据原文/现场演示/课程现场/本次演示/后续演示/演示中/现场问答"等转播框架；事实性内容直接呈现，个人判断、产品自评、事故转述和时间预测使用“课程判断/案例描述/本次运行”保留其认识论边界，不得改写成无条件客观事实
5. **避免套话**：根据课程实际内容组织语言，不使用固定的过渡词（如"首先...其次...最后..."），确保不同课程的总览各有特色
6. **术语一致**：如已提供用户词典，保持课程大纲中的校正结果，统一使用词典中的正确术语写法，不恢复转录稿中的近似误写
7. **专有名称保真**：保留 Skill 名称、工具名、项目名、产品名、命令名、API、文件名和框架名的原始语言与大小写；原文或用户词典中是 `Course Generator` 等英文专有名称时，不翻译成中文
8. **图片资产保真与总览配图克制**：只插入 manifest `overview.image_ids` 声明的图片，按声明顺序使用原始 Markdown，不改 URL、不改 alt；归属章节、`asset_only` 或 `skip` 的图片不要在总览重复插入
9. **封闭来源**：不为让总览更完整而补充原文外的受众收益、行业背景、产品能力、实施步骤、缩写释义、商业价值或趋势判断；来源中的可能性、举例和保留意见保持同等语气。单个仓库、一次运行、一个团队或一张截图里的数字只能写成该样本事实，不得外推为“常见规模”“普遍适用”“行业惯例”“标准做法”或“属于常态”
10. **书稿素材取向**：总览应指出课程中最有后续写作价值的核心问题、关键方法论或实践经验，但不新增独立素材索引
11. **成品清洁**：来源里的课堂称呼、重复主语、残句和"这样的一个/比如说/就是说/我们我们/什么什么"等逐字稿赘词必须重写；不要在成品中写“原措辞不匹配”“统一改为”“修订说明”等编辑过程。时间、课时和学习安排只有来源明确支持时才写，不能把一次活动的上下文补成通用课程安排
12. **权威口径**：current 模式先读取全部 `corrections`，总览不得出现任何 `deprecated_terms`，章节导览也不得用旧口径概括已经修正的主题；不要在总览讨论内部修订过程。historical 模式必须把每条 `reader_notice` 原样写入“课程概述”开头，明确这是一份历史版本整理，不能用更顺滑的措辞弱化或省略
13. **过程信息隔离**：除非来源本身讨论相同名称，总览不得出现 `source-index.json`、`course-manifest.json`、`SRC/BLK/MAT/IMG` 审计 ID，也不得向读者解释生成账本、门禁或修订工作流
14. **结构导览可选**：
   - 不要固定生成"核心工作流地图"
   - 只有当课程大纲显示原文确实包含流程链路、方法框架、能力模型、系统架构或主题关系时，才加入简短结构导览
   - 导览标题应按内容自动命名，如"核心工作流地图""方法框架""能力模型""主题关系"
   - 没有明确结构时直接省略该部分，不要为了模板完整而硬加
   - 导览可以使用一行箭头链路或短列表，但必须服务于理解课程结构

## 输出格式

```
# [课程标题] - 总览

## 一、课程概述
[historical 模式先原样写入 manifest 中每条非空 `reader_notice`；current 模式省略这一步。]

[基于内容分析的简要概述，以段落形式展开介绍课程背景、核心价值和主要内容简介。说明本课程最值得沉淀的核心问题、实践经验或方法论价值。每段聚焦一个核心意思，避免过长段落。]

[如果 manifest `overview.image_ids` 非空，在最相关段落后按声明顺序插入原始 Markdown；如果为空则省略。总览配图应服务课程整体理解，不要自行加入未声明图片。]

[如果课程确实包含清晰的流程链路、方法框架、能力模型、系统架构或主题关系，可加入一个自动命名的结构导览部分；否则省略本部分。例如：
## 二、[核心工作流地图/方法框架/能力模型/主题关系]
[用一段话或一行箭头链路说明结构，例如：原始素材 -> 转录/OCR -> Markdown -> Skill -> Agent 编排 -> 知识库/交付物。标题和内容必须贴合素材，不固定套用该示例。]

后续二级标题序号根据是否加入结构导览自动顺延：如果没有结构导览，学习目标就是"二"；如果有结构导览，学习目标就是"三"。]

## [二或三]、学习目标
[根据课程实际内容，提炼 2-3 个核心学习目标，以段落形式阐述。目标应具体反映本课程的核心内容和预期收获，避免空泛表述。]

## [三或四]、课程结构
本课程共分为X个章节，每个章节聚焦一个核心主题。

[以段落形式逐一介绍各章主题和核心内容，注意：
- 根据各章实际内容描述其侧重点，不使用固定句式
- 突出章节之间的逻辑递进关系
- 说明核心章节及其原因
- 用自己的语言组织，避免模板化表达]

## [四或五]、学习路径建议
[根据课程的实际内容结构和难度梯度，给出具体的学习建议。建议应体现课程内容的特点，而非通用套话。]
```

## 输入内容

- 课程大纲：[生成的课程大纲]
- 课程标题：[AI 生成的课程名称]
- 来源权威：[manifest `source_authority`；current 模式附全部 corrections/deprecated_terms 与章节路由，historical 模式附必须原样写入的 reader_notice]
- 总览正文配图清单：[manifest `overview.image_ids` 对应的 IMG 编号、原始 Markdown 与 source ref；无则写"无"]
- 用户词典：[如果存在，列出 config/user_dictionary.yaml 中的 terms；如果不存在则写"未配置"]
