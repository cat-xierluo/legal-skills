# DSH 插件的工作台与运行视图

在新增可视化插件、重排主界面，或用户反馈“能跑但不愿使用”时读取。这里给出设计与验收方法；版式按产品任务选择，不要求所有插件使用同一套三栏、配色或流程画布。

## 先观察真实入口

从用户实际使用的 Desktop/profile 打开页面，记录主要任务、默认首屏、一次选择后的详情、需要滚动或展开才能完成的动作。先判断信息架构，再调间距和颜色。常见失效包括：

- 列表、详情和诊断按接口返回顺序纵向堆叠，选中对象后仍需寻找详情。
- 大标题、技术ID、原始JSON和可复制提示词占据主屏，真正的进展和成果在下方。
- 有“刷新成功”却没有当前对象、来源或过期状态；轮询重绘使展开区域、焦点和选择不断丢失。
- 每个字段都做成卡片、每个操作同等强调；“高级”入口只是将调试表单原样塞进弹窗。

把反馈记进产品自己的任务源。只有跨插件可复用的经验进入本Skill，产品特有编排合同、账号/路由和任务状态继续留在产品项目。

## 从参考提炼交互，而非照搬页面

选择与当前问题相似的成熟页面，逐项记录“解决什么问题—用户动作—状态变化—适用边界”。不为凑数量扩大调研；已有足够依据就实现一个可试用切片。

| 可借鉴的结构 | 适用问题 | 提炼方式 |
|---|---|---|
| 合同工作台：队列、文档、决定分区 | 用户需持续切换对象，又要保留当前工作内容 | 列表与详情保持稳定关联，决定靠近其依据；窄屏可切换单个面板 |
| 星标面板：搜索/筛选、紧凑条目、按需详情 | 对象增多后难以找到目标 | 筛选集中放在列表侧；条目只呈现识别和选择所需信息；空结果说明与空库说明分开 |
| 超能面板：概览、状态徽标、批次与可展开操作 | 需要判断哪些执行正在推进、哪里需干预 | 概览显示可核计数/状态；操作紧随具体对象；资源或连通状态不冒充业务完成 |
| 运行图与节点检查器 | 多步骤执行难追踪、长日志难定位 | 以当前执行关系为主，点节点看细节；完整原始状态按需展开 |

本机参考源码可从 `dsh-plugins` 中的 `plugins/dsh-contract-copilot/src/client/Workbench.tsx`、`plugins/dsh-star-board/renderer/source.js`、`plugins/dsh-super-board/renderer/source.js` 查找。后两者含历史 Hermes/FloPi 接口：只提炼结构，不能直接导入其运行时或据此声称 DSH 适配完成。路径不可用时从当前项目实际插件查找，不能要求技能使用者拥有该私有仓库。

外部可对照 [LangSmith Studio](https://docs.langchain.com/langsmith/use-studio) 的线程、图和可展开执行细节，以及 [n8n 画布分组](https://docs.n8n.io/build/understand-workflows/workflow-components/canvas-groups) 对大型流程的收拢方式。它们是交互参考，不是 DSH 提供对应后端能力的证据。文档能力和版本按实现当时重新核对。

## 安排信息层次

先画出用户从“找到对象”到“理解进展/取得成果/继续操作”的最短路径。列表型任务通常适合主从布局：

- 工作台头部：当前页面与少量主要动作；新建入口不必永久占用大块首屏。
- 列表：搜索、状态筛选、简短标题、阶段和最近更新时间；保留完整标题的可达入口。计数必须来自当前已读集合，分页或截断时说明范围。
- 详情：稳定对象标题与状态、下一步动作、概览/运行/成果等必要分区。先展示用户能据此行动的信息。
- 技术详情：身份、修订、来源、绑定、原始输出与复制材料按需展开；复制失败仍有手动获取方式。

“更新于…”说明观测时间；“运行中”须有对应证据。无可靠分母时展示阶段和进展文本，不用假百分比填满视觉。缺失用量显示未知，不写成零。空状态可引导下一步，加载、无匹配、断线、过期与业务受阻分开表达。

保留列表/详情各自的滚动与当前选择；窄容器可用“返回列表”或可访问的分页/标签。断点以插件实际可用宽度校验，不能只看浏览器窗口宽度——宿主侧栏会吃掉空间。不要为追求固定版式造成页面横向溢出。

## 区分运行图、布局与编排草案

运行图消费真实节点与连接。卡片可以显示角色、实际后端、阶段、连接；无法核实的字段保留未知。连线的方向和含义须清楚，节点详情再提供完整身份及来源。

拖动位置、平移、缩放、适合视图与复位属于视图操作；相同对象刷新可保留布局，切换身份要防止串用。提供键盘或按钮等价操作，说明拖动是否仅调整布局。

真正的编排编辑另有产品合同：可编辑草案、节点/依赖身份、循环或不支持配置的反馈、保存/恢复、应用前差异、正式写入口与操作回执。后台没有支持时不要让画布连线或“运行”按钮假装生效；把缺口列为实际功能任务。拖动既有运行图不能隐式取消、重派或修改已在运行的业务。

## 将高级观察做成运行检查

让用户先选对象，再看该对象的新鲜状态与有界输出。可用独立检查面板或抽屉，按空间选择，不在主工作台同时展示所有终端和原始字段。

- 对象区：名称、连通状态、搜索；选中态清晰，长名称可识别。
- 输出区：当前对象、观察时间、刷新动作、截断/不可读状态；读取错误时不能将旧输出显示为新结果。
- 更多信息：能力与完整标识折叠；需要时再展开交办准备。复制材料、消息已接收、实际执行与成果验收分别呈现。
- 弹层：可用关闭按钮与 Escape，焦点进入/限制/返回合理；背景不可操作，关闭只清订阅，不停止业务。

状态查询沿正式只读接口。界面打开、筛选、缩放不应额外触发模型；模型总结作为独立可选动作，并标明来源和成本。

## 让运行对象可辨识，正确呈现终端快照

不要只把“Terminal 1”或Session ID作为用户的唯一辨识信息。先核正式元数据是否提供项目、工作区目录、分支和运行后端；列出可核字段，完整路径按需显示，搜索覆盖这些字段。同名对象用短稳定身份区分。目录尾名可标“工作区”，不能据此伪称项目注册名；路径、分支缺失时显示未知，不从命令提示符或当前焦点猜测。

TUI/PTY的增量输出流不等于当前屏幕：重绘、光标移动和退格会使直接拼接结果重复或错位。优先使用适配器正式的屏幕快照入口，并携带screen/stream/不可用等来源；没有快照支持时说明限制。排除未提交输入草稿，限制正文大小；以纯文本等宽字体保留布局，按需折行，清楚显示采样时间、截断及重新读取状态。未实现输入转发时不要把它包装成可交互终端。可读样例要包含真实CLI/TUI屏幕，不能只验证几行普通日志。

执行图、进展摘要和运行检查是同一事实的不同视图。明确哪些来自任务状态、哪些来自原生执行事件、哪些只是连接元数据。模型自报、终端在线和候选返回不能相互替代；节点仍缺子任务或验收事件时把缺口记到产品任务，不用颜色或动画补造已完成关系。

## 视觉体系与实现边界

消费匹配安装版本的 DSH 主题和 UI primitives；确认导出与token真实存在。自有 CSS 限定插件根作用域，避免覆盖宿主标题、按钮和其它插件。选择一套连续的字体、间距、圆角、边框和状态色；主要动作与次要动作区分，不把大量边框或颜色当作设计本身。

长标题、文件路径、空数据、大列表、报错、多候选和主题切换须仍可读。用真实长任务名检查主操作按钮不会挤成逐字竖排；标题截断后仍提供完整内容入口，连续路径或无空格文本也要能换行。核实状态色变量是前景、强调色还是浅背景，不能仅因变量名相似就配对；在真实主题下确认文字可读。图内节点文字的截断不应使完整信息不可达。轮询更新先比较对象/修订，再增量更新；仅同身份可保留选择、展开、编辑草稿与焦点，迟到响应不得写到新对象。

不要仅为模仿参考引入图引擎或整套 UI 框架。先核平台已有能力与实际交互复杂度；需要新依赖时另说明体积、许可、宿主兼容和维护边界。

## 共享视觉层接入与维护

新建/改版前从目标插件仓 README/DESIGN/任务源查找公共视觉入口、主题角色和已有消费者。已有 SDK primitives 或项目共享样式直接消费；确有通用缺口时先核平台能力，再补最小公共层。公共层集中维护画布/侧栏/输入/文字/边界/选中/悬停/聚焦角色、间距及适用的分栏规则，业务状态和会话/权限仍归插件。具体值只维护在项目公共源码与契约，本 Skill 不保存另一套数值配置；无需另造配置文件。

将视觉角色映射到匹配版本的 DSH 主题导出，核变量的真实含义与合法声明集。迁移 Hermes 时可以复用设计角色与维护流程，不能直接复制 Hermes 的 `--ui-*` 变量、SDK import 或构建/重载步骤并宣称 DSH 可用；平台适配分别确认。本文仅规定接入方法，是否已有 DSH 公共实现和哪些消费者已迁移必须从目标项目核实，未实现的记后续任务。

维护反馈先入**插件项目任务源**，列真实消费者、范围、兼容性与验收。Skill TASKS 只追踪方法更新，避免与产品维护队列重复。新增通用元素改公共源，业务特有布局留插件；并非所有消费者必须采用三栏。优先可选参数和兼容默认；破坏性改动要列迁移范围、同步消费者及契约，不只改首个页面。

写前核并发与消费者 imports，改后按 DSH 工件/装载合同重建受影响 bundle、运行相关公共/消费者回归，再验证实际容器宽度、亮暗/长内容、选中/悬停/禁用/键盘焦点与原业务动作。原生和合成证据分开，纯样式不调用业务模型；身份和迟到响应断言不因新外观而减弱。共享接口事实回公共 README/DESIGN，用户可见变化回消费者 CHANGELOG，实际验收与未验证项回项目任务卡。登记维护规则不自动授权定时巡检、部署、发布或批量迁移。

## 按用户路径验收

编译和机械lint不证明界面可用。按本次受影响动作选取代表性路径，保存候选版本、实际尺寸、断言与必要截图：

1. 默认首屏能找到主要动作；有实际任务时，选择后可直接看到其进展、成果或下一步。
2. 搜索/筛选/清除、空结果、长标题和窄容器不丢当前对象、不造成页面横向溢出。
3. 标签、展开、图选择与布局在同对象刷新后保持；切对象、断线重连、旧响应迟到不会串数据。
4. 画布拖动/缩放/复位和键盘操作实际执行；核它们是否按设计只改视图。
5. 检查面板真实选择对象、读取/失败、关闭、焦点返回可用；原始输出及材料不能流到其它对象。
6. 在正常用户入口确认新bundle已载入，再做代表性交互；CLI部署和静态截图不能代替这一步。

自动化浏览器可覆盖布局边界和交互回归，真实 Desktop 核宿主尺寸、主题及装载接缝；两类证据分别写。不要让测试通过改弱原身份/迟到响应断言适配新外观。纯UI切片无需重复业务模型调用；用户体验反馈仍是后续迭代输入，单次截图通过不代表长期可用性已证实。

## 来源与沉淀边界

2026-10-02 来自实际插件试用反馈、上述三类插件源码及两份官方交互文档的提炼。原始截图、具体失败、实现状态与运行证据由对应插件项目维护。本指南表达可复用设计方法，不将仍在制作的改版标为全量验证，不复制个人数据或把某个产品布局设为所有插件的强制模板。
