# 技术服务合同 审查意见（微案例）

- 合同名称：技术服务合同（contract-micro-service-scope.docx）
- 审查立场：甲方（委托方）
- 审查目的：签约前把关
- 审查口径：常规
- 合同类型路由：服务类合同（一般服务/技术服务），如涉及成果交付与知识产权归属，需叠加"知识产权类—技术开发"配套标签

---

## 一、总体判断（先说结论前提）

本合同文本仅有三条，**缺失服务类合同的绝大部分核心条款**：服务范围、交付标准、验收、价款与付款、期限与里程碑、违约责任、知识产权归属、保密、解除与争议解决**均未约定**。

其中最致命的是第二条：服务范围被写成"全程技术服务，具体服务内容由双方另行沟通确定"。**这不是措辞粗糙的问题，而是合同标的不确定的问题**——对甲方而言，等于花钱买了一个内容待定的承诺。

**因此我需要先暂停，向你确认几项事实后才能出正式的"能否签"结论。**（见第四节）在这些事实缺失的情况下，任何"可签/有条件可签"的结论都是对甲方的误导。

## 二、微观条款风险清单

### 风险 1：服务范围未约定，合同标的不确定（第二条）

| 项目 | 内容 |
|:---|:---|
| 风险名称 | 服务范围过粗，标的不特定 |
| 风险等级 | **P0** |
| 相关条款 | 第二条 |
| 原文 | "乙方为甲方提供本合同项下的全程技术服务，具体服务内容由双方另行沟通确定。" |

**风险后果**：

1. **合同可能不成立或部分不成立**。标的是合同的必备内容，"服务内容另行沟通确定"意味着双方对最核心的给付义务尚未达成合意。若后续沟通不成，甲方可能连"要求乙方做什么"都无法主张。
2. **无法认定违约**。没有范围就没有履行标准，乙方做多做少都不构成违约；甲方要追责时，举证义务内容这一步就会卡死。
3. **谈判地位反转**。签约后甲方已被锁定，"另行沟通"实际由乙方主导；乙方可主张任何超出其理解的工作属于"合同外增项"，另行收费。这是服务类合同中最常见的变相加价路径。
4. **"全程"二字对甲方是虚假安全感**。"全程"看似宽，但因无边界描述，实践中反而无法据以要求任何具体动作，法院/仲裁难以据"全程"扩张义务。
5. **验收与付款无锚点**。范围不定→交付物不定→验收无标准→付款条件无从触发或无从拒付。

**判别标准**（该条是否合格，看下列是否可回答）：

- 乙方要交付什么具体成果或服务动作？（可列举）
- 交付物形态是什么？（代码/文档/部署/驻场人天/运维响应）
- 服务期限与频次是什么？
- 什么算做完了？（验收标准）
- 范围之外的需求怎么处理？（变更机制与计价）

以上任一项无法回答，即属"服务范围过粗"。本合同五项**全部无法回答**。

**整改建议**：

- 第一优先：将服务范围**从正文移入附件《服务需求说明书/SOW》，并明确附件为合同不可分割组成部分**，签署时同步签署，不接受"事后补"。
- 第二优先：在正文保留"范围+变更机制+兜底归属"三段结构，杜绝开口条款。
- 若确因项目处于早期无法一次写死，**正确做法不是留空，而是改签"框架协议 + 订单/SOW"结构**：框架定规则（计价方式、变更流程、验收规则、责任），单个 SOW 定内容，无 SOW 不启动、不付款。**切勿用一份"内容待定"的正式服务合同代替框架协议。**

**推荐措辞（供采用，需按实际业务填入方括号内容）**：

> **第二条 服务范围**
>
> 2.1 乙方应向甲方提供的技术服务内容、交付成果、技术标准、服务期限、人员配置及验收标准，以本合同附件一《服务需求说明书》为准。附件一为本合同不可分割的组成部分，与本合同正文具有同等效力，并应于本合同签署时同时签署。
>
> 2.2 附件一未列明但为实现本合同目的、完成约定交付成果所必需的辅助性工作（包括但不限于[环境配置、数据迁移、接口联调、上线支持、交付文档编制及不超过[  ]小时的交付培训]），视为已包含在服务范围内，乙方不得据此另行收费。
>
> 2.3 服务范围的任何变更，须经双方书面签署《变更确认单》后方可生效，《变更确认单》应载明变更内容、对工期的影响及费用增减。未经甲方书面确认的工作，乙方不得实施，亦不得要求甲方支付任何费用；乙方擅自实施的，费用由乙方自行承担。
>
> 2.4 双方就服务范围的理解发生争议的，在不显著增加乙方成本的前提下，应作有利于实现本合同目的的解释。

**法律依据方向**：《民法典》第四百七十条（合同内容一般包括标的、数量、质量等条款）、第四百七十一条至第四百八十八条（合同成立与要约承诺规则，关涉"另行协商"条款的合意认定）、第五百一十条至第五百一十一条（约定不明时的补充与确定规则——需提示：补充规则可兜底质量、价款、地点等，但**难以兜底"做什么"这一标的本身**）、第一百四十二条（意思表示解释规则）。

**建议展现方式**：整条重写 + 保留批注说明修改原因（P0 重大修订）。

### 风险 2："另行沟通确定"属无效力开口条款（第二条后半句）

| 项目 | 内容 |
|:---|:---|
| 风险等级 | **P0** |
| 相关条款 | 第二条、第三条 |

**风险后果**：第二条"另行沟通确定"与第三条"未尽事宜由双方另行协商确定"叠加，使本合同在结构上成为一份**没有强制力内核的意向书**。"沟通/协商"既未约定期限，也未约定协商不成的后果，属典型的无救济开口条款：协商不成时，既不能强制对方接受某一方案，也没有约定解除权和退出路径。

**整改建议**：任何"另行确定"必须配三件套——**期限 + 不成的后果 + 兜底规则**。

**推荐措辞**：

> 就本合同约定需另行确定的事项，双方应自[本合同签署之日/该事项触发之日]起[  ]个工作日内书面确定；逾期未能达成一致的，[适用本合同第[  ]条约定的兜底标准／甲方有权书面通知解除本合同且不承担违约责任，乙方应在[  ]个工作日内退还已收取但未提供对应服务的款项]。

**建议展现方式**：局部补入。

### 风险 3：核心条款体系性缺失

| 项目 | 内容 |
|:---|:---|
| 风险等级 | **P0（整体）** |
| 相关条款 | 全文 |

现有文本缺失以下条款，对甲方均为不利缺口（缺失时通常由法定规则填补，而法定规则未必对委托方有利，且举证成本高）：

| 缺失条款 | 对甲方的具体不利 | 优先级 |
|:---|:---|:---|
| 价款与付款方式 | 无付款节点即无付款抗辩权；乙方可能主张按市场价或按工时结算 | P0 |
| 验收标准与验收流程 | 无验收即无拒付依据；易被主张"默示验收" | P0 |
| 服务期限/里程碑 | 乙方无逾期概念，甲方无法主张迟延违约 | P0 |
| 违约责任与赔偿 | 只能主张实际损失且举证极难，无违约金杠杆 | P0 |
| 知识产权归属 | 技术服务成果（代码、文档、算法）默认归属易生争议，甲方可能只得使用权 | P0 |
| 保密与数据合规 | 乙方接触甲方业务数据/个人信息无约束，甲方可能承担对外合规责任 | P1 |
| 解除权与退出机制 | 项目失控时甲方无单方退出路径，已付款项难以追回 | P1 |
| 人员与转委托限制 | 乙方可随意换人或分包给第三方 | P1 |
| 争议解决与管辖 | 未约定则按被告住所地或合同履行地，甲方可能被迫异地应诉 | P1 |
| 通知送达条款 | 后续书面通知（含解除通知）无有效送达地址，无法举证 | P2 |
| 合同生效与附件效力顺位 | 附件与正文冲突时无优先规则 | P2 |

**整改建议**：本轮不建议在现有三条框架上"打补丁"，建议**按服务类合同标准骨架整体补齐**后再进入逐条谈判。

### 风险 4：第一条鉴于条款空转（第一条）

| 项目 | 内容 |
|:---|:---|
| 风险等级 | **P2** |
| 相关条款 | 第一条 |

第一条"鉴于双方就上述合同标的达成一致"中，"上述合同标的"在文中**并无所指**（前文无标的描述），属于自我指涉的空转表述。风险在于：一旦发生争议，乙方可能援引该条主张"甲方已确认标的达成一致"，反过来削弱甲方"标的不明"的抗辩。

**整改建议**：删除该虚指表述，或改写为真实的交易背景陈述。

**推荐措辞**：

> 第一条 鉴于甲方因[  ]业务需要，拟委托乙方提供本合同附件一所载技术服务；乙方确认其具备提供该等服务所必需的资质、技术能力与人员配置。双方经平等协商，订立本合同。

**建议展现方式**：局部替换。

## 三、宏观与中观层提示

**宏观层（交易结构）**：

- 合同类型可能与交易实质不匹配。若本次交易实际包含**定制开发、成果交付、知识产权产出**，则应按"技术开发合同"或"技术服务 + 开发"双标签处理，知识产权归属条款必须单列，不能沿用一般服务合同骨架。
- 主体资格、授权情况、乙方相关资质未见材料，**未提及/待补充**。
- 付款—交付—验收—退出闭环**完全缺失**，当前结构不可执行。

**中观层（形式）**：

- 合同形式与业务阶段可能不匹配。**若服务内容确实尚不能确定，正确形式是"框架协议 + SOW/订单"，而非一份内容待定的正式服务合同。**这是本案的核心结构性判断，需先与你确认。
- 无附件，正文与附件的效力顺位规则**未提及/待补充**。

## 四、需先行确认的事项（本次审查的暂停点）

以下事实缺口直接决定审查结论的走向，我**不能替你臆测**，请先确认：

1. **服务内容目前是否已经明确？** 是"已谈定但没写进合同"，还是"确实尚未谈定"？
   - 若属前者：直接补入 SOW 即可，问题可控。
   - 若属后者：应改变合同形式（改签框架协议），而非修补本文本。
2. **合同金额、付款节点是否已谈定？**是否已经或即将支付预付款？（若已付款，风险敞口显著上升，处置策略不同。）
3. **本次服务是否会产生定制化成果（代码、系统、文档、技术方案）？**这决定知识产权条款是否必须单列。
4. **是否涉及甲方业务数据、用户个人信息的处理？**涉及则需加数据处理与合规条款。
5. **是否存在未提供的附件、报价单、需求文档、招投标文件或既往邮件确认？**若存在，可能已构成服务范围的组成部分，需一并审查。
6. **甲方在本次交易中的谈判空间如何？**是否可要求乙方接受重构文本，还是仅能做有限修改？
7. **有无签约时限压力？**如确需先行锁定合作关系，可评估"先签框架协议、SOW 后补"的过渡方案。

## 五、审查结论

**审查结论：暂不出具正式"能否签"结论——本轮为条件性保留意见。**

在第四节第 1、2、3 项事实确认之前，我不给出"可签 / 有条件可签 / 不建议签"的正式定性，因为该定性取决于"服务内容是否已谈定"这一尚未确认的前提，贸然定性会误导决策。

就当前文本本身，可以明确的是：**现有三条文本在服务范围、价款、验收、期限、违约、知识产权等核心条款上全面缺失，以现状签署对甲方风险不可控，不应以现状签署。**

**先决事项（无论后续走哪条路径，均须完成）**：

1. 明确并书面固定服务范围，以附件《服务需求说明书》形式与正文同步签署（P0）。
2. 补齐价款与付款节点、验收标准与流程、服务期限与里程碑（P0）。
3. 补齐违约责任与知识产权归属条款（P0）。
4. 删除或改造"另行沟通/另行协商确定"类无救济开口条款，补入期限、不成后果与兜底规则（P0）。
5. 补齐保密与数据合规、解除与退出、人员与转委托限制、争议解决与管辖（P1）。
6. 核验乙方主体资格、资质与签约授权（P0，程序性）。

**待确认事实澄清后的预判路径（供参考，非结论）**：

- 若服务内容已谈定 → 完成上述先决事项 1—6 后，可具备"有条件可签"的评估基础。
- 若服务内容尚未谈定 → 应改签"框架协议 + SOW"结构；以本文本现状签署，我方不建议。

**谈判优先级**：效力与程序（主体、授权、附件效力）→ 服务范围与交付验收 → 资金与付款 → 救济与退出（违约、解除、争议解决）→ 知识产权与保密 → 文本优化。
