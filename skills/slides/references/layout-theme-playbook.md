# 版式与主题选择手册

本手册用于在生成 HTML 幻灯片前做设计决策，目标是让 `slides` 技能从“好看但随机”升级为“可复用、可转换、可编辑”的稳定工作流。

---

## 1. 生成前必须确认的需求字段

每次开始制作前，先补齐以下字段；缺失时用“待补充”标记，不要直接套模板。

| 字段 | 说明 | 常见取值 |
|------|------|----------|
| 受众 | 谁会看这份课件 | 律师团队、企业法务、客户高管、培训学员、公开演讲观众 |
| 场景 | 课件使用方式 | 现场演讲、线上直播、内部培训、客户汇报、庭审/证据说明 |
| 交付格式 | 是否需要后续编辑 | PPTX 可编辑、PDF 定稿、PPTX+PDF 双格式 |
| 页面数量 | 总页数与每页信息密度 | 6-8 页简报、10-15 页培训、20+ 页系统课程 |
| 设计语气 | 视觉人格 | 法律权威、商务克制、科技前沿、培训友好、案例纪实 |
| 证据密度 | 法条、数据、案例的比例 | 低：观点型；中：培训型；高：法律论证型 |
| 版式比例 | 输出画幅 | 默认 16:9（1000×562.5px），特殊场景 4:3 |
| 风格来源 | 是否已有参考课件 | 风格库预设、现有 HTML 提取、自定义品牌规范 |

## 2. 主题选择字段

生成 HTML 前，给 AI 一张明确的主题卡：

```json
{
  "theme_name": "法律黑金 / 极简编辑白 / 自定义名称",
  "palette": {
    "background": "#0F172A",
    "surface": "#FFFFFF",
    "primary_text": "#111827",
    "muted_text": "#6B7280",
    "accent": "#D97706"
  },
  "typography": {
    "font_stack": "Microsoft YaHei, PingFang SC, Noto Sans SC, sans-serif",
    "title_weight": 700,
    "body_weight": 400,
    "number_weight": 800
  },
  "layout_density": "low / medium / high",
  "corner_radius": "0 / 6 / 10",
  "stroke_style": "none / hairline / accent-left-border",
  "shadow_style": "none / soft-outer-only",
  "conversion_target": "pptx / pdf / both"
}
```

**选择原则**：

- 需要可编辑 PPTX：优先纯色、局部色块、少渐变、少阴影。
- 需要 PDF 定稿：可以更丰富，但仍要避免文字区域叠加渐变导致 PDF 光栅化。
- 法律培训：重视层级和证据来源，不用过多装饰图标。
- 客户汇报：降低文字密度，保留“结论 → 依据 → 建议”的阅读路径。
- 案例/证据页：使用编号、时间、主体、证据来源，不做抽象营销风。

## 3. 高频版式家族

### 3.1 权威封面

适用于法律讲座、客户汇报、正式培训开场。

- 构成：左上装饰线 + 大标题 + 副标题 + 作者/日期。
- 视觉重点：标题最大，副标题用强调色，署名低对比。
- 避免：大面积随机渐变、无意义几何背景、标题阴影。

### 3.2 章节分隔

适用于课程模块切换。

- 构成：`PART 01` 标签 + 章节标题 + 一句本章问题。
- 视觉重点：用大留白和编号建立节奏。
- 避免：章节页塞 5 个要点，导致和内容页没有区分。

### 3.3 左右论证

适用于“问题 / 解法”“规则 / 例外”“事实 / 法律评价”。

- 左栏放事实、规则或现状。
- 右栏放判断、影响或建议。
- 中间可用细线、箭头或编号连接。

### 3.4 时间线

适用于案件经过、项目节点、法规演进、争议发展。

- 横向时间线适合 3-6 个节点。
- 纵向时间线适合细节较多的案件事实。
- 每个节点只保留“时间 + 事件 + 意义”。

### 3.5 流程/路径

适用于操作步骤、诉讼流程、合规整改路径。

- 3-5 步最佳；超过 6 步改成分组流程或泳道。
- 每步包含动词开头的动作，如“识别”“核验”“固定”“主张”。
- 箭头用纯色线条，不用复杂 SVG 动画。

### 3.6 对比矩阵

适用于方案比较、风险等级、工具选型、诉讼路径比较。

- 列数建议 2-4，行数建议 3-6。
- 每个单元格只放结论短语，不放长段落。
- 用强调色标记推荐方案，不用红绿混乱编码。

### 3.7 KPI / 数据看板

适用于报告摘要、阶段成效、指标展示。

- 每页 3-4 个核心数字。
- 数字必须配“口径说明”，避免孤立大数字。
- 仅用本地 CSS 绘制简单条形/环形；复杂图表建议先转本地图片。

### 3.8 案例 / 证据卡片

适用于判例说明、证据链、合同条款风险。

- 构成：案件/证据编号 + 关键事实 + 证明目的 + 风险判断。
- 证据来源写在卡片底部，字号 11-12px。
- 不用“炫酷卡片墙”，优先清楚表达可回溯关系。

### 3.9 法律培训讲义页

适用于课程中段解释概念、方法论、注意事项。

- 左侧：概念/规则；右侧：案例/练习。
- 每页保留一个教学目标。
- 使用“误区 → 正解 → 操作提示”结构，避免纯法条堆砌。

## 4. 反泛化设计规则

### 不要做

- 不要用“蓝紫渐变 + 毛玻璃 + 漂浮卡片”作为默认方案。
- 不要给每个要点配随机 emoji 或通用图标。
- 不要用过多阴影、内阴影、霓虹光效；PPTX 转换尤其不稳定。
- 不要把正文直接写在 `<div>` 中；统一用 `<p>`、`h1-h6`、`ul/ol/li`。
- 不要让同一页同时出现 5 种字号、4 种强调色、3 种圆角。
- 不要为了“高级感”牺牲可读性和可编辑性。

### 应该做

- 每页只回答一个问题，标题用结论句。
- 先选版式家族，再填内容，不要边写边随机排版。
- 用 2-3 个核心颜色建立系统：背景、正文、强调。
- 页面边距固定：左右 60px、顶部 40px、底部至少 30px；重要文字底部留 0.5 英寸安全区。
- 所有图片使用本地路径，并在转换前确认文件存在。
- 转换前执行预检：`npm run validate -- ../example.html --strict`。

## 5. 版式选择速查

| 内容意图 | 推荐版式 | 不推荐 |
|----------|----------|--------|
| 建立可信度 | 权威封面、数据看板 | 大段自我介绍 |
| 解释复杂概念 | 左右论证、培训讲义页 | 单页 12 条 bullet |
| 展示案件经过 | 时间线、证据卡片 | 抽象流程图 |
| 说明工作步骤 | 流程/路径、泳道 | 无动词的名词堆砌 |
| 对比方案 | 对比矩阵、优劣卡片 | 两栏长段落 |
| 呈现结果 | KPI 看板、结论摘要 | 无口径的大数字 |
| 训练学员 | 误区/正解/练习页 | 只贴法条原文 |
