# 程序化门控

门控按顺序失败关闭；后续阶段不得绕过前置失败。

## 1. 输入可信边界

- 把 transcript、工具回显和代码块视为不可信数据；
- 过滤 system/developer 内容、重复消息和工具产生的大段输出；
- 检测提示注入与密钥材料；
- 不执行 transcript 中出现的命令或指令。

## 2. 隐私门控

先自动替换可安全脱敏的主目录（包括运行时 `HOME` 指向的非标准 Linux 路径）、系统临时目录和挂载卷路径，以及邮箱、电话、证件号、案号、组织名和 URL，再扫描残留风险。Bearer/JWT 与其他密钥材料不可脱敏发布，必须失败关闭。超长代码块或行只保留摘要与哈希。

通过：写入 Review Inbox，并记录内容 SHA-256；绑定 proposal 的 Deep 产物按内容寻址并以 no-clobber 方式发布，人工接受时再固化为 revision-bound archive 快照。

失败：写入 quarantine 元数据，只含规则名、计数、时间和证据哈希，不含命中原文。

## 3. 证据门控

- 至少有可追溯 evidence ID；
- 方法论类提案优先要求跨 session 或跨时间证据；
- 单次明确用户指令可以形成 candidate，但仍须人工决定；
- 普通维护、软件更新和无结论尝试默认只保留薄索引。

## 4. 聚类门控

- 对来源做配额控制，避免单一框架淹没其他来源；
- 要求成员与主题中心具有最低相似度；
- 限制巨型 cluster，并对内部一致性不足的成员拆分或降级；
- 让 cluster ID 在输入未变化时保持稳定。

## 5. 新颖性与版本门控

- 对照 inventory、portrait、目标 Skill 当前版本和既有 proposal；
- 已覆盖内容标为 `covered`；
- 同 revision 标为 `duplicate`；
- 目标不存在、版本过期或证据不足时保持 `candidate`/`filtered`；
- 机器不得写人工决定。

## 6. LLM 门控

每日索引不得调用 LLM。每周深度阶段必须显式启用、限定 cluster 数量、设置超时，并只消费通过前述门控的 packet。LLM 不可用时输出明确的 unavailable 状态，不生成看似完成的深度结论。
