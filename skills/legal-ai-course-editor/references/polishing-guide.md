# 口语转书面操作细则（polishing-guide.md）

整理前必读。三类操作各自有明确的边界，越界即违反"忠实原意"原则。

## 一、删（只删冗余，不删信息）

可以删：

- 纯语气填充：嗯、啊、呃、然后然后、对吧对吧、这个这个那个那个
- 无信息重复：同一句话在 30 秒内的原样重复（保留最完整的一次）
- 口误自纠：讲者说错后立即自我纠正的，保留纠正后的版本
- 礼貌性客套：开场寒暄、感谢刷屏、提醒点赞转发（除非本身就是课程内容）

不可删：

- 离题但有趣的内容 → 移入讲义附录「题外话」，标注原稿位置
- 答疑环节的全部问答 → 保留（可精简提问，不删回答要点）
- 重复但逐次深化的内容 → 合并保留，不当作冗余删除

## 二、改（补全与书面化，不换表述）

可以改：

- 补全主语与指代：把"它这个就等于说"明确为所指对象
- 断句重组：转写稿的流水句切分为正常书面句
- 书面连接词：口语的"那接下来呢"→"接下来"；"所以说"→"因此"
- 明显同音错字：转写引擎错误，如"股权代持"写成"股权代驰"——仅限上下文可唯一确定的
- 标点与分段：按语义重新分段

不可改（越界）：

- 把口语观点升级成讲者没说的专业措辞（如讲者说"打官司就是要快"，不能改成"诉讼时效管理是争议解决的核心策略"）
- 修改结论的方向、程度、限定条件
- 用编者语言改写案例细节
- 修正讲者"明显说错"的专业内容 → 这不属于转写错误，保留原话并加编者注

## 三、留（必须保留原貌的内容）

- **金句**：讲者的精彩原话 → 引用块保留，一字不改
- **第一人称经验**：「我办过一个案子……」的经验叙述，保留第一人称，不转第三人称概述
- **案例细节**：案情、法院、判项、金额，一个都不合并
- **操作演示**：工具步骤、提示词原文 → 用代码块或编号步骤完整保留
- **立场性限定**：讲者的"我个人认为""不一定对"等限定语 → 保留（可移到句末，不删）

## 四、术语与专名处理

| 类型 | 规则 |
|------|------|
| 法律术语 | 同音错字按上下文修正；术语使用不规范时保留原话 + 编者注 |
| AI 工具名 | 按官方写法核对（如 Kimi、通义千问、扣子）；无法确证标「⚠ 待核实」 |
| 法条引用 | 编号 + 内容双重核对（有检索工具先检索）；讲者口述与检索结果不符时保留原话加注 |
| 英文缩写 | 首次出现补全称，如「RAG（检索增强生成）」 |
| 人名/律所/公司名 | 转写稿同音字无法确证时标「⚠ 待核实」，不猜 |

## 五、回溯定位规则

- 有时间戳的稿：引用与标注用 `[mm:ss]`
- 无时间戳的稿：用「原稿第 N 段附近」（预检时按段落顺序编号）
- 回溯定位写入讲义对应位置的行内小注，如 `> （约 12:30）`

## 六、多人发言处理

- 每次换人发言前插入发言人标识；转写稿未标注发言人且无法从内容区分时，统一用「讲者」「提问者」并注明是整理时的推断
- 对话式答疑整理为 Q&A 格式：**Q**（精简后的问题）/ **A**（要点保留）
