# 公开化设计预检

开工前读取。目标是在批量修改前固定范围、授权与已知风险，避免边改边扩大目标。

## 预检输出

预检完成时应产出一份简短结论（写进任务卡，不另建文件）：

| 字段 | 内容 |
|---|---|
| 目标 Skill 与路径 | 具名目录，确认当前版本与基准 OID |
| 目标形态 | 公仓目录 / 独立仓库 / 平台安装包 / 仅本地候选 |
| 写域 | 允许修改的目录与文件；明确「仅本 Skill」还是含 README/套件页 |
| 授权边界 | 本轮允许到哪一步（候选整理 / push / Draft PR / 合并 / 发布） |
| 风险清单 | 下表中命中的类别及处置 |
| 停止条件 | 候选漂移、发现超出写域的改动、需要生产变更或外部写入时停止 |

## 风险分类与处置

| 风险 | 判断方式 | 预检处置 |
|---|---|---|
| 已跟踪的本地配置 | `git ls-files` 对照私有层路径；ignore 不能解除跟踪 | 记录清单，先另存副本，再逐项退出跟踪；发布包按路径硬排除兜底 |
| 私有历史 | 候选从私仓导出，历史含个人材料 | 默认清洁历史（空仓 + 单一初始提交）；改 remote 直推视为泄露，须用户单独裁决 |
| 第三方材料 | 逐文件查来源与许可（尤其 AGPL 类强传染条款） | 整体删除并自建替代最安全；保留须有用户裁决与归属说明 |
| 个人素材 | 图片、二维码、头像、名片、身份文件名 | 移入私有层；公开层允许清单默认排除二进制个人素材 |
| 真实业务锚点 | 机构名、人名+职称、案号、课程路径、客户项目代号 | 剥离为占位或泛化；确需保留的发布元数据走登记表 |
| 派生隐私 | 用量数值、额度、聚合统计、并发配置 | 按私密处理，用档位/相对变化/桶标签替代 |
| 版本漂移 | SKILL.md / package.json / CHANGELOG 三处版本对照 | 预检即记录差异，收口时统一 |
| 文档-实现承诺 | 文档宣称的能力是否有脚本/入口支撑 | 列出无实现承诺，改为手工步骤或删承诺 |
| 依赖与安装 | 平台许可（如 MIT-0）、宿主版本、外部工具 | 预检查清；缺依赖不自动安装 |

## 需要明确的信息

先从用户指令、会话已有授权与项目规则核对以下事项；已有答案直接复用，只对缺失且影响本次工作的项集中补问：

1. 目标发布形态与目标仓库/平台。
2. 是否保留作者署名及具体署名内容（项目规范允许保留）。
3. 第三方材料的删除/替换/标注。
4. 私有历史的处理方式（清洁导出或经审历史重写，均需明确授权）。
5. 发布边界：整理完成后的 push / PR / 合并 / 上传分别是否已授权。

其余常规选择（占位符写法、文件归属、校验器接口）由执行者自行决定并在任务卡记录。
