# 个人经验剥离

逐文件处理公开层内容时读取。目标不是删光个人痕迹，而是把「个人叙述」转成「可复用机制」，同时把不能泛化的个人事实移入私有层。

## 四种处理方式

| 方式 | 适用 | 示例 |
|---|---|---|
| 占位化 | 值本身是私密的，机制要保留 | 真实模型 ID → `example/model-strong`；真实端口 → `<port>`；真实路径 → `<skill-dir>/...` |
| 泛化 | 个人案例有通用教训 | 「某次授课中…」→ 提取为判据/步骤，删掉人物时间地点 |
| 结构化 | 经验以叙述承载 | 「我发现先做 A 再做 B 比较好」→ 检查清单条目或流程步骤 |
| 移入私有层 | 无法泛化且仍需保留 | 个人画像、真实配置、运行回执 → `config/*.local.*` / `state/` |

## 逐类锚点与替代写法

| 类别 | 剥离目标 | 允许的替代 |
|---|---|---|
| 账号身份 | 登录邮箱、别名、cookie、绑定手机 | `account-1`；账号数量仅作合成示例，真实统计留本地 |
| 额度与用量 | 剩余额度、百分比、单价、429 次数 | 通用判断方法或明确合成示例；真实数值、比例及派生档位留本地 |
| 凭证 | key、token、签名串 | 「已配置/未配置」；`key-<ref>` 引用标签 |
| 网络出口 | 网关地址、代理主机、出口 IP | `<gateway-url>`、「本机回环」 |
| 本机路径 | 用户主目录、worktree 路径 | `<skill-dir>/...`、相对路径 |
| 会话与任务 | 标题、摘要、文件名、提示词正文 | 合成 ID、通用任务类型；不公开可关联真实会话的标识 |
| 产物 | 交付文件、验收记录 | 合成路径与演示数据；真实哈希和字节数留本地 |
| 机构与人员 | 具体机构名、人名+职称 | 虚构占位、泛指 |
| 业务路径 | 真实课程/项目目录 | `references/example/` 泛写 |
| 派生值 | 总用量、命中数、并发 | 按额度类处理 |

**作者署名是发布元数据，不是内容锚点**：frontmatter author、LICENSE 版权行、README 作者区按项目规范保留；为避免被门禁误拦，走[发布前门禁的登记表豁免](release-gates.md#隐私模式检测设计)。

## 维护文档的去留

TASKS/DECISIONS/整改计划这类维护文档：

- **默认本地维护**：原始 TASKS.md、DECISIONS.md 与 Skill 放在同一目录，用 Skill 自带 `.gitignore` 排除并验证未被 Git 跟踪；迁移时复制完整原文到对应本地路径，核哈希并保留归档来源。通用结论进入 references，不用公开摘要替代原件。
- **用户明确要求随 Git 仓库分发时**：也要去具体化——它们会随 clone 进入任何人的上下文。模型 ID、账号、路径、额度数值不写入；只保留通用结论与验收状态。
- **作为独立私仓权威记录时**：可保留更多细节，但公开包用允许清单排除（不进发布物）。

两种形态不能混用：同一文件既声称「私有记录」又出现在公开允许清单里，是门禁必须拦截的矛盾。

## 剥离后自检问题

1. 换一个使用者拿到这个 Skill，会误以为某个占位是真实配置吗？
2. 有没有任何一处叙述能反推出维护者的工作规模、客户或习惯？
3. 个人偏好是否已被写成「可配置项 + 默认中性值」，而不是硬编码在通用层？
4. 删掉的叙述里是否有值得保留为通用判据的教训？（剥离 ≠ 删经验）
5. 示例数据的组合是否产生新的可定位信息（机构+时间+事件）？
