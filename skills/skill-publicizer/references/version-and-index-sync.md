# 版本与索引同步

对齐版本、CHANGELOG、README 与发布字段时读取。目标是让使用者从任一入口看到的版本、能力描述和下载入口一致。

## 同步清单

| 对象 | 检查/修改 |
|---|---|
| `SKILL.md` frontmatter | `metadata.version`（或项目既有版本字段）与 CHANGELOG 最新版本一致 |
| `CHANGELOG.md` | 最新条目在顶部，日期与实际交付一致；历史条目同样去具体化 |
| README 技能列表 | 名称、一句话能力、许可证、版本、备注与 SKILL.md 一致 |
| README 最近更新区 | 按目标项目现行规则排序并裁剪；不把本项目数量当通用规则 |
| 所属套件页 | 若项目有 expert suite 索引，同步成员表和版本状态 |
| 平台同步配置 | 若存在发布 manifest，核对包含路径与字段；平台合同交给 skill-publish-sync |
| 发布字段 | license / author / homepage 与 LICENSE 与项目发布规范一致 |
| 多来源版本文件 | `package.json`、config schema version 等声明随实际格式变化同步 |

## 版本编号

- 首次公开：按目标项目规范选择正式起点（常见为 `1.0.0`；已有历史则不重置）。
- 从私仓迁移：延续既有已确认版本轨迹递增，不因仓库迁移归零。
- 用户可见变化：新增功能升 minor，修复升 patch；破坏性/大规模重构按项目规范评估 major。
- 文档-only 整理：若对外行为或发布内容变化，仍记版本；纯内部流水不发布版本。
- 不用 `Unreleased` 长期承载已合入主干的用户可见变化；归档发布前并入具体版本。

## CHANGELOG 口径

最新条目写使用者可理解的结果：新增能力、边界变化、修复问题、验证边界。不写内部执行流水、worker 分工、模型消耗或候选推进过程。历史条目迁移时保留版本轨迹，但逐条按「个人经验剥离」参考去具体化。

## 验证

- 版本一致性可脚本检查时以脚本为准；无脚本时用 grep/局部解析核对。
- README 链接全部可达；版本、许可证、能力描述三处一致。
- 最近更新区条目数与排序符合目标项目现行规范，不复制其他项目的固定数值。
