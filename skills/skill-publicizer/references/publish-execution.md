# 发布执行与授权边界

执行对外动作前读取。本参考只规定公开化场景的顺序与授权分层；具体命令、身份门禁和隐私预检以 git-workflow 为权威。

## 授权分层

| 层 | 动作 | 授权要求 |
|---|---|---|
| 整理 | 分层、剥离、写文档、写测试、本地提交 | 任务授权即可 |
| 交付候选 | push 分支、创建 Draft PR | 核会话已有明确授权；走 safe-push / safe-pr |
| 采纳入库 | PR 转 Ready、合并、公仓采用 | 用户明确授权 + 独立 review + checks 通过 |
| 公开发布 | tag/Release/平台上传/独立仓推送 | 用户明确授权；平台合同由 skill-publish-sync / release-workflow 维护 |
| 后续运行 | 定时部署、生产安装 | 与发布分开授权；安装入口存在不等于实际可调用 |

任何一层完成不隐含下一层授权。「候选已通过门禁」「review 已 approve」「测试全绿」都不是发布授权。

## 候选交付顺序

1. 独立 worktree 内完成整理与门禁（单 writer）。
2. 身份自检：`identity-audit.sh whoami`；用单次 `GIT_AUTHOR_*` / `GIT_COMMITTER_*` 环境变量提交，不写仓库级 config。
3. `safe-push.sh --base origin/main --remote origin --branch <branch> --expected-name <name> --expected-email <email>`：完整 PR range 身份 + 隐私核验，推送绑定 OID；身份值来自用户/项目确认，不用仓库级 config。
4. PR 标题与正文分别写入文件，用 `safe-pr.py create --base <base> --head <branch> --expected-head <full-oid> --title-file <title> --body-file <body>` 建 Draft；PR 文本隐私由 helper 内置检查覆盖，后验 PR 元数据。完整参数以 git-workflow 为准。
5. 独立 review + checks；用户授权后才可能合并——默认不合并、不转 Ready。

## 发布包构建要点

- **允许清单**：显式列入的条目才进包；不做「整目录减黑名单」。
- **范围合同**：对照用户确认的通用能力、兼容入口、示例与必要测试核允许清单。用户要求完整同源时，不能以缩小隐私审查面为由排除仍在自用的通用功能；个人硬编码迁入本地配置，保留通用实现。真正退役功能须单独取得范围依据，并同步全部消费者与文档。
- **二次排除**：允许清单内仍排除运行产物、缓存、私有目录、内部维护文档。
- **候选绑定**：从绑定的 OID/干净导出目录打包（不由运行缓存树直接交包）；产物已存在则拒绝覆盖。
- **manifest**：逐文件 SHA-256 + 整体摘要 + excluded 清单；homepage 未公开时在 manifest 登记。
- **`.gitignore` 随包**：使用者装包后仍受私有层规则保护。

## 私仓 → 公仓迁移

从私仓导出公开 Skill 到公仓目录时：

1. 默认**清洁历史**：在公仓新目录提交当前候选内容，不携带私仓历史。
2. **禁止改 remote 直推**：私仓改名为公仓再推送等于公开全部历史。
3. **本地私有文件不入库**：迁移后工作区可能残留 `*.local.*` 文件（slides 现象），它们被 ignore 保护但不属于公开层；清理时保留本地副本。
4. **版本衔接**：私仓版本轨迹按项目规范处理——新公开版本从既有确认版本续编（如私仓 1.5.x → 公仓 1.5.x+1），不重置也不凭空跳号；CHANGELOG 历史条目同样去具体化后保留。
5. **索引同步**：README 技能列表 + 最近更新区 + 所属专家套件页一次对齐；条目数量与排序按目标项目现行规范执行，不在本 Skill 固定数值。

### 两个正交轴：实现源与权威仓库

「单源自用公开同源」管的是**实现份数**：任何时刻只有一份可编辑源码，自用差异走本地配置或数据目录。它不规定这份源码放在哪个仓库。公开化时必须再单独裁决**权威仓库**，否则会出现两份实现各自演进的静默分叉。

| 权威仓库形态 | 适用 | 必要条件 |
|---|---|---|
| 公仓为权威源（整目录迁移） | 公开后继续在公仓演进，私仓不再维护该 Skill | 清洁历史提交整目录；公仓项目规范、README 与套件索引同步；私仓只保留本地配置与状态；安装入口改指公仓目录 |
| 私仓为权威源（导出快照） | 实现与个人运行环境强耦合，公开的是同一源码的版本化导出 | 公开目录仅由绑定 OID 的发行构建产生，禁止在公仓独立编辑实现；CHANGELOG/任务记录写明来源 OID、manifest 与同步方向和节奏；私仓与公仓的差异只允许是发行排除项 |
| 仅本地候选 | 尚未决定发表 | 不建立第二个可编辑副本；候选树保留 OID 与验收证据 |

三种形态都满足单源约束；共同禁止项是「两边都能改实现」。裁决结果写入预检输出，执行中不得中途换形态而不重新对账。

发行排除项同样受功能范围约束，不能把所有旧功能归为“私用兼容层”后自动排除。公开传输包与维护源码可以在本地配置和内部记录上不同，通用行为是否可以不同以用户的范围合同为准。

### 按实际能力做前向检查

先按公开使用说明在隔离目录完成安装与首次配置。其余检查逐项按候选声明的能力适用，不因具备其中一项就强制验证其他能力：

| 候选实际能力 | 前向检查 |
|---|---|
| 可选本地配置 | 未配置时按文档运行；有配置时使用合成值，产物不继承维护者身份 |
| 状态库或其他持久化写入 | 使用专用隔离数据根；核首次初始化与再次运行后的记录保留 |
| 只读会话或文件扫描 | 核来源内容未变、覆盖与失败如实报告；只测已声明的读取范围 |
| HTML 或其他报告生成 | 从实际安装入口生成报告，核输出可打开及其代表性交互 |
| 调度器集成 | 本地核对模板、命令和参数；真实创建与触发另核授权，不为验收自动部署 |

不存在的能力标“不适用”并说明依据，这既不是缺陷也不阻塞结论。适用但未执行的项，以及未验证的 Runtime、平台和调度宿主逐项保留 `NOT_VERIFIED`，并写明它阻塞的范围与恢复条件。

关键门禁（静态安全扫描、隐私检查、适用的行为验证、真实产物生成、版本与索引一致性）未执行或未通过时，公开化整理阶段本身保持未完成，不登记为可豁免的 `NOT_VERIFIED`。其他适用门禁（链接/引用、示例与 schema、ignore 正反例、扩展的平台或 Runtime 覆盖）未执行时记 `NOT_VERIFIED`，不阻塞整理阶段完成，但阻塞依赖该项的发布或稳定性结论。检查不适用不构成缺陷，适用项未验证也不能被“其他门禁通过”覆盖。

演示或教学入口须按公开文档实际执行后续命令：读取合成来源不等于写入状态也已隔离，子进程环境不会回传父 shell；绑定合成来源、数据根并排除继承的生产配置。报告或临时文件承诺保留时，在进程退出后检查其存在性；声明清理时检查只清理本次隔离产物。可选依赖的完整回归与无依赖主路径分开记录，不把预装依赖的测试结果扩大为无依赖通过。

测试通过临时 HOME 隔离用户数据时，另核安装在 user-site 的依赖对子进程是否仍可见，避免把测试环境差异误判为产品缺陷。需要依赖的测试可以显式传递已确认的依赖位置；缺依赖专测必须排除该位置。缺少可选依赖只跳过相应测试并记录数量，其他导入错误和默认主路径失败仍须失败，不能用宽泛捕获掩盖缺陷。

## 发布后验证

- 对公开树重跑同一发布门禁（内容一致性）。
- 安装到独立目录核加载入口与版本（文件存在不等于可调用）。
- 平台上传后核平台侧实际条目与字段。
- 回写任务卡：真实远端/平台回执、OID、剩余 NOT_VERIFIED。
