# 发布前门禁

跑门禁与组织验证时读取。门禁是下界：全部通过不等于公开安全已证明；语义隐私与真实行为仍需独立复审。必须扫描 reference 与 CHANGELOG 中的真实统计表、时间窗口和个人偏好；数字不是凭证也可能暴露个人工作规模。已推送过的内容须检查完整历史，不能以当前文件删除冒充撤回。

## 门禁矩阵

| 检查 | 工具/方式 | 必须覆盖 |
|---|---|---|
| 结构与 frontmatter | skill-creator `quick_validate.py` | 命名、frontmatter、无脚手架占位 |
| 静态安全 | skill-lint `security_scan.py audit` | 危险执行、外传、凭证、提示注入；有 critical/high 即 fail |
| Harness 失效 | skill-lint `harness_failure_audit.py audit` | 约束/验证/证据绑定缺失 |
| 示例与 schema | 专用验证器或 JSON Schema 子集校验 | 成对解析、字段封闭；坏文件非零退出 |
| 链接与引用 | 脚本检查 Markdown 相对链接 | 被引用文件存在；无悬空引用 |
| 版本一致 | 脚本或人工 | SKILL.md 版本 = CHANGELOG 最新 = 其他声明版本 |
| ignore 覆盖 | 复现目标仓库各级规则的 Git 正反例 | 新增 `*.local.*` 不被跟踪；example/schema 可跟踪 |
| 打包排除 | 发布检查脚本 | 私有层/内部文档/运行产物不在发布集合 |
| 隐私模式 | 优先复用目标仓等价门禁；否则在目标 Skill 内自建 | 见下节；skill-lint/Git 通用扫描不覆盖中文专名，slides 的公开 check-privacy.js 是已知实现 |
| 离线测试 | `python3 -m unittest` / 项目测试 | 脚本行为回归，含错误路径 |
| 候选绑定证据 | skill-lint `harness_evidence_gate.py` | 有可执行 checker 时取得 `HARNESS_REVIEW_VERIFIED`；纯文档 Skill 标 NOT_VERIFIED，不凭空造 checker |

### 结构工具的项目差异

`quick_validate.py` 是通用结构检查，不同项目可能把 `version`、`author`、`homepage` 放在根 frontmatter 或 `metadata`，并有自己的发布字段规范。公开化时按以下顺序处理：

1. 先读取目标仓项目发布配置和同类已公开 Skill 的实际 frontmatter。
2. 目标项目要求的字段以目标仓规范为准，不因通用白名单更窄而删除；字段层级与位置另见 skill-lint 的 `references/frontmatter-metadata-policy.md`。
3. 记录实际使用的校验器脚本路径与其 SHA-256（多数通用校验器不带版本号）；若它拒绝项目合法字段，该结构项标 `NOT_VERIFIED`，继续用其他门禁，不修改目标 Skill 来迎合不匹配的通用工具。
4. 独立 reviewer 复核项目规范、同类样例与候选 frontmatter 三者一致。

## 派生统计与发布正文

先区分统计的来源：私人会话数量、实际预算和可关联私人运行的统计可能暴露工作规模，应留在本地任务记录与仓外回执，不写进 README、CHANGELOG 公开条目、PR 或提交说明。公开候选本身的文件清单、已公开版本、功能页数与合成测试数量可以披露，但应绑定公开候选或明确的合成样例；不能由“只是数字”推断安全，也不能把公开发布所需的元数据一概判为隐私。

## 隐私模式检测设计

slides 案例的收敛原则：**不是维护者私有的客户名单，而是通用模式——凡提交内容里明显含具体名称的都拦**。本 Skill 不内置该脚本；优先复用目标仓/目标 Skill 的等价门禁（例如公开 slides 的 `scripts/check-privacy.js`），复用时须补齐本节「不回显原文」与 strict 语义差距。没有等价门禁时，可在目标 Skill 内实现，也可用仓外或既有通用检查器完成同一门禁；检查器位置可变，正反例、退出码合同和证据要求不变。纯提示词 Skill 不得为满足门禁凭空增加用户可见功能。

| 类别 | 检测目标 | 误报控制 |
|---|---|---|
| 具体机构名 | 2-5 汉字 + 机构后缀 | 泛指前缀豁免（尤其/面向/各级…） |
| 人名+职称 | 2-4 汉字 + 律师/教授等 | 同上 |
| 本机绝对路径 | 家目录形态等 | 无 |
| 内部编号 | `DEC-数字`、memo 前缀 | 无 |
| 联系方式 | 微信 ID、手机号、邮箱 | 无 |
| 个人素材文件名 | 含二维码/头像/身份证的文件 | 无 |
| 真实业务路径 | 培训班/课件目录 | 泛指豁免 |
| 配置文件从严 | 身份/联系/素材字段必须为空 | 发布模板必须空 |

**登记表豁免**：有意保留的发布元数据（作者署名）逐条登记 `file`、匹配规则、理由、复核结论；可审计、评审逐条质疑；登记表越长越可疑。优先沿目标项目的既有记录机制；若目标确需文件化配置，同时提供 `config/privacy-exemptions.example.yaml`、对应 schema 和明确的校验入口。本技能只提供下述字段示意，不声称已附带该模板或校验器。本地复核记录放 `config/privacy-exemptions.local.yaml` 并被私有层规则忽略：

```yaml
schema: skill-privacy-exemptions.v1
exemptions:
  - file: LICENSE.txt
    match: "<escaped pattern>"
    reason: "版权署名（发布元数据）"
    review: "2026-01-01 人工复核通过"
```

**报告纪律**：findings 只含相对路径、行号、规则码、修复提示；命中原文（密钥、邮箱、路径片段）不回显。

**目标退出码合同**：0=通过，1=命中（或 strict 模式下 warn），2=用法/读取失败；以退出码为准，不以肉眼扫描为准。这是新门禁的推荐合同；既有工具可能只有 0/1 或缺少 `--strict`，复用时先核对实际行为并补齐差距。

## 负控三件套

1. 注入各类真实痕迹样例 → 全部命中（验证召回）。
2. 泛指与虚构示例 → 零误报（验证精度）。
3. 干净树 → 零命中（验证基线）。

反例集：错误类型、缺必填、额外字段、外部引用、损坏 JSON——各自非零退出。

## 独立复审

- 指派**无旧上下文**的只读 reviewer，绑定当前候选 OID；给结构化输出（分级发现 + 文件行号 + 建议），不给自由叙述。
- PM 独立验收：复跑关键门禁、核对文件清单与 diff，不采信 worker 自报。
- 至少两轮：第二轮**换更宽判据**再扫一遍（slides 教训：第一轮通过后宽判据仍抓出 8 处漏网）。
- 复审发现的个人化残留按本技能剥离参考处理；阻断项关闭前不发表完成结论。

## 前向测试

无旧上下文的使用者视角验证：

- 只读 SKILL.md + 参考文档，能否正确完成首次配置？
- 空配置/匿名缺省路径是否可用（不报错、不含个人信息）？
- 配置了合成身份后，产物元数据是否与维护者身份隔离？

行为依赖 Agent 理解的 Skill，前向测试是比静态检查更强的证据。
