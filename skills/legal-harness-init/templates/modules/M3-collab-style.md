# M3 协作偏好片段库

agent 在用户卡壳时主动调出本片段库参考。

## 使用场景

用户卡在以下问题时参考：

- "详尽 vs 简洁怎么选？"
- "批注 vs 修订怎么选？"
- "中英文怎么选？"

## 详略片段

### 详尽

```markdown
- 详尽：每个法律观点附依据（法条 / 案例 / 实务惯例）
```

适用：

- 审查意见书（给律师同行看）
- 法律意见书
- 学术论文
- 复杂法律分析

### 适中

```markdown
- 适中：要点 + 关键理由
```

适用：

- 备忘录
- 内部意见
- 修改建议
- 合同审查（给非律师业务部门看）

### 简洁

```markdown
- 简洁：只给结论和行动项
```

适用：

- 摘要
- 要点清单
- 行动项
- 给老板/客户的高层沟通

## 批注 vs 修订片段

### 批注

```markdown
- 批注：保留原文，在旁边加意见
```

适用：

- 多人协作（保留讨论痕迹）
- 给客户看的（保留原文让客户理解）
- 复杂法律文件（不希望直接覆盖）

### 修订

```markdown
- 修订：直接修改原文，保留修改痕迹
```

适用：

- 自己用的工作文件
- 与对方律师交换的版本
- 标准化合同模板

### 两个都要

```markdown
- 批注 + 修订：先批注建议、再给修订版
```

适用：

- 重要法律文件（既要看原文又要看修改）
- 给客户的高优先级合同
- 与对方律师交换的初次版本

## 语言片段

### 中文

```markdown
- 中文
```

### 英文

```markdown
- 英文
```

适用：涉外业务、主要服务英语客户。

### 中英混排

```markdown
- 中英混排：中文沟通，关键英文术语保留
```

适用：跨境业务、需要参考英文资料的场景。

## 风格片段

### 法律严谨

```markdown
- 风格：法律严谨（用法律术语，引用法条）
```

适用：

- 律师同行间的交流
- 正式法律意见
- 学术研究

### 通俗易懂

```markdown
- 风格：通俗易懂（少用术语，给客户看的）
```

适用：

- 给非律师客户
- 给业务部门
- 培训学员

### 学术风格

```markdown
- 风格：学术风格（重论证、引文献）
```

适用：

- 学者/研究
- 学术论文
- 学术培训

## 完整组合片段

### 诉讼律师（默认组合）

```markdown
## 协作偏好

- 详尽：每个法律观点附依据（法条 / 案例 / 实务惯例）
- 修订：直接修改原文，保留修改痕迹
- 中文（必要时保留英文专有名词）
```

### 非诉律师（适中 + 批注）

```markdown
## 协作偏好

- 适中：要点 + 关键理由
- 批注：保留原文，在旁边加意见
- 中文
```

### 企业法务（适中 + 修订 + 通俗）

```markdown
## 协作偏好

- 适中（给业务部门看的，少用术语）
- 修订：直接修改合同条款
- 中文
- 风格：通俗易懂
```

### 涉外律师（详尽 + 修订 + 中英混排）

```markdown
## 协作偏好

- 详尽
- 修订（英文合同直接改）
- 中英混排：中文沟通，关键英文术语保留
```

### 培训师（适中 + 通俗）

```markdown
## 协作偏好

- 适中
- 通俗易懂（培训学员非律师背景）
- 中文（案例用真实案件脱敏）
```

### 法律研究/学者（适中 + 学术）

```markdown
## 协作偏好

- 适中（学术写作但要可读）
- 批注（保留原文便于修改）
- 中文（必要时保留英文文献原文）
- 风格：学术风格
```

## 详略 vs 产出的关系

| 详略 | 适合产出 | 不适合产出 |
|---|---|---|
| 详尽 | 审查意见书、法律意见书、研究报告 | 给客户看的简要沟通 |
| 适中 | 备忘录、内部意见、修改建议 | 学术论文、法律意见书 |
| 简洁 | 摘要、要点清单、行动项 | 复杂法律分析 |

## 后续动作

agent 拿到用户回答后：

1. 取最贴近的片段
2. 根据用户的实际偏好微调
3. 写入 AGENTS.md 的 M3 段（建议 3-5 行）

不需要每个维度都写——只写用户最在意的 2-3 个维度。
