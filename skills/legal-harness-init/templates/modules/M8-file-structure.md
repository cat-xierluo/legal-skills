## 使用场景

用户卡在以下问题时参考：

- "项目用什么目录模板？"
- "命名约定怎么定？"
- "哪些文件不进 git？"

## 按项目类型的文件结构片段

### 诉讼 + new-case 模板

```markdown
## 文件结构

- 使用 `new-case` 12 目录模板
- 案件档案根目录：`{内部项目代号}/`；真实案号只放受控事实载体
- 命名约定：`YYMMDD 文件描述.{ext}`（日期读 mtime）
- 不进 git：草稿、客户原始材料、录音录像
```

### 非诉合同 + 自由目录

```markdown
## 文件结构

- 不使用 new-case 模板，按业务类型自建目录：
  - `01 DD 报告/`
  - `02 合同版本/`
  - `03 沟通记录/`
  - `04 工作底稿/`
- 命名约定：`v{N}_{YYMMDD}_{描述}.docx`（版本 + 日期 + 描述）
- 不进 git：客户提供的机密材料、待签版本
```

### 知产 + new-case 模板（按业务子类型）

```markdown
## 文件结构

- 使用 `new-case` 知产模板：
  - 注册模板（7 目录，含独立商标注册证目录）

- 不进 git：客户图样源文件、内部沟通
```

## 命名约定片段

### 日期前缀（推荐）

```markdown
- 命名约定：`YYMMDD 文件描述.{ext}`（日期读文件 mtime/birth time）
```

适用：

- 按时间排序
- 多人协作一致
- 法律场景高频（DEC-2026-06-11 已确认）

### 版本号

```markdown
- 命名约定：`v{N}_{YYMMDD}_{描述}.{ext}`（版本 + 日期 + 描述）
```

适用：

- 合同版本管理
- 文档迭代频繁
- 非诉合同场景

### 项目/业务标识

```markdown
- 命名约定：`{内部项目代号}_{业务类型}_{YYMMDD}.{ext}`
```

适用：

- 多项目并行
- 企业法务
- 律所批量案件

### 复合命名

```markdown
- 命名约定：`{内部项目代号}_{业务类型}_v{N}_{YYMMDD}_{描述}.{ext}`
```

适用：

- 复杂项目
- 长期跟踪
- 知产复审

## 不进 git 的内容（法律场景特例）

### 客户原始材料

```markdown
- 不进 git：客户原始材料（合同原件、客户提供的证据等）
```

为什么：含敏感信息，可能不适合进 git。

### 草稿

```markdown
- 不进 git：草稿（中间工作产物）
```

为什么：不是交付物，可能误导。

### 录音录像

```markdown
- 不进 git：录音录像（沟通录音、庭审录像等）
```

为什么：大文件、二进制、不易 diff。

### 内部沟通

```markdown
- 不进 git：内部沟通（IM 记录、邮件等）
```

为什么：隐私、不易管理。

### 客户正本

```markdown
- 不进 git：客户正本（客户签字盖章版）
```

为什么：客户机密、版本管理应在客户侧。

### 待签版本

```markdown
- 不进 git：待签版本（中介状态）
```

为什么：避免误发。

### 压缩包与大体积二进制

```markdown
- 不进 git：压缩包和项目规则指定的大体积二进制；大文件使用提交前检查、LFS 或受控存储处理
```

为什么：git 性能及误提交材料风险；`.gitignore` 不能按实际文件大小匹配。

## .gitignore 法律场景范本

```gitignore
# 草稿
**/drafts/
**/*.draft.*
**/_draft/

# 客户原始材料
**/客户材料/
**/01 - *客户*
**/原始材料/

# 本地受控事实
.legal-context.local.md
**/.legal-context.local.md

# 录音录像
**/*.mp3
**/*.mp4
**/*.mov
**/*.wav

# 内部沟通
**/IM/
**/聊天记录/
**/邮件/

# 客户正本
**/正本/
**/原件/
**/签字盖章/

# 待签版本
**/待签/

# 大文件
*.zip
*.rar
*.7z
# Git 不支持按文件大小写 gitignore；大文件需在写入前检查或使用 LFS/受控存储。

# 临时文件
.DS_Store
*.tmp
*.swp
*~

# IDE
.vscode/
.idea/
```

## 完整组合片段

### 严格模式（高敏感）

```markdown
## 文件结构

- 使用 new-case 12 目录模板
- 命名：`YYMMDD 描述.{ext}`
- 不进 git：草稿、客户原始材料、录音录像、内部沟通、客户正本、待签版本
- 启用 .gitignore 范本（见 references/）
```

### 低敏模式（个人/学习）

```markdown
## 文件结构

- 自由目录（按需）
- 命名：`YYMMDD 描述.md`
- 不进 git：凭证、个人信息、来源受限材料和本地受控事实文件；其余按项目规则确认
```
