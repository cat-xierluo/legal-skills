# 14 - M8 文件结构约定深度讲解

## 模块定位

回答"这个项目用什么目录模板、命名约定、哪些文件不进版本"。**项目级**，每个项目可能不同。建议 3-8 行。

## 引导问题范本

agent 会按以下顺序问：

1. **是否用 new-case 的目录模板？**（必答）
   - 诉讼：12 目录模板
   - 知产：7/8 目录模板（按业务子类型）
   - 咨询：2 目录模板
   - 不使用：自由目录
2. **命名约定？**（可选）
   - 是否加 YYMMDD 日期前缀
   - 是否按"项目代号_材料类型_日期"格式
3. **哪些文件不进 git？**（必答）
   - 草稿 / 客户提供的原始材料 / 内部沟通 / 音视频 / 大文件
4. **是否有特殊的目录结构需求？**（可选）

## 常见答案片段

参考 [templates/modules/M8-file-structure.md](../templates/modules/M8-file-structure.md) 的完整片段库。

### 诉讼 + new-case 模板

```
## 文件结构

- 使用 `new-case` 12 目录模板
- 案件档案根目录：`{内部项目代号}/`；真实案号只放受控事实载体
- 命名约定：`YYMMDD 文件描述.{ext}`（日期读 mtime）
- 不进 git：草稿、客户原始材料、录音录像、内部沟通
```

### 非诉合同 + 自由目录

```
## 文件结构

- 不使用 new-case 模板，按业务类型自建目录：
  - `01 DD 报告/`
  - `02 合同版本/`
  - `03 沟通记录/`
  - `04 工作底稿/`
- 命名约定：`v{N}_{YYMMDD}_{描述}.docx`（版本 + 日期 + 描述）
- 不进 git：客户提供的机密材料、待签版本
```

### 知产 + new-case 模板（按业务子类型）

```
## 文件结构

- 使用 `new-case` 知产模板：
  - 注册模板（7 目录，含独立商标注册证目录）
  - 异议/复审/无效模板（8 目录，含独立商标注册证目录）
- 申请文件加 `YYMMDD ` 前缀（日期读文件 mtime）
- 不进 git：客户图样源文件、内部沟通
```

### 企业法务 + 自建目录

```
## 文件结构

- 自建目录：
  - `01 待审合同/`
  - `02 已审合同/`
  - `03 合规文档/`
  - `04 内部意见/`
  - `05 模板库/`
- 命名约定：`{业务线}_{合同类型}_{YYMMDD}.docx`
- 不进 git：合同正本（客户机密）、待签版本
```

### 法律研究 + 自建目录

```
## 文件结构

- 自建目录：
  - `01 课题资料/`
  - `02 文献综述/`
  - `03 案例汇编/`
  - `04 研究报告/`
  - `05 培训讲义/`
- 命名约定：`v{N}_{YYMMDD}_{章节}.md`
- 不进 git：来源受限文献、客户材料、含个人信息的案例材料和未脱敏工作底稿；其余是否入库按项目规则确认
```

## 文件结构

## 与 new-case skill 的协作

`new-case` skill 会创建标准化目录。本 skill 在 M8 里**推荐**使用 new-case 模板，但不强制——用户可以选"不用 new-case"。

详见 `new-case` skill 的 SKILL.md。

## .gitignore 的法律场景特例

法律项目特别需要 gitignore 的内容：

| 类型 | 为什么 |
|---|---|
| 客户原始材料 | 含敏感信息，可能不适合进 git |
| 草稿 | 工作中产物，不是交付物 |
| 录音录像 | 大文件、二进制、不易 diff |
| 内部沟通 | 隐私 |
| 客户正本 | 客户机密 |
| 待签版本 | 中间状态，避免误发 |
| 压缩包/大体积二进制 | git 性能及误提交材料风险；用提交前检查、LFS 或受控存储处理 |

agent 会主动提示按项目现有规则配置 `.gitignore`；不能仅凭文件大小规则推断通配模式，也不能把“研究项目”默认等同于全部材料可提交。

## 命名约定的法律场景价值

按时间顺序命名（加 `YYMMDD` 前缀）的好处：

- 按文件名排序就是按时间排序
- 不用看文件 mtime
- 多人协作一致
