# 12 - M6 项目上下文深度讲解

## 模块定位

回答"这个项目是什么类型、编号是什么、委托人是谁、当前在哪一阶段"。**项目级**，每个项目不同。建议 3-5 行。

## 与 M1 的关系

- **用户级 M1**：你的稳定身份（律师 + 上海执业 + 主营诉讼）
- **项目级 M6**：本项目的具体身份（我作为 XX 公司代理人参与 XX 案）

两者不冲突。

## 引导问题范本

agent 会按以下顺序问：

1. **这是什么类型的法律工作？**（必答，单选）
   - 诉讼 / 非诉合同 / 知产 / 企业法务 / 法律研究 / 其他
2. **项目编号？**（必答）
   - 诉讼：`[YYYY]法院代号+民/刑/行+初/终+XXXX号`（如 `(2026)沪0115民初1234号`）
   - 非诉：`{YYMMDD} {客户简称} {业务类型}`（如 `260812 ABC 并购 DD`）
   - 知产：申请号（如 `商标 12345678` 或 `专利 CN2024XXXXXX.X`）
   - 法务：内部编号
   - 研究：课题编号
3. **委托人/客户？**（必答）
   - 自然人 / 法人 / 内部部门
   - 简短描述（脱敏或简称）
4. **当前阶段？**（必答）
   - 诉讼：诉前 / 立案 / 审理 / 判决 / 上诉 / 执行
   - 非诉：DD / 谈判 / 签约 / 交割 / 后合同
   - 知产：申请 / 审查 / 驳回复审 / 注册 / 续展
   - 法务：常法服务 / 专项
   - 研究：选题 / 调研 / 撰写 / 评审

## 好 vs 坏

### 好的 M6

```
# 项目：诉讼 · (2026)沪0115民初1234号

- 类型：合同纠纷
- 委托人：上海 ABC 科技有限公司
- 对方：上海 XYZ 有限公司
- 阶段：审理中
- 关键时点：举证 09-01，开庭 09-15
```

- 一行讲清类型 + 编号
- 后续逐条列举关键事实
- agent 读完能精准定位项目

### 坏的 M6

```
# 当前项目

我们正在处理一个诉讼案件，是关于合同纠纷的。客户是上海一家科技公司。对方也是上海的一家公司。现在案件在审理中。

```

- 没编号——复盘无法定位
- "上海一家科技公司"不具体
- 没关键时点——agent 不知道紧迫程度

## 与 M7 的关系

M6 描述项目是什么（宏观），M7 描述项目关键事实（细节）。

- M6 = 类型、委托人、阶段
- M7 = 案号、管辖、对方当事人、关键时点（按项目类型动态）

两者一起回答"这个项目到底在做什么"。

## 跨项目的复用

M6 是项目级，**每个项目一份**。同一用户处理多个项目时：

- 用户级 `~/.claude/CLAUDE.md` 含 M1-M5（跨项目稳定）
- 项目 A 的 `<项目 A>/AGENTS.md` 含 M6-M8 + M5 细化（项目 A 专属）
- 项目 B 的 `<项目 B>/AGENTS.md` 含 M6-M8 + M5 细化（项目 B 专属）

agent 在项目 A 目录下工作时只读 M1-M5 + A 的 M6-M8，不会受 B 影响。
