# 11 - M5 回溯契约深度讲解（与 §06 联动）

## 与 §06 的关系

[references/06-audit-trail-contract.md](06-audit-trail-contract.md) 讲**机制**（什么是回溯契约、为什么、写入位置原则）；本节讲**M5 模块本身**（怎么回答、用户级 vs 项目级、措辞范本）。

## 模块定位

回答"AI 做了哪些动作必须留痕、写到哪里、什么格式"。

- **用户级 M5**：总开关 + 通用触发场景（覆盖你常做的几类工作）
- **项目级 M5 细化**：本项目特有的留痕场景（叠加用户级总开关）

## 用户级 M5 引导问题

agent 会按以下顺序问：

1. **是否开启回溯契约？**（默认开）
   - 法律人强烈建议开启
2. **通用触发场景**（必答，按你常做的工作勾选）：
   - 关键决策（合同条款、责任限制、管辖、价款）→ DECISIONS
   - 案件/项目信息变更（案号、对方、阶段）→ DECISIONS
   - 新增/删除材料 → CHANGELOG
   - 对外发送文书 → 双重确认 + DECISIONS
   - 待办/期限变更 → TASKS
   - 等等
3. **是否有特别想留痕的动作？**（可选）

## 项目级 M5 细化引导问题

在项目级流程结尾问：

1. **本项目有没有特殊的回溯要求？**（必答）
   - 例 1（诉讼）：关键时点（开庭日期、举证期限、上诉期）→ TASKS
   - 例 2（知产）：申请号变更、驳回/复审/无效节点 → TASKS
   - 例 3（非诉）：合同版本切换、签约/交割里程碑 → DECISIONS
2. **本项目核心交付物是什么？**（必答）
   - 例：起诉状、合同、申请文件、研究报告

## 措辞范本（直接可用）

### 用户级 M5 完整段

```
## 回溯契约（Audit Trail Contract）

我是法律工作者，AI 在协助我工作时，必须把以下"关键动作"按以下规则留痕：

### 必须回溯的动作

- 关键决策（条款、管辖、责任、价款）→ docs/DECISIONS.md
- 案件/项目信息变更（案号、对方、阶段）→ docs/DECISIONS.md
- 新增/删除材料 → CHANGELOG.md
- 对外发送文书 → 双重人工确认 + docs/DECISIONS.md
- 期限/时点变更 → TASKS.md

### 回溯原则

- 每次写入必须含日期（YYYY-MM-DD）、上下文、动作、影响
- 不替我下"实质性结论"，但要把达成结论的过程完整留痕
- 不删除已有记录，只追加或标记作废
- 写入前先检查目标文件是否存在、是否已记录同类内容，避免重复
```

### 项目级 M5 细化段

```
## 项目级回溯补充

（按本项目类型自动填入）

### 关键时点

- 开庭日期：YYYY-MM-DD → TASKS.md
- 举证期限：YYYY-MM-DD → TASKS.md
- 上诉期：YYYY-MM-DD → TASKS.md

### 项目特定触发

- 对方当事人变更 → DECISIONS.md
- 证据材料目录结构变更 → CHANGELOG.md
- 策略调整 → DECISIONS.md
```

## 三种留痕文件的典型条目

### DECISIONS.md 范例

```markdown
# DEC-001：管辖法院选择

- 日期：2026-08-12
- 背景：合同纠纷，原告住所地与合同履行地不同
- 选项：A. 原告住所地法院；B. 合同履行地法院；C. 协议管辖法院
- 决定：A. 原告住所地法院
- 影响：起诉状管辖条款相应修改
- 复核：杨卫薪
```

### CHANGELOG.md 范例

```markdown
# CHANGELOG

## 2026-08-12

- 新增证据材料：`/cases/XX/evidence/05-证据材料/合同原件.pdf`
- 来源：客户现场提交
- 影响范围：证据目录结构

## 2026-08-10

- 起诉状 v1 → v2：管辖条款从"原告住所地"改为"协议管辖"
- 影响范围：起诉状全文
```

### TASKS.md 范例

```markdown
# TASKS

## 进行中

- [ ] 举证期限前提交补充证据
  - 案号：(2026)沪0115民初1234号
  - 截止：2026-09-01
  - 负责人：杨卫薪

- [ ] 上诉期内决定是否上诉
  - 案号：(2026)沪0115民初1234号
  - 截止：2026-09-15
  - 负责人：杨卫薪
```

## M5 与其他模块的协作

| 关系 | 说明 |
|---|---|
| M4 → M5 | M4 规定"什么不能做"，M5 规定"做了要留痕"——两者互补 |
| M6 → M5 | M6 描述项目是什么，M5 细化补充本项目特殊留痕场景 |
| 用户级 M5 → 项目级 M5 | 用户级是总开关（覆盖你常做的工作），项目级是补充（针对本项目） |

## 关闭回溯契约的情况（极少数）

**默认开启**。只在以下情况关闭：

- 个人练习 / 学习项目（不留痕无影响）
- 完全私密的内部使用
- 用户明确知道风险并主动选择关闭

agent 会主动说明风险："关闭回溯契约意味着 AI 做了关键工作不会留痕，事后无法复盘/审计。法律工作强烈不建议关闭。"
