# 11 - M5 回溯契约引导

## 与 §06 的关系

[references/06-audit-trail-contract.md](06-audit-trail-contract.md) 规定机制与载体选择；本节规定如何问用户并生成 M5。

## 引导顺序

1. 项目是否已经有决策、证据、期限和交付版本的权威载体？逐类记录名称或路径。
2. 哪些真实变化会影响权利义务、期限、审批、对外承诺或后续判断？
3. 每类记录由谁写、谁复核、谁批准？
4. 哪些字段需要脱敏或只进入受控载体？
5. 没有对应载体时，是标记待补充，还是由用户指定现有系统？

项目类型只用于提示可能的变化：诉讼关注证据/程序期限/策略；非诉关注条款决策/里程碑/交付版本；知产关注申请程序/官期/答复策略；法务关注审批/风险事件/模板版本；研究关注来源/论证取舍/稿件版本。

## 生成规则

- 用“变化类型 → 现有权威载体 → 最少字段”表达。
- 事实变化先写事实/证据载体；只有形成真实策略取舍时再写决策载体。
- 对外发送是权限与审批问题；可记录交付状态，但留痕不等于授权。
- 项目没启用对应文档时不创建空文件，不把所有事项硬塞进 DECISIONS/CHANGELOG/TASKS。
- 期限缺起算事实、送达信息或适用规则时，标记待补充和待人工复核。
- 所有记录遵守 [references/18-privacy-and-context.md](18-privacy-and-context.md)。

## 推荐产物

直接使用 [templates/modules/M5-audit-trail.md](../templates/modules/M5-audit-trail.md) 的通用片段，替换为项目真实权威载体；未知项保留“待补充”。

## 验证问题

用一个虚构场景测试：“举证期限发生变化，应记录在哪里？”

通过条件：agent 先选择项目既有期限台账/任务源，要求核对起算事实和计算依据，并保留责任人/复核状态；不能机械回答 CHANGELOG 或 DECISIONS。
