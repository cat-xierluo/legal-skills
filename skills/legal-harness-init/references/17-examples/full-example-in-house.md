# 参考范例：企业法务

> ⚠️ 这是参考范例，**不直接套用**。展示完整的企业法务 AGENTS.md 长什么样。

## 用户级 `~/.claude/CLAUDE.md`

```markdown
# 公司法务 · 北京 · 服务对象为 TMT 行业某互联网公司

## 工作流与产出

- 合同审查：审查意见 + 修改建议 + 风险提示（给业务部门看，少用术语）
- 合规审查：合规清单 + 风险评级 + 整改建议
- 法律培训：培训讲义 + 案例 + 互动问答
- 内部意见：备忘录 + 决策依据

## 协作偏好

- 适中（给业务部门看的，少用术语）
- 修订：直接修改合同条款
- 中文

## 工具链与禁区

### 允许的工具

- 读/写本地文件
- 检索法规
- 内部知识库查询

### 禁止的动作

- 不要替我对外发送合同
- 不要替代内部审批流程
- 不要替业务部门做最终决策

### 必须人工复核

- 涉及公司治理、合规风险的条款
- 跨境业务合规审查
- 内部规则修订
- 对外交付的文件

## 回溯契约（Audit Trail Contract）

### 必须回溯的动作

- 合规审查结论 → docs/DECISIONS.md
- 模板修订 → CHANGELOG.md
- 风险事件 → docs/DECISIONS.md（含风险等级、应对方案）
- 待办事项 → TASKS.md
- 内部规则修订 → CHANGELOG.md

### 回溯原则

- 每次写入必须含日期、上下文、动作、影响
- 不删除已有记录
- 风险事件须含风险等级和应对方案
```

## 项目级 `<项目>/AGENTS.md`

```markdown
# 项目：法务 · YYYY Q3 合同审查专项

## 上下文

- 类型：内部合同审查
- 服务对象：销售部 + 海外业务部
- 审查范围：与 {客户} 的框架合同 + 配套协议
- 当前阶段：审查中

## 关键事实

- 服务对象：销售部 + 海外业务部
- 服务范围：合同审查（年约 200 份）+ 合规咨询
- 当前重点：跨境数据合规 + 与 {客户简称} 的框架合同审查
- 关键时点：合同定稿 YYYY-MM-DD，内部审批 YYYY-MM-DD

## 文件结构

- 自建目录：
  - `01 待审合同/`
  - `02 已审合同/`
  - `03 合规文档/`
  - `04 内部意见/`
  - `05 模板库/`
- 命名约定：`{业务线}_{合同类型}_{YYMMDD}.docx`
- 不进 git：合同正本（客户机密）、待签版本

## 项目级回溯补充

- 合同重大修改（金额/管辖/责任）→ DECISIONS.md
- 风险事件 → DECISIONS.md（含风险等级、应对方案）
- 模板修订 → CHANGELOG.md
- 内部审批流程变更 → DECISIONS.md
```

## 关键说明

- 企业法务的核心是**服务内部**——M1 不要写成"律师"，要写成"公司法务"
- 协作偏好要适配"非律师读者"——少用术语，详略适中
- 跨境业务合规审查是高频关键场景，M4 中建议单独列出
- 内部审批流程不可由 AI 替代——必须在 M4 明确"不要替代内部审批流程"
