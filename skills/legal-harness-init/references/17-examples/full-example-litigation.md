# 参考范例：诉讼律师

> ⚠️ 这是参考范例，**不直接套用**。展示完整的诉讼律师 AGENTS.md 长什么样，含敏感信息时必须脱敏（用 `{案号}` `{委托人}` `{对方}` 等占位符替代真实信息）。

## 用户级 `~/.claude/CLAUDE.md`

```markdown
# 律师 · 上海执业 · 主营民商事诉讼（合同纠纷/股权纠纷）+ 知识产权诉讼

## 工作流与产出

- 合同审查：审查意见书（条目式 + 风险等级）
- 起诉/答辩：起诉状、答辩状、管辖异议、证据目录
- 庭审准备：代理词、质证意见、庭审提纲
- 复盘：案件复盘报告

## 协作偏好

- 详尽：每个法律观点附依据（法条 / 案例 / 实务惯例）
- 修订：直接修改原文，保留修改痕迹
- 中文（必要时保留英文专有名词）

## 工具链与禁区

### 允许的工具

- 读/写本地文件
- 检索案例/法条
- IM 沟通（已配置）

### 禁止的动作

- 不要替我向法院提交任何文书
- 不要伪造证据材料
- 不要替我对案件做实质性结论（如"本案必胜"）
- 不要删除已有记录

### 必须人工复核

- 起诉状/答辩状/代理词的最终版本
- 证据材料清单
- 涉及金额、管辖、上诉期的判断
- 对外发送文书

## 回溯契约（Audit Trail Contract）

我是法律工作者，AI 在协助我工作时，必须把以下"关键动作"按以下规则留痕：

### 必须回溯的动作

- 案号/管辖/对方当事人变更 → docs/DECISIONS.md
- 新增证据材料 → CHANGELOG.md
- 策略调整 → docs/DECISIONS.md
- 对外发送文书 → 双重人工确认 + docs/DECISIONS.md
- 开庭日期/举证期限/上诉期变更 → TASKS.md

### 回溯原则

- 每次写入必须含日期（YYYY-MM-DD）、上下文、动作、影响
- 不替我下"实质性结论"，但要把达成结论的过程完整留痕
- 不删除已有记录，只追加或标记作废
- 写入前先检查目标文件是否存在、是否已记录同类内容，避免重复
```

## 项目级 `<项目>/AGENTS.md`

```markdown
# 项目：诉讼 · [YYYY]沪0115民初XXXX号

## 上下文

- 类型：合同纠纷（民商事诉讼）
- 委托人：上海 {客户简称} 科技有限公司
- 对方当事人：上海 {对方简称} 有限公司
- 当前阶段：一审审理中
- 关键时点：举证期限 YYYY-MM-DD，开庭 YYYY-MM-DD

## 关键事实

- 案号：[YYYY]沪0115民初XXXX号
- 管辖法院：上海市浦东新区人民法院
- 对方当事人：上海 {对方简称} 有限公司
- 案由：买卖合同纠纷
- 案件标的：人民币 XXX 万元
- 是否涉外：否

## 文件结构

- 使用 `new-case` 12 目录模板
- 案件档案根目录：`[YYYY]沪0115民初XXXX号/`
- 命名约定：`YYMMDD 文件描述.{ext}`（日期读 mtime）
- 不进 git：草稿、客户原始材料、录音录像

## 项目级回溯补充

- 本案关键时点（开庭/举证/上诉）变更 → TASKS.md
- 对方当事人变更 → DECISIONS.md
- 证据材料目录结构变更 → CHANGELOG.md
```

## 关键说明

- 用户级文件跨项目稳定，每个诉讼项目都用同一份
- 项目级文件每个案件一份，结案后归档
- M5 回溯契约在用户级开"总开关"，项目级细化针对本案件的关键时点
