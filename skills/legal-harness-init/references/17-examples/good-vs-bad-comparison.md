# 好 vs 坏：AGENTS.md 对比

## 对比 1：M1 角色身份

### ❌ 坏

```markdown
# 关于我

我是杨律师，毕业于 XX 大学法学院，执业 10 年了。我对工作认真负责，希望 AI 能认真对待每一份材料。我平时主要做诉讼和合同审查。我的手机是 138xxxxxxxx。

```

**问题**：
- 履历对 agent 无用
- 联系方式是隐私
- 没讲业务方向、地域、角色
- "认真负责" agent 不可执行

### ✅ 好

```markdown
# 律师 · 上海执业 · 主营民商事诉讼（合同/股权）+ 知产诉讼

```

**优点**：
- 一行讲清角色、地域、业务方向
- 跨项目稳定
- agent 读完知道默认走"上海法院管辖 / 民商事诉讼惯例"

## 对比 2：M5 回溯契约

### ❌ 坏

```markdown
## 回溯

我希望 AI 在做重要事情的时候记录一下。重要的事情包括案号变化、新增材料、决策这些。具体写到哪里可以参考项目里的 docs 文件夹。

```

**问题**：
- "重要的事情" agent 判断会偏
- "项目里的 docs 文件夹"没说具体文件
- 没说格式
- 句式不像指令

### ✅ 好

```markdown
## 回溯契约

关键动作必须留痕：

- 案号/管辖/对方当事人变更 → docs/DECISIONS.md
- 新增证据材料 → CHANGELOG.md
- 策略调整 → docs/DECISIONS.md
- 对外发送文书前 → 双重人工确认 + DECISIONS.md

写入原则：日期 + 上下文 + 动作 + 影响；不删除已有记录。

```

**优点**：
- 每个触发场景具体到"动作 → 文件"
- 写入位置明确
- 格式原则清晰
- 用祈使句 agent 能直接执行

## 对比 3：M4 工具链与禁区

### ❌ 坏

```markdown
## 工具与红线

AI 可以读文件、写文件、检索，这些都没问题。但是不要替我提交东西到法院，那是我自己做的事情。合同金额要看一下。证据不能伪造，这个很重要。对外发送的文书需要我确认一下。

```

**问题**：
- 没有分点（允许 / 禁止 / 复核）
- 模糊表述（"看一下"、"很重要"）
- 句式不像指令

### ✅ 好

```markdown
## 工具链与禁区

### 允许

- 读/写本地文件
- 检索

### 禁止

- 不要替我向法院提交文书
- 不要伪造证据
- 不要替我做实质性结论

### 必须人工复核

- 合同金额/费率变更
- 关键条款决策
- 对外发送文书

```

**优点**：
- 三段清晰（允许 / 禁止 / 复核）
- 每段列举式
- 祈使句 agent 能直接执行

## 对比 4：M7 案件关键事实

### ❌ 坏

```markdown
## 关键事实

这个案件是上海法院在管的，对方是另一家公司。我们已经在准备起诉状了。

```

**问题**：
- 没案号——无法检索/复盘
- "另一家公司"不具体
- "准备起诉状了"是动作不是事实

### ✅ 好

```markdown
## 关键事实

- 案号：(2026)沪0115民初1234号
- 管辖法院：上海浦东新区法院
- 对方：上海 XYZ 有限公司
- 关键时点：举证 09-01，开庭 09-15

```

**优点**：
- 列举具体事实
- 关键时点显式列出
- agent 读完能精准工作

## 对比 5：M2 工作流与产出

### ❌ 坏

```markdown
## 我的工作

我平时主要做合同审查工作。客户会发合同给我，我需要审查合同里的条款是否合规、是否对客户有利。审查完了我会出具审查意见。我也会做一些诉讼相关的工作，包括写起诉状、答辩状等。另外如果客户有法律研究的需求，我也会做一些研究。

```

**问题**：
- 一段话，agent 不易抽取要点
- 没区分"高频/低频"
- 没明确产出格式

### ✅ 好

```markdown
## 工作流与产出

- 合同审查：审查意见书（条目式 + 风险等级）
- 起诉/答辩：起诉状、答辩状、证据目录
- 庭审准备：代理词、质证意见、庭审提纲

```

**优点**：
- 列举式，3-5 行
- 每类工作对应明确的产出
- agent 读完就知道"我该用什么格式输出"

## 对比 6：M8 文件结构

### ❌ 坏

```markdown
## 文件结构

项目里的文件按照自己的规则组织。一般是建几个文件夹，文件名有规律。具体看实际需要。

```

**问题**：
- 没模板
- "有规律"但没说
- "看实际需要"——agent 不知道

### ✅ 好

```markdown
## 文件结构

- 使用 new-case 12 目录模板
- 命名：`YYMMDD 描述.{ext}`
- 不进 git：草稿、客户原始材料

```

**优点**：
- 三行讲清结构、命名、gitignore
- agent 读完知道怎么创建目录、怎么命名、哪些不提交

## 共性总结

| 好 AGENTS.md 的特征 | 坏 AGENTS.md 的问题 |
|---|---|
| 用祈使句（"不要 X"、"必须 Y"） | 用"我希望"、"建议" |
| 列举式、分段清晰 | 一段话、流水账 |
| 具体到动作和文件 | 抽象模糊 |
| 不超过 80 行 | 100+ 行甚至 200+ 行 |
| 跨项目稳定 | 含项目特定信息 |
| 区分用户级和项目级 | 所有内容堆一起 |
