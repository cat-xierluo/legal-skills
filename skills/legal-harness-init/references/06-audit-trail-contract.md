# 06 - ⭐ 法律人专属：回溯契约机制

## 为什么这是本 skill 的核心

法律工作和普通 AI 协作最大的差别是**可追溯、可审计**。

- 律师工作涉及委托人利益、对方当事人、法院、监管机关——每一份文书、每一个决策都可能产生法律责任
- 律师执业受监管——行政处罚、行业处分、责任追究都需要证据
- 律师要复盘——案号变更、对方变更、策略调整都是过程性决策，事后说不清

**普通用户的 AGENTS.md 不强调回溯**——他们只需要 agent 协作流畅。但法律人 AGENTS.md **必须**规定：哪些动作 AI 必须留痕、写到哪里、什么格式。这是法律 AGENTS.md 和普通 AGENTS.md 的最大差异。

## 一句话结论

**回溯契约 = 在 AGENTS.md 里明确规定"AI 做了哪些动作必须留痕、写到什么文件、什么格式"**。这是 M5 模块的核心。

## 为什么"重要的事情记录一下"不够

朴素表述：

```
❌ 我希望 AI 在做重要事情的时候记录一下。
```

问题：

1. "重要的事情" agent 判断会偏——你以为重要的它可能不记
2. "记录一下" agent 可能写到乱七八糟的地方（聊天输出、临时文件）
3. 没说格式——agent 可能就写一句话，没法复盘

**正确做法是具体到"触发场景 → 文件 → 字段"**：

```
✅ 关键动作必须留痕：

- 案号/管辖/对方当事人变更 → docs/DECISIONS.md（含日期/背景/选项/决定）
- 新增证据材料 → CHANGELOG.md（含文件路径/材料来源/影响范围）
- 策略调整 → docs/DECISIONS.md
- 对外发送文书前 → 双重人工确认 + DECISIONS.md 记录决策
```

## 三个留痕目的地

按动作性质写不同文件（不要都堆一处）：

| 动作性质 | 写到哪里 | 字段 |
|---|---|---|
| **重要决策/取舍** | `docs/DECISIONS.md` | 决策标题、日期、背景、选项、决定、影响 |
| **可观测的历史变更** | `CHANGELOG.md` | 版本、日期、变更类型、影响范围 |
| **进行中/待办** | `TASKS.md` 或 `status/TASKS.md` | 任务、状态、负责人、截止 |

| 动作 | 文件 | 范例字段 |
|---|---|---|
| 案号/管辖/对方变更 | `docs/DECISIONS.md` | `DEC-XXX：变更 X；日期；背景：原 Y；选项：A/B；决定：A；影响：...` |
| 新增证据材料 | `CHANGELOG.md` | `## 2026-08-12 新增证据 1：XX.pdf；来源：客户；影响范围：...` |
| 合同版本切换 | `CHANGELOG.md` | `## v2→v3 切换；日期；变更类型：关键条款；影响：...` |
| 关键条款决策（管辖/责任/担保） | `docs/DECISIONS.md` | `DEC-XXX：管辖条款选 X；日期；选项：...；决定：...；影响：...` |
| 待办（举证/答辩/缴费） | `TASKS.md` | `- [ ] 举证期限 2026-09-01；案号；负责人` |
| 对外发送文书 | `docs/DECISIONS.md` + 双重人工确认 | `DEC-XXX：发送 X 文书给 Y；日期；Z 复核；渠道：...` |

## 按项目类型的回溯触发场景

**诉讼**：
- 案号/管辖/对方当事人变更 → DECISIONS
- 新增证据材料 → CHANGELOG
- 策略调整 → DECISIONS
- 对外发送文书 → 双重确认 + DECISIONS
- 开庭日期/举证期限/上诉期变更 → TASKS

**非诉合同**：
- 合同版本切换 → CHANGELOG
- 关键条款决策（管辖/责任/担保/价款）→ DECISIONS
- 里程碑事件（签约/交割）→ DECISIONS
- 待办事项 → TASKS

**知产**：
- 申请号/阶段变更 → CHANGELOG
- 驳回/复审/无效决策 → DECISIONS
- 续展/年费节点 → TASKS
- 答复策略 → DECISIONS

**企业法务**：
- 合规审查结论 → DECISIONS
- 模板修订 → CHANGELOG
- 风险事件 → DECISIONS
- 待办事项 → TASKS

**法律研究**：
- 研究思路与取舍 → DECISIONS
- 检索结果/案例汇编节点 → CHANGELOG
- 待办（检索/撰写）→ TASKS

## 写入原则（措辞范本）

可直接粘贴到 AGENTS.md 的 M5 段：

```
## 回溯契约（Audit Trail Contract）

我是法律工作者，AI 在协助我工作时，必须把以下"关键动作"按以下规则留痕：

### 必须回溯的动作
（按当前项目类型自动填入，见本文件 §"按项目类型的回溯触发场景"）

### 回溯位置
- 重要决策 → docs/DECISIONS.md
- 用户可见变更 → CHANGELOG.md
- 进行中/待办 → TASKS.md（或 status/TASKS.md，按项目约定）

### 回溯原则
- 每次写入必须含日期（YYYY-MM-DD）、上下文、动作、影响
- 不替我下"实质性结论"，但要把达成结论的过程完整留痕
- 不删除已有记录，只追加或标记作废
- 写入前先检查目标文件是否存在、是否已记录同类内容，避免重复
```

## 写入前检查清单

AI 在写入回溯记录前必须做：

1. **目标文件存在吗？** 不存在则提示用户先创建（或 agent 创建空模板）
2. **是否已有同类记录？** 避免重复追加；如果已有则更新而非新增
3. **格式符合规范吗？** 日期格式（YYYY-MM-DD）、字段完整
4. **是否影响其他记录？** 涉及交叉引用时同步更新

## 不写入的情况

回溯契约有边界——不是所有动作都要写：

- **日常对话中的工具调用**（读文件、跑命令）——不写
- **草稿性质的思考**（agent 自己推理）——不写
- **用户明确要求不记录的私密操作**——不写
- **已经包含在更高层记录里的细节**——不重复

**判别原则**：这个动作**是否会影响后续决策、是否会承担法律责任、是否需要向第三方披露**？任一为是 → 留痕。

## 与其他模块的关系

- M4 工具链与禁区：M4 规定"什么不能做"，M5 规定"做了就要留痕"——两者互补
- M6 项目上下文：M6 描述项目是什么，M5 细化是"本项目要特别注意的留痕场景"
- 用户级 M5 是"总开关"（开启 + 通用触发），项目级 M5 细化是"本项目补充"

## 用户级 vs 项目级 M5

**用户级 M5**：通用触发场景（覆盖你常做的几类工作），如：
- 合同条款决策 → DECISIONS
- 对外发送文书 → 双重确认 + DECISIONS
- 金额/费率变更 → DECISIONS

**项目级 M5**：本项目特有的留痕场景（叠加用户级总开关），如：
- 某案件的关键时点（开庭/举证/上诉）→ TASKS
- 某知产案件的驳回/复审节点 → TASKS
- 某非诉项目的合同版本切换 → CHANGELOG

## 实际范例

### 范例 1：诉讼律师用户级 M5

```
## 回溯契约

关键动作必须留痕：

- 案号/管辖/对方当事人变更 → docs/DECISIONS.md
- 新增证据材料 → CHANGELOG.md
- 策略调整 → docs/DECISIONS.md
- 对外发送文书前 → 双重人工确认 + DECISIONS.md
- 开庭日期/举证期限/上诉期变更 → TASKS.md

写入原则：日期 + 上下文 + 动作 + 影响；不删除已有记录。
```

### 范例 2：知产权律师项目级 M5 细化

```
## 项目级回溯补充（针对 {申请号}）

- 商标局发文 → CHANGELOG.md（含发文日期、文书类型）
- 驳回/复审/无效决策 → DECISIONS.md
- 续展节点前 60 天 → TASKS.md
- 客户对申请文件的实质修改 → DECISIONS.md（含改前/改后）
```
