# 09 - M3 协作偏好深度讲解

## 模块定位

回答"你希望 AI 怎么和你协作"。**用户级**，跨项目稳定。建议 3-5 行。

## 回答什么

| 维度 | 问什么 | 为什么需要 |
|---|---|---|
| 详略 | 详尽 / 适中 / 简洁 | 决定 agent 输出篇幅 |
| 批注 vs 修订 | 批注（不改原文）/ 修订（直接改）/ 两个都要 | 决定 agent 处理文档的方式 |
| 中英文 | 中文 / 英文 / 中英混排 | 决定 agent 默认语言 |
| 风格 | 法律严谨 / 通俗易懂 / 学术风格 | 决定 agent 措辞 |

## 引导问题范本

agent 会按以下顺序问：

1. **详尽 vs 简洁？**（必答，单选）
   - 详尽：每个要点都展开（含背景、依据、建议）
   - 适中：要点 + 关键理由
   - 简洁：只给结论和行动项
2. **批注 vs 修订？**（必答，可多选）
   - 批注：保留原文，在旁边加意见
   - 修订：直接修改原文（含删除/添加/替换）
   - 两个都要：先批注建议、再给修订版
3. **语言？**（必答）
   - 中文 / 英文 / 中英混排
4. **风格？**（可选）
   - 法律严谨（用法律术语，引用法条）
   - 通俗易懂（少用术语，给客户看的）
   - 学术风格（重论证、引文献）

## 常见答案片段

参考 [templates/modules/M3-collab-style.md](../templates/modules/M3-collab-style.md) 的完整片段库。

### 诉讼律师（默认详尽 + 修订 + 中文）

```
## 协作偏好

- 详尽：每个法律观点附依据（法条 / 案例 / 实务惯例）
- 修订：直接修改原文，保留修改痕迹
- 中文（必要时保留英文专有名词）
```

### 非诉律师（适中 + 批注 + 中文）

```
## 协作偏好

- 适中：要点 + 关键理由
- 批注：保留原文，在旁边加意见（便于客户/律师讨论）
- 中文
```

### 企业法务（适中 + 修订 + 中文）

```
## 协作偏好

- 适中（给业务部门看的，少用术语）
- 修订：直接修改合同条款
- 中文
```

### 涉外律师（详尽 + 修订 + 中英混排）

```
## 协作偏好

- 详尽
- 修订（英文合同直接改）
- 中英混排：中文沟通，关键英文术语保留
```

### 培训师（适中 + 通俗 + 中文）

```
## 协作偏好

- 适中
- 通俗易懂（培训学员非律师背景）
- 中文（案例用真实案件脱敏）
```

## 好 vs 坏

### 好的 M3

```
## 协作偏好

- 详尽：每个法律观点附依据
- 修订：直接修改合同条款
- 中文
```

- 三个维度都明确
- 一行一个要点
- agent 读完能直接执行

### 坏的 M3

```
## 协作偏好

我希望 AI 帮我处理事情时能尽量详细一点，但也不要太长。修改合同的时候要看具体情况，能直接改就直接改，不能改的就给我建议。语言用中文就好。

```

- 表述模糊（"尽量详细"、"看具体情况"）
- 三心二意（"能直接改就直接改" = 不可执行）
- agent 不知道该按哪个走

## 详略 vs 产出的关系

| 详略 | 适合产出 | 不适合产出 |
|---|---|---|
| 详尽 | 审查意见书、法律意见书、研究报告 | 给客户看的简要沟通 |
| 适中 | 备忘录、内部意见、修改建议 | 学术论文、法律意见书 |
| 简洁 | 摘要、要点清单、行动项 | 复杂法律分析 |

## 批注 vs 修订的边界

**批注适合**：
- 多人协作（保留讨论痕迹）
- 给客户看的（保留原文让客户理解）
- 复杂法律文件（不希望直接覆盖）

**修订适合**：
- 自己用的工作文件
- 与对方律师交换的版本（对比清楚）
- 标准化合同模板

**两个都要适合**：
- 重要法律文件（既要看原文又要看修改）

## 与语言的关系

**默认中文**大多数中国法律人都选。但要注意：

- 涉外业务保留英文专有名词（"force majeure"、"indemnity"）
- 学术研究用中英文献引用格式
- 翻译/对比文件保留双语对照
