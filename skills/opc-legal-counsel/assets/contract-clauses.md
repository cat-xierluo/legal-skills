# 合同条款设计工具箱

本文件提供业务结构和占位模板，不提供可直接粘贴的最终法律文本。先根据 `references/contracts.md` 完成交易判断，再结合检索结果和谈判位置改写。

## 一、主体与授权

核查签约、履行、付款、开票和持有权利的主体；签字人无显然权限时，要求提供授权链。

```text
双方确认，本合同项下的签约主体、履行主体、收付款账户及联系人如下：【逐项填写】。
任何主体或授权变化，应由有权主体通过约定通知方式确认；未经确认，不当然改变本合同的权利义务承担。
```

## 二、范围与依赖

把“做一个系统”“按客户要求”等抽象描述拆成交付物、排除项、环境、资料、人员和第三方依赖。

```text
交付范围以附件【范围基线】为准。未列入范围的需求，按变更程序评估对费用、工期、资源和风险的影响后实施。
甲方应在【节点】提供【资料/环境/权限】；因协作条件未满足导致的影响，由双方在变更单中确认。
```

## 三、变更机制

```text
提出变更的一方应说明变更内容、原因和期望时间。承接方评估工作量、费用、进度、数据和权利影响后，双方通过【有权确认方式】形成变更单。变更单生效前，继续执行原基线，但继续执行会造成明显损失的除外。
```

## 四、交付与验收

验收应具有客观标准、测试环境、反馈期限、缺陷分级、修复轮次和最终确认记录。具体期限由项目复杂度和双方资源确定，不套用固定天数。

```text
乙方按【交付清单】提交至【位置】并通知甲方。甲方按附件【验收标准】完成测试，逐项反馈可复现问题及证据。双方区分阻断交付的问题与不影响主要使用的问题，并按【修复/确认流程】处理。
```

## 五、价款、税费与付款

不要预设固定首付款比例或税率。付款节点应覆盖前期投入，并与可验证交付对应；税务口径需由当前有效规则和实际纳税身份核验。

```text
合同价款、是否含税、票据类型和开票信息见附件【商务条款】。如适用税务规则或双方纳税身份发生变化，双方依据经核验的现行规则协商调整开票安排；未经书面确认，不当然改变未税价或服务范围。
```

## 六、知识产权与第三方材料

分别处理背景成果、新产生的定制成果、通用能力、开源组件、模型、素材和客户资料。

```text
各方在合同签署前已拥有或独立形成的背景成果仍归原权利人。项目新成果的权利安排、许可范围和移交条件见附件【成果清单】。第三方材料按其许可条件使用，双方不得要求对方转让其无权处分的权利。
```

## 七、数据与保密

```text
双方仅为履行本合同处理必要数据，并按附件【数据处理说明】约定角色、目的、范围、访问、供应商、留存、删除和事件协作。未经有权确认，不得将对方数据用于训练、营销或其他独立目的。
```

保密条款应明确秘密信息边界、例外、访问人员、使用目的、返还删除和违约处置；不要把公开信息或依法独立取得的信息一概纳入。

## 八、保证、责任与补救

把可控制的行为义务与不可保证的结果分开。责任上限、排除损失和例外必须结合交易金额、可控风险、保险、数据与知识产权暴露谈判，不使用固定比例。

```text
一方发现可能影响履行的事件时，应及时通知并采取合理减损措施。发生不符合约定的交付时，优先按【修复、替换、重做、退款或终止】顺序补救；无法补救或达到约定严重程度时，守约方可采取进一步措施。
```

## 九、暂停、终止与交接

```text
发生【持续不付款/重大协作失败/安全事件/严重违约】时，受影响方可按约定程序暂停相应履行。终止时，双方按附件【退出清单】完成费用结算、成果交付、账号权限、数据返还删除、保密和持续服务安排。
```

## 十、通知与争议

约定可证明送达的地址、邮箱或系统；争议条款的有效性、管辖连接点、仲裁机构名称和程序要求必须外部核验。

## 使用检查

- 条款是否反映真实交易，而非复制通用模板；
- 权利与责任是否落在实际可控制的主体；
- 交付、验收、付款和权利移转是否对应；
- 第三方模型、数据、素材和分包是否进入合同；
- 变更、失败、暂停、终止和交接是否可执行；
- 需要精确法律依据的内容是否已标注检索状态。
