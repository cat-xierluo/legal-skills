# OPC 经营法律风险自检

使用方法：每一项记录“是 / 否 / 不适用 / 待核”，并附责任人、证据和截止日期。标记“待核”的规则命题按 `references/legal-retrieval-protocol.md` 创建检索任务。

## 主体与治理

- [ ] 已明确法律主体 OPC 与经营模式 OPC 的区别
- [ ] 签约、履行、收付款、开票和持有资产的主体可对应
- [ ] 公司与个人的账户、合同、账簿、资产和费用可区分
- [ ] 股东借款、报销、关联交易和重大支出有真实依据与留痕
- [ ] 联合创始人、代持、顾问股、分成和退出安排已书面化
- [ ] 核心账号、印章、域名、代码库和支付权限有备份与交接

## 合同与履约

- [ ] 已核验对方主体、签约权限和收款账户
- [ ] 范围、排除项、依赖和变更程序清楚
- [ ] 交付、验收、付款与权利移转相互对应
- [ ] 第三方模型、素材、组件、数据和分包已分配责任
- [ ] 责任、补救、暂停、终止和退出机制可执行
- [ ] 报价、宣传、聊天承诺和正式合同不存在未解释冲突

## 财税与资金

- [ ] 每笔主要收入可对应业务、合同、交付、资金和票据
- [ ] 私户、平台或第三方代收付均有台账和商业解释
- [ ] 股东取款、报销、借款、分红和服务费按真实原因处理
- [ ] 当前税率、优惠、申报和票据要求已由权威来源或专业人员核验
- [ ] 已建立流水、凭证、申报和异常提醒的定期复核

## AI、数据与知识产权

- [ ] 已画出模型、数据、内容、用户、供应商和责任链
- [ ] 已区分内部、特定客户和公众开放场景
- [ ] 已识别错误输出、误导、侵权、泄露和滥用的业务后果
- [ ] 具备人工复核、权限、停止、回滚、投诉和事件响应机制
- [ ] 数据目的、范围、共享、留存、删除和供应商访问可解释
- [ ] 代码、模型、素材、数据集和成果的来源与授权有证据
- [ ] 上线日期适用的标识、许可、备案、公示或行业义务已外部核验

## 用工

- [ ] 员工、顾问、兼职、实习和外包关系与实际管理一致
- [ ] 工作或交付、报酬、成果、保密和退出已书面约定
- [ ] 绩效、变更、请假和日常管理持续留痕
- [ ] 离场时可完成账号、设备、数据、客户和成果交接
- [ ] 工资、社保、解除、补偿和当地程序已由现行依据核验

## 监管与争议

- [ ] 业务准入、许可、备案和宣传限制已按经营地与日期核验
- [ ] 产品能力、证据和公开承诺一致
- [ ] 投诉、平台处置和监管文件有统一登记与负责人
- [ ] 合同、流水、交付、页面、日志和沟通可形成时间线
- [ ] 已识别期限、资产、证据灭失和持续损害风险
- [ ] 高风险事件已准备专业人员交接材料包

## 结果分级

- **立即行动**：风险正在持续、证据可能消失、期限临近或外部机构已介入；
- **近期补救**：结构性缺口已存在，但仍可通过梳理和补救降低风险；
- **制度建设**：尚未发生事件，用流程、模板和权限防止复发；
- **待检索**：具体规则未核验，不得据此作确定性对外承诺。
