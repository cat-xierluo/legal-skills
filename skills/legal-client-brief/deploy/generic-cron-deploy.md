# 纯 cron / launchd / CI 的能力边界

## 结论

纯命令调度器只能执行确定性脚本，不能独立完成需要语义判断的选题、联网研究、事实冲突处理和法律表达。因此，本技能不提供“省略 Agent 步骤但声称自动生成客户简报”的 cron、launchd 或 GitHub Actions 样例。

## 可接受的两阶段模式

1. **Agent 阶段**：具备 Skill、联网和文件权限的 Agent 生成完整简报、朋友圈和公众号三份 `_DRAFT` Markdown，并通过白名单、窗口与案例证据校验。
2. **命令阶段**：cron、launchd 或 CI 仅调用 `scripts/build_report.py`，把已有三件套打包为 HTML、PDF、meta 和 checklist。

命令阶段的输入、输出与失败状态必须显式记录；不得用 `|| true`、空文件、预置 PASS 或“文件数 + 1”掩盖失败。

## 不建议的做法

- 在 CI 中留下“此处省略模型生成”后仍上传空或旧 PDF。
- 只换日期、不判断相对上期的真实增量。
- 把真实客户配置和白名单提交到仓库。
- 将 `_DRAFT.pdf` 自动作为邮件、IM 或客户系统附件发送。
- 在失败后仍发送“本期已生成”通知。

## 验收

调度上线前至少手动跑两个不同窗口：第二次必须检查旧内容去重；两次均检查三件套/PDF 哈希、白名单、案例证据、A4 页尺寸和人工复核耗时。动态稳定性未做三轮独立证据验证时，状态写 `NOT_VERIFIED`，不宣称“稳定自动化”。
