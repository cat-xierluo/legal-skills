## [1.6.0] - 2026-10-26

### 修复
- 适配原生 CLI 持久化时段时区：计划显式绑定本机时区与预期回读，保留原规则时区漂移检查；隔离 CLI 验证修改与恢复。
- 单供应商容量提示作为咨询级风险保留，不再单独阻断 `--strict`；结构与规则警告仍按严格门禁处理。
- 盘点账号输出统一为单次扫描内的匿名标签，去除昵称、邮箱片段、域名和上游半遮罩；映射仅留内存，盘点结果仍保存在私有状态中。
- 将配置复制指南移入 references，移除 Skill 内 README；复制示例拒绝覆盖既有私有配置并使用 0600 权限。
- 公开参考删除个人调用统计，保留核验方法；明确画像由 Agent 解释、盘点与设计校验不会自动生成嵌套路由。
- 设计校验器改用严格 JSON 解析，拒绝重复键；格式不符时停止语义检查并返回结构化错误。嵌套深度含入口最多 8 个组，叶子模型不计层数。
- 画像 schema 增加约束内 `expensive_models` 清单，盘点脚本读取该规范字段并兼容历史私有格式。
- 设计校验器对非字符串成员和暂停目标 fail-closed，不再输出 traceback；账号顺序输出恢复未知/空/已设置三态。
- 根 README 与 Skill 发布分发套件索引对齐为 9 个成员、源码 v0.1.3；仓库根发布检查不再误报必需的 `state/.gitignore`。
- 修正路由治理 §2.8 的代理探测与继承边界：双路失败不证明必须代理，空 choice 仍继承
  全局；账号与 CLI 子进程的显式 choice 优先，回环例外与系统透明转发另核。
- 改为先验证必须代理的 provider，再切全局直连；回退绑定本次字段与预期后态，避免断路
  或覆盖并发修改。同步既有治理记录与历史观测证据边界，不改生产配置。
- 原始 `TASKS.md`、`DECISIONS.md` 改为同目录本地维护记录，由 Skill 内 ignore 规则排除；
  公开树不再发布摘要版。配置说明放入 `references/configuration.md`，列出五类 example 的私有副本、用途、
  schema 与最小复制/校验路径。

### 变更
- 新增[智能路由设计](references/adaptive-routing-design.md)：按用户已配置的 provider、账号池、模型能力与任务角色生成个性化路由草案；沉淀角色分层、资源映射、意图规则、子 Agent/辅助调用边界与设计检查矩阵，不写入任何个人模型或账号。
- 路由设计示例改为单一入口嵌套多个角色组：外层 `order + turn` 负责角色层编排，内层组负责同层成员回退；补充 compact、轻任务、普通任务、困难升级与项目级终审的规则顺序示例。
- 从私有维护仓库迁入 legal-skills 公开目录；原始任务与决策记录迁入 Skill 同目录本地维护并由 ignore 排除，
  公开层保留通用入口、参考、脚本、示例/schema、许可证与变更记录。
- 本机画像、集成信息、路由策略与可执行 policy 放在 `config/*.local.*` 私有层；
  观察、盘点、计划、回执与快照放在 `state/`，均由随包 ignore 规则排除。
- 通用入口补公开主页；示例命令的网关端口改为 `<port>`，具体模型组示例改为泛化占位。

## [1.2.0] - 2026-10-22

### 新增
- 路由治理参考补三处实测坑（`references/routing-governance.md`）：
  - 本机解析到回环的厂商域名会让全局代理被绕过；0.1.1307 源码解释 `loopback` 例外、解析、
    onLAN 直连与 provider 级代理 choice 的先后，排障时先核解析来源。
  - 区分规则命中、目标不可用与分类器回退：`unready/then/instead`、
    `classified.error/fallback`、`tries`/`served` 分别断言，不把落点偏离直接归因于配置顺序。
  - 强模型入组会被兜底消耗；顺序结论限定于 `order` 的新 turn 重选路径，末位只是降低概率，
    硬性不消耗用移除或 `pause`。记录 0.1.1307 没有“规则未命中移出回退”的开关。
  - 能力层必须显式接进唯一入口，并区分「组存在」与「外层会选到」；同一 provider/model
    与固定 effort 经能力组和免费池重复进入会被折叠到首次出现位置，共享会改变默认落点。
    单一候选休息会移到队尾并可能被探测，关闭或移除才无候选承接。
  - 嵌套组的内外层 routing/rules 相互独立；外层 `order` 不会改写内层 `smart`。经外层请求
    的会话保持由外层 affinity 控制，内层 stays 仅在直接请求内层组时生效；变更后需分别核对
    直接请求与外层请求的两层 `tries`。
