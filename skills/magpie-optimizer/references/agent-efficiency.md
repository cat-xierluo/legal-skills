# 从网关输入检查 Agent 与 Skill 的效率

当请求成功但等待长、worker 带入过多背景，或希望检查 Skill、工具和主子 Agent 的 token 开销时读本文。优化对象是通过验收的任务总成本与完成时间；网关是观察入口，并不控制客户端全部提示词、工具目录或原生调用。

## 1. 先分清开销来自哪里

读取指定时窗的现有路由记录，不先重启、清缓存或重放全部请求。将请求关联到原任务与具体主/子会话；身份不明时保留未知，不把同一时窗的全部流量都归给一个 worker。

| 输入部分 | 可以核查的内容 | 可采用的局部动作 |
|---|---|---|
| `system` | 宿主内置提示、附加运行规则 | 区分宿主固定内容与用户可维护内容；不能通过删安全指令或假设忽略规则节省 |
| `tools` | 工具定义及重复 schema | 仅在宿主支持时，为具名任务选择必要工具；没有能力不能声称 Skill 已裁剪工具目录 |
| `skills` | Skill 目录元数据、实际加载的正文 | 触发描述准确，正文渐进披露；只读当前分支需要的参考，不预加载全部 references |
| `memory`、`files` | 项目规则、历史记录、输入文件 | 保留适用规则与权威事实，去掉重复副本；文件范围和版本清楚，按需有界读取 |
| `results` | 工具结果、日志、搜索输出 | 限定查询、投影字段和分页；保留定位信息与失败证据，不用无边界输出再截掉关键错误 |
| `chat` | 历史对话、派工说明和协作往返 | 新有界任务用完整必要任务卡，避免重复携带整份报告和可重新读取的附表 |

`prompt.parts` 是运行时分项，不是独立账单。即使总量标成 `counted`，各部分也可能是估计后分配；同样的系统规则在两个请求里显示不同 token，不足以证明系统提示变了。缺失、未知种类、分项合计与总量的差额都要披露。不能把嵌套 `items` 再加一次，也不能据文件名或工具名的计数断言其内部命令或实际 Skill 调用次数。

只读聚合可使用 [`magpie_efficiency.py`](../scripts/magpie_efficiency.py)：显式给出日志、带时区的起止时间与新私有输出文件。它扫描现有日志、统计输入分项和延迟覆盖，不读取认证、原始会话或网关密钥，不联网、不改请求。参数和部分覆盖状态以脚本 `--help` 与回执为准；这不是完整请求账分页或账单核验，完整观测沿[观测合同](observation.md)。

```sh
python3 <skill-dir>/scripts/magpie_efficiency.py <private-routing.jsonl> \
  --since <ISO8601-with-timezone> --until <ISO8601-with-timezone> \
  --output <private-dir>/efficiency.local.json
```

输入只限具名普通文件，输出拒绝覆盖；读取预算、坏行、未知完成状态及字段缺失分别披露。不能把局部日志读取完成称为“所有 Agent 已覆盖”。

## 2. 精简新 worker 的上下文

先选有明确交回条件的任务，列出不可丢的背景，再精简重复材料。可用以下任务卡；它不是要求所有任务使用同一模板：

```text
目标与交回对象：要解决什么，向谁交付。
必要事实：权威结论、版本、关键证据及仍未知的部分。
输入与作用域：允许读/写的文件，必要位置及当前候选身份。
硬约束：质量、保密、成本、模型选择、在途任务与操作边界。
验收：实际产物、检查方式、失败/停止条件与所需证据。
按需材料：有缺口再读取的具名来源；不要假定删掉了便不再需要。
```

在当前宿主确实支持时，对新有界 Codex worker 显式使用 `fork_context=false` 并提供必要任务卡。该参数只表示不复制父聊天历史，**不保证移除系统提示、项目规则、Skill 元数据或工具定义**。规则加载、权限与模型选择仍按实际运行时执行；不修改既有模型钩子来追求短提示。

需要长背景的规划、审计或接续任务保留必要材料，必要时继续原 worker；不能为了做出短提示将同一工作不断拆成新会话。缺背景导致重复探索、返工或验收失败时补回，再计总成本。

只改变本次新派工。不要批量压缩、换模型或终止运行中的任务；全局上下文窗口、自动压缩阈值和 Agent 默认值另作具名计划。Skill 中的建议不等于已接入宿主的自动裁剪器。

### 宿主本身可核的配置

当固定开销仍较大时，再按当前安装版核[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)和[Skill 加载说明](https://learn.chatgpt.com/docs/build-skills)：

| 入口 | 用途与限制 |
|---|---|
| `skills.max_context_tokens` | Skill 目录元数据预算；不是正文预算。减小可能压缩或省略发现信息，不能代替保留本任务所需 Skill 的验证 |
| `skills.config` 的 `enabled` | 停用具名不需要的 Skill 而保留文件；必须先核任务依赖与作用域，不批量关闭用户常用能力 |
| MCP 的 `enabled_tools` / `disabled_tools` | 在支持的服务器或插件范围选择工具；以实际工具列表验收，不把批准偏好当工具裁剪 |
| `tool_output_token_limit` | 限制历史内的工具结果；过低可能截断错误、引用或验收证据，先优先缩小查询与投影 |

这些是候选配置入口，**本 Skill 不自动写入或热加载**。官方本地 Skill 配置说明要求重启后生效；正在执行任务时不为试验重启。也不以降低 `project_doc_max_bytes` 的方式静默截掉项目硬约束。配置需在后续新任务或具名隔离环境实际核验，不能将文档能力等同于本机所有客户端均已支持。

## 3. 延迟按阶段解释

先区分最终失败、实际 `tries` 失败和回退恢复；候选 `order` 出现不等于请求过。总生成时间、TTFT、首段可见文本、排队和工具执行时间也不是一个指标。

HTTP 状态和业务结果分列：200 仍可能带空文本、未完成流等错误。按 `kind` 区分主任务、子任务、分类、标题、预测、搜索与视觉辅助调用；预测没得到建议不能直接计成主 Agent 任务失败，也不能只凭频次关闭仍有用的能力。未知 kind 保留为其他，不按名称猜角色。

安装版支持 `net` 时分别看：`own` 是网关准备，`before` 是最后一次出站前的其他请求，`pool`/DNS/connect/TLS 是连接阶段，`send` 是 Go HTTP 客户端所见的请求写入，`wait` 是写完到响应头首字节。插件自己的 fetch 可能没有这些分项；缺失不能补零。

还要核实际协议路径。某些版本的 Codex 流请求会先尝试 WebSocket，失败后再走 HTTP；HTTP trace 此时可能只覆盖握手，不能将其 `send` 当整个 WebSocket 消息上传时间。[安装版示例源码](https://github.com/yetone/magpie/blob/v0.1.2528/internal/gateway/codex_socket.go)与[网络字段定义](https://github.com/yetone/magpie/blob/v0.1.2528/internal/gateway/nettrace.go)仅用于理解机制，实际结论绑定正在运行的版本。

只读核对 provider 代理边界；需要连接测试时另行限定新连接数、超时和目的地，不切全局节点影响在途业务。主页 HEAD 返回错误状态仍可能证明 TLS/HTTP 可达，**不能证明登录、推理或长流成功**。小请求成功也不能排除长请求断流。

提前结束且缺少 `response.completed` 表示流未完整结束，不能独自确定是供应商、代理还是中间链路；`context canceled` 不能确定取消发起方。避免以无限重试或重新发送整个大上下文掩盖问题。已有 HTTP/1.1、请求压缩或 WebSocket 回退机制时，先核安装版实现，不重复增加开关或修改已安装核心代码。

## 4. 做保留质量的同题对照

1. 固定任务输入、必要事实、约束、输出范围与验收；候选与产物按现有任务证据绑定哈希。对照可以比较整份材料与必要任务卡，但必须写明两者的实际差异，不能叫作未执行的“完整历史 fork 对照”。
2. 尽量固定模型、推理强度、工具、账号/套餐及运行条件，保留缓存、负载、输出长度和时间顺序差异。用原生会话用量与网关实际身份交叉核实；未取得 served 回执时不只凭模型配置宣称同源。
3. 先独立验收语义质量与硬约束，再比较总输入、非缓存输入、缓存读取/写入、输出、累计调用、失败、返工与任务墙钟。请求耗时相加不等于并发任务墙钟。
4. 保留反向结果：提示更短可能破坏缓存前缀，非缓存输入反而更多；缩短输出也可能降低任务完成度。不能只选择看起来省的指标。价格和账单未知时不报金额收益。

原生 `input_tokens` 与网关 `usage.in` 不一定同义：某些运行时的 `usage` 是列表，`in` 只记非缓存输入，另记 `cache_read`；另一些格式为对象。先核当前版本及真实匹配记录，不重复扣减/相加缓存，不把输出内 reasoning 再计一次。schema 不识别时保留未知。

单次同题试用只描述该样本差异，不证明稳定提速或普遍省钱。需要每份验收成果的完整账本比较时，按[效果复核](outcomes.md)执行；局部路由样本不冒充其完整分页证据。

## 5. 交付与停止条件

交回：实际修改、新任务是否采用、质量对照、输入/缓存/延迟差异、失败及覆盖缺口、恢复条件。公开层只留方法与合成测试；私人读数、原始输入、账号和真实产物留私有层。

没有足够证据时，可交付已验证的任务卡改进及仍待定位的出站问题；不为声称“优化完成”改动模型优先级、必需代理、额度休息或在途任务。经济性结论与网关健康分别结算。
