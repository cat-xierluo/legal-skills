# 额度、任务与成果

**以下命令在 Skill 目录内执行，`scripts/`、`config/`、`state/` 均相对该目录。**

## 选择顺序

先设能力门槛：任务风险、工具调用、上下文、图像输入、语言与推理能力。只在合格模型中比较质量稳定性、可用额度、到期、边际费用、延迟、缓存和返工概率。成本优化的目标是“单位验收成果的总成本”，包含生成、分类、重试、上下文重传和人工返工，不是 token 单价最小。

把资产分成四类：已购买套餐（存在五小时/周/月多窗口）、会到期赠送积分、可持续但限流的免费模型、实际余额付费。不同单位不能合并成一个百分比；未知不等于免费或无限。区分 `quota.resetsAt`、订阅 `until` 和积分批次 expires_at，不能互相替代。Magpie 缺失长期窗口时，不据五小时余量承诺可持续批量执行。

## 推荐分层

| 层 | 任务 | 路由选择 | 成本边界 |
|---|---|---|---|
| free | 提取索引、格式规范化、短文初筛、明确规则的整理 | 已核实免费的显式白名单；先 order，保留 auto 缓存 | 只回退到同类免费模型；全部失败则等待 |
| build | 已拆解的实现、文档初稿、固定验收的测试补充 | 套餐执行模型＋同档已确认赠送入口；按时段 pause | 不把低价模型自动当作最终裁判 |
| deep | 复杂设计、难题调试、关键判断与最终复核 | 强模型白名单；套餐或即将过期的同能力积分 | 不因主力失败偷偷降级到 free |

免费账号的供应商级总并发可从 1 起测；这是保守起点，不是官方限额。队列建议先用长度 2、等待 15 秒，在观察排队/429 后调整。不要给每个组各设一个“独立并发”却忽略它们共享同一账号。两个平台入口可能消耗同一账号池，核对来源后再计容量。

`smart` 指向额度续期，并不衡量模型智力；`order` 给明确顺序；`pace` 依赖周额度信息，读不到时不拿它伪装自动精算。`stays=auto` 优先缓存；`session` 强调稳定，但非严格永不迁移。`pause` 每个请求都执行，可能打断会话粘性；若用户想“高峰期仅降低优先级”，用 time+use 强选替代，原模型仍可能作 fallback。若用户想“高峰期绝不消耗”，用 pause，并接受所有替代不可用时失败。

## 时段与卡库存

把时段作为用户偏好而非硬编码平台事实；由用户确定的时区转换为 Magpie 所在机器时区。时段条件按机器时钟，无需额外 cron。顺序：能力/安全限制 → 全局暂停 → 意图或复杂度 → 时段优先 → 默认顺序。免费入口不足以接长上下文或图像时，不勉强路由。

对提供重置卡的供应商，先核当前用卡规则、真实库存和过期时间，再提出安排建议。用户设定的可用时段只用于安排已有高价值任务；不自动切换账号、领取或消费卡，也不把一个供应商的机制套用于另一个供应商。库存读取可委托用户已配置的工具，缺失时记为未知。

AutoClaw 等积分先查每批到期；只有用户明确把“当日优先消耗”作为策略，才按该偏好排序，不能把订阅 until 当成奖励到期。安排产物可复用的低交互任务，接近过期也不生成无用内容。

MiniMax 多入口可能共享额度；禁用一个组成员不等于禁止原生客户端调用。高峰倍率未获账户页面证实时记 user_reported；用 pause 能实现用户的避峰偏好，无需声称已经证实倍率。达到套餐上限后的积分包扣除要另核；不承诺只要显示订阅就绝不消耗积分。

## 将 token 留成资产

每个任务先有真实输入、唯一产物位置与验收标准。例如：带来源的材料索引、去重知识条目、测试覆盖、可复用脚本、可复查文献笔记。免费模型生产候选，强模型只处理争点和验收抽样；高风险内容保留专业复核。

沿已有任务账本记录：asset_id、来源版本、产物路径、模型/组、调用来源、输入/输出/cache token、套餐窗口前后读数、验收、返工次数。不把推理全文或账号密钥归档。没有可靠 API 账单时费用写 unknown；没有同账号同窗口连续观测时不算耗尽预测。

个人策略、任务账本与观察记录放在 Skill 目录内的 `config/*.local.json` 与 `state/` 私有层，不进版本库；本文只保留通用方法。

观察指标：验收成果数、每成果总调用与返工量、429/错误比例、排队与首 token 延迟、缓存复用、临期额度损失。先用少量代表性任务确认能力，再扩量；不要因额度宽松自动启动或分派新任务。
