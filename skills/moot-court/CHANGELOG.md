# 更新日志

## [1.1.0] - 2026-09-18

### 新增

- 默认自动多角色模拟庭审：主 Agent 兼任调度员与书记员，分派法官与民事原被告或刑事控辩；通过限定材料包、正式发言与下一轮派发完成间接通信，不依赖 Subagent 直接消息。
- 新增 Python 标准库书记员工具：版本化材料快照、单写者顺序事件、派发与发言身份校验、同稿去重、取消重派、进度恢复及笔录生成。事件是内部权威记录，对角色只提供筛选后的材料与公开发言。
- 增加角色任务模板、民刑演练议程、复核标准、合成案卷和 CLI 回归；输出模拟庭审笔录、争点攻防复盘及庭前补强清单。

### 修复

- 撤销 AI 代打故意遗漏、绕开问题的规则，双方在现有材料范围内充分论证；分别记录材料缺口、论证缺口与角色执行失误。
- 不再用“无公证”“复印件”等标签自动判断证据薄弱；不将角色超时、工具失败、未提交反证或未回答直接等同于实体攻防结论。
- 责任人、期限和处分范围未提供时标记待确认，避免从模板推断用户授权或真实案件安排。

### 文档完善

- 将技能级 DECISIONS.md 与 TASKS.md 纳入版本管理，标记旧决策的替代关系，记录验证边界，并为真实案卷、刑事演练、跨 Runtime、长案卷和隔离恢复等升级方向定义依赖与验收。
- 明确 Runtime 续接、一次性子任务与主控搬运材料的适配方式；共享目录属于逻辑隔离，文件不会自动唤醒 Agent，记录脚本离线不代表模型离线。
- 声明单轮合成演练、协议校验、专业法律复核与跨 Runtime 稳定性验证的不同证据边界；不将 close 或静态扫描当作法律正确性证明。

## [1.0.0] - 2026-09-18

### 新增

- 首个正式版本：庭前推演与预案技能，纯提示词编排、零脚本零依赖，开箱即用。
- 三道工序框架：要件自查 → 对抗推演 → 预案定稿；时间紧可只做自查或出简版清单。
- 要件自查：按"诉讼请求 → 权利基础规范 → 构成要件 → 待证事实 → 证据"做证据覆盖表，每个要件标注有证据（✓）/薄弱（△）/无证据（✗）；配套程序、实体、证据三类抗辩核对表（时效、主体、管辖、合同效力、履行抗辩、因果关系、损失数额、违约金调减、证据四性等），汇成《推演重点清单》。
- 对抗推演：对方代理人视角按"只打有据可依的点"规则攻击薄弱要件与高威胁抗辩；承办法官视角专门追问双方回避的问题（证据空格、含糊表述、文书与证据出入、金额计算），问到底为止；支持用户亲自下场答辩，也支持 AI 代打（代打刻意保持"合格但真实"水准以暴露真实漏洞）；我方答辩按"答上了/绕开了/没答上"三档判定，回避问题单独成表。
- 预案定稿：漏洞与补强清单（对方打法→现状→开庭前动作→紧急程度分级必办/应办/可办）、证据补强动作（途径/责任人/截止日，客观无法补的写替代思路）、庭审提纲（逐焦点应答口径、不利问题回应准备、向对方发问清单、质证意见要点）。
- 安全边界：按最坏情形推演并注明前提、仅有我方材料时声明推演设定、交付物标注"庭前推演产出"、敏感材料提示、正式文书交由对应文书技能。
