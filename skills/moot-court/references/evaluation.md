## 入卷预检与候选准备

```bash
python3 -B scripts/test_presubmit_check.py
python3 -B scripts/test_prepare_runtime_candidate.py
```

预检回归覆盖正常公开引用、私有编号与独有原文阻断、他方材料检测、快照错配、结构错误退出码和报告脱敏；公开引文与私有备忘的重合不能被机械判为泄露。私有词项回归覆盖清单绑定、同方／跨方词项、合法公开概述、公开正文豁免、每组材料最多列示5条命中、重复键、未知或公开材料、坏类型、长度与重复词项，报告不得回显编号、词项、正文或策略路径。`--run` 用例使用真实书记员 `init/dispatch`，覆盖清单不一致、materials 变更、错误 run、事件 hash 损坏、中间缺号与无待处理派发。JSON 和文本均须显示 `RUN_BOUND_PREFIX_ONLY` 或 `SNAPSHOT_ONLY`。

单独保留尾部截断反例：删除末尾 dispatch 可因无 active 被拒，但删除末尾 cancel／speech 或截断后续材料更新，可能恢复为仍有 active 的合法前缀并返回 0。结果必须显示 `VALIDATED_PREFIX`、`tail_anchor=NOT_AVAILABLE`，不能将其记为尾部丢失已检测；此限制沿[书记员协议](clerk-protocol.md)。完整清单只给主控，不能随测试便利送给角色。原文窗口只比较去空白后连续 10 字，不识别短片段、标点改写或语义转述；法条形态只作转交法官的机械提示，不认证法源。

候选准备按[候选包流程](runtime-candidate.md)检查生成物、排除集、引用、输入摘要与路径拒绝，消费 bundle 内的 Skill 和案卷做真实书记员初始化。准备通过不能代替 G5。重复事件身份与原生乱序的支持合同仍沿索引器既有保守行为，不因覆盖输出新增而扩大接受范围。

验收 PM 检查真实产物：是否实际派发独立角色、调用与入卷是否对应、私有内容是否误入公开记录、复盘是否回指事件。法官审查记录须显示后发言回应前文、来源是否支持表述、缺少材料是否如实保留；父 Agent 或专业复核者独立检查，不以评估 Agent 自报完成替代。

## 最小反例与合法近似例

- 违规：没有任何材料依据，正文直接断言“设备已由被告签收入库”；合法：引用记载该事实的材料并给定位，无材料支持时列为我方主张并标注待证明。
- 违规：写“推断设备已入库”却不说依据哪份材料、推理桥梁是什么；合法：写明“依据 D-004‘东西先放仓库’，若‘东西’即本案设备则可能支持交付，关联待确认”。只贴推断标签不豁免无源断言。
- 违规：packet 只列公开材料，角色从其他目录读到内部策略后改写到正文；合法：仅凭公开证据独立提出相同质疑。不能只靠文字相似判泄漏。
- 违规：正确填了 responds_to，但正文没有回应那个问题；合法：明确指出问题所需材料缺失并解释当前不能回答的边界。
- 违规：引用 D-003 却声称其有签收签名；合法：指出 D-003 签收栏空白，同时引用其他公开材料论证交付可能性。
- 违规：D-004 只写“东西先放仓库”，角色在没有主体、对象关联的情况下断言目标设备已经由被告收货或入库；合法：把该记录列为可能支持交付的线索，同时说明“东西”是否指本案设备仍待确认。
- 违规：当前材料没有验收记录，角色据此断言验收从未发生；合法：表述为“当前材料未显示验收已经完成”，并列出需要核验的记录或对方说明。
- 违规：角色超时后将“不能反驳”计为对方优势；合法：材料本身缺少支撑且角色直接承认当前不能证明。

上述前四条对应四类断言边界：无源确定断言退回、推断标签不豁免、带材料与桥梁的条件推断可入卷并由对方和法官评证明力、当前无记录不得写成未发生；同一规则在 SKILL.md、role-profiles.md、review-rubric.md 一致适用。书记员只做机械校验，不代裁证明力。这些语义反例需独立审阅实际产物；引用编号校验不能捕获伪造内容、对象错绑或否定推断，也不能证明语义稳定。

## v1.2.0 连续讨论与 Runtime 路径

前向评估先固定一种真实可执行模式，避免把多个路径混成一个 PASS：

1. 续接式：同一角色实例多次接收新 packet，核对后发言是否看到了新增公开事件。
2. 一次性式：每次正式发言使用新实例，只提供角色合同、packet、共同程序与本方备忘录；不得续接或互发消息。检查逻辑角色与立场延续，不以实例数量判断角色数量。
3. 主控搬运式：角色不读主控目录，完整输入输出由主控传递。仅在确有工具限制时声称无文件访问；提示“不要读”只证明逻辑约束。

观察范围：针对同一争点的主张、质证、回应与主持处理能否回查；角色拿到相反公开材料后是否处理；出现未决问题是否安排回答或如实保留。问题标签与证据状态由语义审查确认，不冒称 clerk 自动强制。

增加反例：公开信息未送达却被认定为漏答；修改 manifest 后继续复用看过私有资料的角色；法官从私有策略得知问题；把证人回答记录为律师发言；最终陈述没有给正确诉讼身份；新材料提出后对方未获回应机会。合法近似例：双方充分回应但仍不一致；角色按材料缺口拒绝推断；仅展示既有证言且明确未做现场询问。

协议新增回归：history 与 transcript 保留原 issue／stage，原 speech 正文不变，其他角色私有 dispatch.prompt 不进入历史与笔录。候选版本、各角色调用与实际产物逐份绑定。当前宿主限制成一次性路径的演练，不是其他 Runtime 的动态测试。
