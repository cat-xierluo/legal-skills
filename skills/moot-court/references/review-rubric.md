# 庭后复核标准

复核者独立于参演角色。检查实际记录与原始材料，不能仅复述双方或书记员的自评。拿到摘要时回查相关发言原文及材料定位；未能回查则标“未核实”。

| 检查对象 | 可观察证据 | 不通过时处理 |
|---|---|---|
| 来源与事实身份 | 每个重要事实的材料编号、定位；主张／假设标识 | 撤回无来源事实，重跑受影响回合 |
| 事实强度与否定推断 | 四类边界逐项核对：无源确定断言未入卷；推断标签附有材料依据与推理桥梁；条件推断保留不确定性，证明力交由对方和法官评断；“未见记录”没有被改写为“未发生” | 退回原角色收窄或补充推理桥梁，重跑受影响回应；复核者不得静默代改 |
| 更正与跨运行边界 | 已入卷发言未被覆盖；更正回合显式引用原发言编号并写明更正内容，受影响双方获得回应机会；close 后新运行未把旧运行编号填入 respond_to，旧记录只作为公开来源说明 | 从原事件重开受影响链路；来源映射写进公开说明而非必答集合 |
| 相互回应 | 必答发言与本轮正文逐项对应 | 交回原角色补答，不以填写 responds_to 冒充回应 |
| 材料可见范围 | packet、正式稿、私有资料边界；入卷质证前仅允许说明私有材料存在与拟证明对象，检查是否附具体数量、人员类别、具体取证路径、取得／核实状态、私有结论或编号；区分公开案卷未见某项证言与本方是否已取得，允许基于公开材料的补证方向和合理质证 | 停止传播，重新构造未污染的角色上下文；保留事故说明；交原角色按边界修稿，需披露的细节先私下申请并更新材料版本、对等送达 |
| 入卷前保密检查 | 回查法官及双方每份正式稿在 commit 前的机械预检与主控保密复核；词项仅逐字命中，不能替代复核，法官免递归实体审批不免此检查 | 停止传播并记录遗漏；不能事后补签冒充入卷前检查，重跑受影响链路 |
| 法源来源 | 是否有未经核验的具体法律名称、条文编号或法条原文入卷；无条号的无名规则命题是否标注待核验 | 退回原角色改为无名命题或补充已核验法源；不得由主控就地改写 |
| 主控改写 | 入卷正文与角色原稿的差异；改写是否记录并披露 | 未记录的就地改写按流程违规处理；记录改写范围与原因并交独立复核评价 |
| 完整原稿送审 | 法官实际收到的完整 body/citations紧凑JSON对象、接受稿与入卷稿一致；送审摘要或 citations 顺序改写不能替代原稿；正文引号与 Markdown 标记保留 | 补送完整原稿，由原法官复审；保留旧摘要与错误退修记录，并用固定角色审计器复核 trace、SHA与回执 |
| 审查尺度 | 待核实设问、条件推断与确定断言分开；有据的事实认定意见获准表达；分歧不被强迫收敛 | 修正过度退修或禁止事实论证的主持意见，并恢复受影响方的表达机会 |
| 归纳与承认范围 | 法官归纳是否保留原话条件、否定范围和事件回指；“不主张”没有被升级为自认，条件接受没有被删掉前提 | 从原事件重开受影响归纳；不以后续概括覆盖双方原话 |
| 引用与推理 | 引用内容是否支持结论，有无相反材料 | 区分误引、遗漏与真实争议，不能机械判胜负 |
| 技术故障 | 取消记录、失败信息、真实回执 | 恢复／重派，故障不得作为对方攻防成果 |
| 交付闭环 | 目标争点覆盖表、发现与动作的对应 | 未覆盖明列，不能写“所有问题解决” |

发现分四类：

- 案件材料缺口：本次范围内缺失或无法核实，写明需要什么及可能途径，不断言现实中不存在。
- 论证缺口：已有材料与结论之间仍缺推理，或某个实质异议尚未解释。
- 角色执行失误：漏读、误引、虚构、越权或未按任务回应，先修正角色输出再评价案件本身。
- 编排／工具失误：主控摘要漏前提、改写原稿、预检或送审错绑、宿主调用错绑、运行故障等，先修机制或调度并重跑受影响链路。

后两类不能直接转成客户补证任务。角色执行失误和编排／工具失误应记录修复、重跑或审计证据；只有真实案件材料缺口和可补强的论证缺口才进入庭前补强清单。

“答得流畅”不等于有据，“对方没答”不等于我方成立。格式校验可自动化；事实含义、法律适用与回应质量保留专业判断。任何自动分数都不得转为胜诉概率。

事实强度按四类边界检查正反例：①无源确定断言——反例：无任何材料依据却写“设备已入库”；正例：引用记载该事实的材料并给定位，无材料时列为我方主张并标注待证明。②只贴推断标签——反例：“推断设备已入库”却不说依据和桥梁；正例：写明依据 D-004 及关联待确认的限定，标签不豁免无源断言。③条件推断——基于材料、写明推理桥梁与不确定性的论证可以入卷（正例：“若 D-004 的‘东西’即本案设备，则可能支持交付，关联待确认”），证明力由对方质证和法官评断，复核者不因“只是推断”而排除。④当前无记录——反例：缺验收记录就断言验收从未发生；正例：表述为“当前材料未显示验收已完成”并列出待核验事项。若越界已影响后续发言或法官归纳，从原事件重开受影响链路，不能只在终稿里润色掩盖；书记员不判断证明力，也不代改观点或禁止合理对抗。

硬失败：虚构材料／法条、私有内容不当公开、故意弱化角色、错版本入卷、运行故障被当作实体失败、未执行却声称独立多 Agent 或稳定验证。出现后不得沿用受污染结果作无保留交付。

验收属性与职责：记录工具校验身份／版本／顺序／去重；法官负责实际回应、事实强度与程序处理记录；主控负责机械预检、转交前保密复核、调用与落盘，不判断实体观点；独立复核者检查来源、推理与覆盖。核审查回执的完整稿件SHA与法官原生调用，不能把回执当正式事件；法律专业人员复核法律判断。版本与实际工具调用日志关联保存，旧版本测试不能证明新版本行为。

## 庭审真实性与连续讨论

- 程序适配：采用哪套方案、哪些环节省略；是否混用赛事或法域规则；辩护人、被告人、证人身份是否被偷换。
- 公开脉络：必答发言与相关公开材料是否送达，材料更新后对方是否获回应机会；不能把未送达当对方漏答。
- 连续讨论：逐争点回查具体主张、质疑、回应与主持处置，记录因前文发生的追问、澄清、限定或保留；双方仍分歧不代表失败，重复独白也不等于成功。
- 主持边界：法官问题来自公开案卷，未替一方补证；程序异议有处置或明确待核验；不因“法官角色”身份而给结论更高证据地位。
- 知识边界：续接或冷启动是否沿用正确 run／role；可见性撤回后有无旧知识污染；材料可见不等于证据已采纳。
- 双层复盘：先评价当时公开记录，私有准备建议单列并控制接收范围；不以事后全知倒推对方当时应该知道。

评估不按“问得像法官”“轮次够多”或“输赢明显”判通过。研究提示见 [方法报告 S12](research-methods.md)；本技能应保留具体反例和实际发言检查。
