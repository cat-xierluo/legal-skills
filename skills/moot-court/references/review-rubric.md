# 庭后复核标准

复核者独立于参演角色。检查实际记录与原始材料，不能仅复述双方或书记员的自评。拿到摘要时回查相关发言原文及材料定位；未能回查则标“未核实”。

| 检查对象 | 可观察证据 | 不通过时处理 |
|---|---|---|
| 来源与事实身份 | 每个重要事实的材料编号、定位；主张／假设标识 | 撤回无来源事实，重跑受影响回合 |
| 相互回应 | 必答发言与本轮正文逐项对应 | 交回原角色补答，不以填写 responds_to 冒充回应 |
| 材料可见范围 | packet、正式稿、私有资料边界 | 停止传播，重新构造未污染的角色上下文；保留事故说明 |
| 引用与推理 | 引用内容是否支持结论，有无相反材料 | 区分误引、遗漏与真实争议，不能机械判胜负 |
| 技术故障 | 取消记录、失败信息、真实回执 | 恢复／重派，故障不得作为对方攻防成果 |
| 交付闭环 | 目标争点覆盖表、发现与动作的对应 | 未覆盖明列，不能写“所有问题解决” |

发现分三类：

- 材料缺口：本次范围内缺失或无法核实，写明需要什么及可能途径，不断言现实中不存在。
- 论证缺口：已有材料与结论之间仍缺推理，或某个实质异议尚未解释。
- 角色执行失误：漏读、误引、虚构、越权或未按任务回应，先修正再评价案件本身。

“答得流畅”不等于有据，“对方没答”不等于我方成立。格式校验可自动化；事实含义、法律适用与回应质量保留专业判断。任何自动分数都不得转为胜诉概率。

硬失败：虚构材料／法条、私有内容不当公开、故意弱化角色、错版本入卷、运行故障被当作实体失败、未执行却声称独立多 Agent 或稳定验证。出现后不得沿用受污染结果作无保留交付。

验收属性与职责：记录工具校验身份／版本／顺序／去重；主控复核材料披露与实际回应；独立复核者检查来源、推理与覆盖；法律专业人员复核法律判断。版本与实际工具调用日志关联保存，旧版本测试不能证明新版本行为。
