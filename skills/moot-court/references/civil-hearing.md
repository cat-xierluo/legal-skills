# 通用民事演练闭环

本文件定义当前默认民事主线。原告、被告分别代表本方诉讼立场，法官主持，主 Agent 兼任书记员；书记员不是第四个实体论辩方，也不需要单独常驻实例。案由决定请求和争点，先复用同一流程；不为婚姻、合同等例子自动添加专门角色或未核验的法律规则。

先按[程序方案](procedure-profiles.md)明确本次法域、审级、材料和预算。下表是训练闭环，不承诺覆盖所有现实法定环节；证人、鉴定人及复杂多方暂不展开，也不阻塞这套流程。

## 从材料到交付

| 环节 | 各角色做什么 | 书记员记录与下一步条件 |
|---|---|---|
| 1. 庭前准备 | 从已有材料提取请求、答辩、争议与证据；双方独立准备 | 建立材料版本与可见范围，初始化空运行目录；不得预写对方回答 |
| 2. 开庭与请求答辩 | 法官宣布范围和议程；原告明确请求与依据，被告逐项回应 | opening；请求、回应与本次范围均可回查。材料很短时可与首次举证合并，但必须保留双方真实发言 |
| 3. 整理争点 | 法官从双方立场确认本次需要解决的问题 | opening或questions；列出目标争点与顺序，不由私有策略暗示问题。已在庭前明确的单争点可先公布，双方发言后复核 |
| 4. 举证与质证 | 提出方说明材料及证明目的，对方具体质疑，提出方回应；双方均可提出本方已有材料 | evidence；按争点建立“材料—异议—回应”关系；没有本方证据时可质疑对方证明，不能强行补造 |
| 5. 法官追问与争点辩论 | 法官追问具体缺口；双方先答问题，再讨论证据到结论的推理并回应反方 | questions／debate；每次回应绑定已入卷发言。法源未核验时只讨论事实与证据，不用记忆补规则 |
| 6. 双方总结与法官归纳 | 双方分别总结请求／抗辩和关键回应；法官归纳已回应问题、仍有分歧及材料限制 | closing；必须给双方总结机会，法官不能替任一方回答；不作用户的真实处分或预测裁判 |
| 7. 庭后交付 | 独立复核者检查实际记录；不可用时声明单Agent复核 | 输出模拟庭审笔录、争点攻防复盘、庭前补强清单；每项发现回指事件或材料缺口 |

相邻环节在简单材料下可以合并一次发言，stage标示主要动作；复盘按实际正文核对覆盖，不以某个stage标签代替完成证明。合并不能取消对方回应机会，不能让尚未看到对方发言的角色提前反驳。争点较多时重复4—5，最后统一收尾；不为每个争点重复整场开庭。

## 书记员贯穿所有环节

每次只派发一个正式发言：dispatch固定角色及必答对象 → 提供该角色材料包与完整公开历史 → 收到完整稿件 → commit入卷 → 根据法官公开安排派发下一步。只有共同约束、当前角色职责和本方备忘录进入角色输入，不整份复制所有角色模板。详见[调度规则](drill.md)与[Runtime适配](runtime-adapters.md)。

## 怎样判断“跑通”

- 流程完成：上述7项功能在实际材料与发言中均有对应；双方主要意见得到回应，正常交付三项成果，无待提交回合。
- 事实与法律判断：另看材料能否证明、法源是否核验。留下证据缺口或双方仍有分歧，不等于调度没有跑通。
- 范围有限：只演练一个争点时写清覆盖范围，不宣称整案全部请求已经审查；遗漏的目标环节或预算内未答事项必须列出。
- 工具关闭：按[书记员协议](clerk-protocol.md)，约定流程及交付完成用普通close；目标环节或回应没完成才用close --incomplete。事实有待查项或恰好用满预算不自动判运行不完整。关闭状态仍不单独证明流程充分或法律结论正确。

现有合成民事记录的覆盖与限制见TASKS Task-018；在其他Runtime继续使用[同一基准](runtime-validation.md)，不先换案卷、扩角色或开发专门程序。

仅有单方材料时，另一方可以审查证明与提出有依据的条件性解释，缺失请求或证据明确列出。反诉、多方当事人及二审另拟范围，不把利益相反主体混成一个角色。材料中的既有证言、鉴定意见仍可出示质证；暂不模拟其提供者现场回答。

调解空间、放弃请求、事实承认或私有材料披露涉及用户真实处分时由用户决定，不由模拟角色代作。责任人和真实期限未提供时保持待确认。
