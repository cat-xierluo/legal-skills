# 盲评探针：无答案角色分包验证

本文件说明如何用 `scripts/prepare_probe.py` 反复做「角色不知道预期答案」的语义回归。它是流程说明，不是领域结论；跑通本流程只说明协议与输入边界成立，不说明法律判断正确。

## 工具做什么与不做什么

`prepare_probe.py --run <绝对路径> --output <绝对路径>` 实际调用既有 `clerk.py packet`，只把当前派发转成该角色可读的冷启动输入：

- 只输出书记员 packet 的白名单字段（`instruction`、`assignment`、`documents`、`history`、`submission_template`），其余字段一律丢弃。
- `submission_template` 保留原 `schema_version`、`run_id`、`turn_id`、`role`、`material_version`、`read_through`、`responds_to`；宿主读到 output 即可按此结构生成提交。
- 不再次 `dispatch`、不 `commit`、不修改 run，不生成 `transcript.md` 或 `state.json`。
- 不加载、不拷贝 `assets/semantic-probe-reviewer.json`；正文不含预期结论、评分口径、他方私有材料或材料清单路径。
- 通用角色任务文本只说明纪律（用哪些材料、怎么引用、怎么保留提交字段），不含任何针对具体案件的结论。

拒绝条件（一律非零退出并给出单行中文原因，不打印 Traceback）：

- `--run` 不存在、不是目录，或当前没有待交稿派发。
- `--output` 已存在：原子创建、绝不覆盖；出错时只清理本次自己创建的文件。
- `--output` 的父目录不存在。
- packet 缺字段、提交模板与派发不匹配，或含非本角色的私有材料。
- packet 命中禁止标记（复核答案资产名、参考答案、评分步骤、材料清单文件名、事件流路径）：宁可报错也不产出。

## 源 run 绝对路径的说明

packet 正文**不包含**源 run 绝对路径。但主控仍需持有它：`clerk commit` 需要 `--run`。路径由主控掌握，不随角色输入分发；角色没有义务、也没有指引去定位该目录。

## 消费流程

每个回合重复以下四步，顺序不可颠倒：

1. **准备 packet**：主控 `dispatch` 后运行 `prepare_probe.py`，为当前角色生成唯一输入文件。
2. **干净上下文一次性角色**：把该文件作为该角色本轮的**全部**输入，交给一个没有历史对话的独立上下文执行一次发言。不要把上一轮内容、其他角色输出或复核答案带进同一上下文。
3. **主控入卷**：角色按 `submission_template` 产出提交，主控执行 `clerk commit`，然后 `cancel` 关闭该回合或直接进入下一回合。
4. **下一 packet**：回到第 1 步取下一个角色的输入。

全部角色的正式发言都入卷之后，才把 `assets/semantic-probe-reviewer.json` 交给一位**未参与生成任何发言**的复核人。该资产含来源、四类语义边界（事实归属、推断限度、角色可见范围、程序回应性）、材料编号预期与评分步骤；它不是结论，也不能替代真实复核人判断。

## 每次必须留存的证据

每轮记录以下三项，缺一不可：

- 上下文身份：本次发言所用的 Agent／会话标识，确认是干净上下文。
- 输入摘要：对本轮 packet 计算 hash（或记录其完整摘要），证明用的是哪一份输入。
- 产物 head：入卷发言对应的提交标识或 run 事件序号。

## 协议 PASS 与语义 NOT_VERIFIED 必须分开写

- 协议层：字段完整、引用合法、材料版本一致、无重复入卷、越界引用被拒。这层可用 `test_prepare_probe.py` 等真实 CLI 回归证明，记 `PASS`。
- 语义层：四类语义边界是否被遵守。这层**只能**由未参与复核人按 `semantic-probe-reviewer.json` 判定；未做或未做完，一律记 `NOT_VERIFIED`。

不得用「生成 packet 时没有答案」推断「角色确实没有读到其他磁盘内容」；也不得用字符串不含答案自报法律正确。

## 降级与披露

- 无 Subagent／一次性上下文能力时：可在同一主控中顺序扮演各角色，但必须记为**单 Agent 降级演练**，明确披露该轮不具备上下文独立性。
- 无权限隔离时：如实说明本轮只有输入分发上的逻辑隔离，没有工具级权限阻断。
- 任何上述降级都只影响语义层结论的可信度，不改变协议层记录方式。
