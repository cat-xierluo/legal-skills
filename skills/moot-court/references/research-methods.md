# 中外模拟法庭研究与本技能的取舍

研究日期：2026-09-19。用途：维护方法与适用边界；运行时按程序方案读取对应流程，不必重复加载本报告。本文比较代表性做法，不代表覆盖所有国家、法院或赛事。下述“迁移”是本技能的设计判断，不是来源对 AI 系统有效性的背书。

## 1. 先区分训练对象

| 形式与来源 | 训练机制 | 可迁移的方法 | 不能直接照搬 |
|---|---|---|---|
| Jessup 国际法论辩（S1、S2） | 既定争议事实、书状、口头陈述、法官问题、反驳与再反驳 | 回应限于对方刚提出的实质问题；法官保持主持边界 | 不能把围绕既定事实的论辩当成证据调查；赛事评比不是裁判预测 |
| AMTA 美国大学 Mock Trial（S3） | 开场、双方举证、证人询问与交叉询问、结案陈词 | 将证据呈现、质疑、回应分成相邻动作；证人受角色材料约束 | Midlands 是竞赛证据规则；部分事实发挥例外不适用于真实案卷预演 |
| Vis 国际商事仲裁训练（S4） | 书面准备、程序与实体争点、仲裁庭提问、庭后反馈 | 准备材料服务现场应变；主持不能变成炫技考试；表现与实体结果分开 | 不替代中国民刑诉讼程序，也不把仲裁角色改名为法官便称适配 |
| 国内模拟法庭（S5、S6、S13） | 有控辩与书状评审，也有依据赛题组织质证、法官介入和多轮辩论的安排 | 庭前交换、法官整理争点、基于案卷的攻防 | 各赛事规则与年度不同，不存在一套可直接概括为“中国模拟法庭统一规则”的流程 |
| 中国真实诉讼程序（S7、S8） | 按程序开展调查、发问、辩论和最后意见／陈述 | 明确阶段、诉讼身份、发言许可与程序结果 | 竞赛省略不能冒充真实庭审已完成；辩护人不等于被告人 |

**结论**：以用户案件材料开展的庭前压力测试，应默认采用“证据审理式预演”，保留争点和程序动作；纯法律争点可选“法官问答式论辩”。正式竞赛则加载具体年份规则。三者共用书记员记录层，不混用规则。

## 2. 从研究中提取的设计要求

### 轮次要有因果关系

一轮不是每人各写一份报告。先有具体主张、证据或问题，再把它作为下一次任务的必答对象；后续发言会改变待答事项和下一步安排。法官可在适当节点提问，但应给双方陈述和回应空间。技能把这种关系落实为“争点—发言—回应—主持处置”，见 [调度规则](drill.md)。

S1 对反驳范围的限制和 S2 对法官介入的指导、S6 附件中的分组质证和交叉回应支持这种设计；并不要求所有案件照搬 Jessup 的人数、分钟数或发言顺序。AI 文本的一次生成也不等于现实中的若干分钟，技能单独记录派发预算。

### 全局视野来自共同案卷与已公开记录

真实角色通常不会互相拥有内部策略；这不妨碍讨论。同一争点所需的公开材料与已公开发言必须送达各角色。区分“角色尚不知情”“公开后仍未送达”“已收到但没回应”：第一种可符合设定，第二种是编排故障，第三种才进入应答复核。

本技能的推导：法官在其程序允许接触的案卷范围内统筹公开庭审，主控从全量资料管理流程，庭后复核者可按授权作更广检查。主控不能把私有材料暗示成法官的问题，庭后知情也不能追溯证明先前公开论证成立。详见 [信息模型](information-model.md)。

### 证据有多个状态

被上传、对角色可见、当庭提出、遭到质疑、经过回应、被纳入本轮推理，分别代表不同事情。把材料设为 `visible_to: [all]` 只改变本次模拟中的可读范围，不代表法院已采纳，不是对公众发布。状态通过相关正式发言追踪，不要求脚本自行裁判可采性。

### 真实感不能靠编造证人或裁判结果

S3 对角色事实与推断设有限制，也保留特定交叉询问中的发挥空间；S6 同样存在角色回答可超出赛题的赛事约定；本技能为了真实案卷训练选择更严格的“不补造案情”。材料未载明的证人回答不能由模型补齐。证人／被告人需独立角色合同、有限知识与程序安排，不能由代理人临时换帽子。本版仍是三角色核心环节预演，完整询问与最后陈述能力另行开发。

### 评价训练质量，不只评价“谁赢”

分别复核程序推进、信息送达、具体回应、引用支持、论证变化与可执行补强。S2、S4 都提示不能只按案件实体上哪方应胜来给参演者评分。AI 研究 S12 进一步说明：问题听起来像法官，并不自动证明问题多样性或抗迎合能力。因此保留反例和独立产物复核，不以“讨论了很多轮”当成功。

## 3. Runtime 不应决定庭审方法

| 方案 | 优点 | 代价与决定 |
|---|---|---|
| 直接使用宿主 Agent Teams 群聊 | 消息便捷、角色可持续在线 | 可用时作为传输优化；消息到达不等于入卷，仍要统一发言许可与版本 |
| 主控派发—角色返回—书记员入卷 | 可跨续接式与一次性子任务，能保持公开记录顺序 | 本技能默认；依赖主控持续推进，文件不会自行唤醒 Agent |
| 自建常驻多 Agent 服务 | 可管理实时消息、角色长期生命周期 | 需要部署、权限、成本和运维；当前无必要，不扩展为平台 |

官方文档 S9—S11 说明不同 Runtime 的子任务、续接及工具授权机制有差别。不能写死“所有 Subagent 不能互通”，也不能写死“所有平台都能恢复”。采用运行前能力清单，完整方案见 [Runtime 适配](runtime-adapters.md)。文档支持与真实实测分栏，不把文档研究写成跨平台验收。

## 4. 现有版本缺口与本轮落点

| v1.1.0 中的缺口 | 本轮处理 | 剩余范围 |
|---|---|---|
| 每争点“两轮”含义不明确 | 定义交流回路、主持节点、待答事项与结束条件 | 语义完成由主控／复核者检查，脚本不强制 |
| 只有粗粒度 opening/evidence/debate | 在现有阶段下定义提问、回答、质疑、回应、主持处理等动作 | 多角色程序状态机未实现 |
| 可见材料容易被误当采纳材料 | 增加可见性与证据处理状态的独立模型 | 权限强隔离仍取决于宿主 |
| 续接原 Agent 可能保留过期或越界知识 | 规定角色绑定、撤销可见性后的冷启动和污染处理 | 无法“删除”旧模型记忆，不能承诺硬遗忘 |
| 历史发言缺争点／阶段元数据 | 从原 dispatch 派生历史上下文与笔录元数据，不泄露私有 prompt | 发言身份校验不证明内容回应充分 |
| 刑事辩护角色容易代替被告人 | 明示三角色训练与完整刑事庭审的差距 | 证人、被告人、鉴定人专用角色与前向评估列入任务 |
