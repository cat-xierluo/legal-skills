# 调度与回合规则

## 角色任务与宿主工具分离

主 Agent 是唯一调度入口，书记员是其职责，不必另占一个 Subagent。法官和双方各有独立角色任务。每轮只派发一个正式发言；双方庭前准备可并行，不能把同一旧快照上的并行稿冒充连续攻防。

先确认宿主是否能创建、等待、续接子任务，以及能否控制上下文继承与文件访问。使用宿主实际暴露的工具，不猜命令、不直接读写其他产品的邮箱或 task 文件，不安装额外编排平台。

| 宿主能力 | 做法 |
|---|---|
| 可续接同一 Agent | 续接角色，传本轮 packet；公开历史以 packet 为准 |
| 只能一次性执行 | 重建同角色，传角色说明、本方备忘录、packet；不继承主控全部对话 |
| 无共享目录 | 主控把 packet 内容作为输入，取得提交 JSON 后落盘 |
| 可直接互发消息 | 消息只作通知；正式发言仍需书记员入卷后才可引用 |
| 无子任务工具 | 明示单 Agent 分角色；不得虚构独立 Agent 身份或执行日志 |

会话 ID 只是宿主适配信息；角色身份以案件类型、派发角色和版本化材料包为准。主会话停止后文件仍在，但不自动续跑。恢复时先 status，再 packet，不凭旧聊天记忆推进。

## 一次发言的调用合同

将 role-profiles.md 中适用角色指令与书记员 packet 一起派发。要求返回 submission_template 的完整 JSON；只填写 body、citations，其余字段保持不变。发言正文写明：回应哪个问题、观点、材料依据（编号与定位）、推理、尚未核实事项，以及需对方回答的问题。

`responds_to` 由主控指定。每个必答发言应在正文逐项处理；没有依据时明确不能回答及原因，不能只填编号。脚本只能核对编号与派发一致，实际回应质量由主控和庭后复核检查。

有私有材料时，角色可在自己的工作区形成准备备忘录，但正式稿不引用或泄露未公开内容。需要公开时先返回单独的披露请求给主控；主控核对范围，必要时询问用户，更新 manifest 可见性并取消重派。不将私有研究全文作为共享“研究进度”。

## 发言安排

1. 法官根据可见材料提出议程和初始争点；双方分别陈述请求／指控与回应。
2. 对每个目标争点，由承担该项主张的一方先提出具体依据，另一方回应，再由前者回应实质异议；法官按需追问。
3. 第二轮聚焦尚未回答、矛盾、材料证明范围，不重复首轮全文。双方承认材料支持的部分，无须为对抗而否认一切。
4. 每争点两轮为默认预算，仍有实质新问题时最多四轮；无新增依据或无法补证时记录待查事项，不能强制双方达成一致。
5. 双方作简短总结，法官归纳已回应与未解决事项，不输出胜率或以“法官角色”替代专业复核。

案件程序决定具体顺序；civil-hearing.md 与 criminal-hearing.md 是演练组织框架，不宣称复现全部真实庭审程序。

## 异常与角色记忆

每次正式发言后，由对应角色或主控在该角色可见范围维护简短备忘录：已表达立场、关键引用、未解决问题、后续核实项。它是角色工作资料，不是公开记录，也不存储或要求模型隐藏思维过程。

新材料／更正足以改变争点时允许重开，注明触发依据；禁止借“重开”无限追加预算。变更案件立场时保留旧表述并解释材料变化，不能悄悄改写先前发言。

超时重试原任务时检查是否已入卷；同稿可重试 commit，异稿需要新回合。需新建 Agent 继续同一派发时，确保旧 Agent 已停止或忽略其迟到结果。每轮最多两次技术重试；持续失败按不完整演练收口。用户加入角色时等待其真实回答，等待不等于技术失败或实体败诉。
