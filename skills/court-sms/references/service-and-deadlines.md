# 送达证据与期限核对

适用：归档判决、裁定，或需要计算缴费、举证等期限时。先核对起算事实，再识别适用规则，最后计算；下载成功、日期可解析均不代表期限已确定。

## 送达事实

- 对每一份文书、每一个受送达人分别核对。记录法院文书 ID；没有 ID 时使用本地稳定标识，并保留与原文件的对应关系。
- 电子送达先核对适用基础（同意、确认的地址、范围等）及该份文书的到达/发送成功凭证。法院回证、法院对应系统发送成功记录、受送达人提交的到达证明须能关联目标文书和受送达人。
- 二维码生成时间、文书制作/签发日、API 记录创建日、下载时间、普通短信发送或接收时间，均只作为时间线索。若短信本身构成有效电子送达，须核对其送达内容、接收地址与适用依据后，另行记录为到达证据；不能按时间字段名称自动推定。
- 同一批下载不证明同一时刻送达。只有回证明确列出多份文书及同一受送达人时，才可分别关联该回证。不得借另一份缴费通知书的日期计算裁定上诉期。
- 平台显示发送成功与当事人到达证明冲突时，保留双方材料并人工核对；适用司法解释第135条的证明例外，不能机械取最早、最晚或首个来源。

## 确定性送达证据检查

使用 Python 3.8+ 标准库，无第三方依赖。核对原始材料后，为每个文书/受送达人准备如下本地 JSON。以下为虚构示例；不得将真实凭证、号码或私有路径提交到仓库。

```json
{
  "document_id": "DEMO-RULING",
  "recipient_id": "DEMO-RECIPIENT",
  "service_basis": {"checked": true, "ref": "demo/consent.pdf#page=1"},
  "conflict_checked": true,
  "has_conflict": false,
  "evidence": [
    {
      "kind": "court_delivery_receipt",
      "event": "delivered",
      "date": "2026-09-30",
      "document_ids": ["DEMO-RULING"],
      "recipient_id": "DEMO-RECIPIENT",
      "checked": true,
      "ref": "demo/receipt.pdf#page=1"
    }
  ]
}
```

在技能目录执行：

```bash
python3 scripts/check_service_evidence.py /private/path/service-evidence.json
python3 -m unittest discover -s scripts -p 'test_service_evidence.py' -v
```

`kind/event` 支持：`court_delivery_receipt/delivered`、`court_system_record/sent_success` 或 `arrived`、`recipient_arrival_proof/arrived`。日期按中国办案适用的本地日期核对，保留原始时间及时区于证据中，不因执行机在海外而改变起算日。手工核对、重新命名 kind 或勾选 checked 都不能替代证据内容。

- 退出码 0：已提交材料满足契约，输出 `confirmed`、`served_on`、`evidence_refs`；只允许进入期限适用性核对，不能据此直接宣告上诉期限。
- 退出码 2：证据不足、冲突或绑定失败，输出 `pending` 且 `served_on=null`；继续下载归档，展示缺口，不输出确定期限或倒计时。
- 退出码 1：文件不可读/JSON 无效，停止期限计算并报告输入错误；不得绕过检查。
- 工具不联网、不读取 ref 指向的文件、不鉴定回证真伪，也不验证 checked 的真实性。原件核对与法律适用仍由处理者负责。纸质、公告等其他送达方式需按对应法律另行核验，本检查器不自动判定。

## 期限适用性

必须阅读文书末尾救济告知及相关正文；不能只读首页或用文件标题判定“一审”“可上诉”。普通规则只是候选：

- 民事：通常一审可上诉判决15日、可上诉裁定10日；先核对审级、程序及救济类型。保全裁定、终审裁判、小额诉讼等不能直接套用；在我国领域内没有住所的当事人还涉及民诉法第286条等特别规定。
- 行政：通常可上诉一审判决15日、裁定10日，仍须核对适用条件。
- 刑事：通常可上诉判决10日、裁定5日，按刑诉法核对起算及期间规则，不能一概引用民诉法。
- 缴费、举证、复议等分别读取原通知规定的义务、起算事件及期限性质。公告费用、诉讼费和上诉期不得共用同一个“7日/10日”模板。
- 救济告知与查得规则不一致、可上诉性不明、特殊程序或送达方式未核清时，状态为“期限待核验”，请求人工复核，不自行作不利取舍。

确认适用规则后，按日计算通常不计起算当日，期间内节假日照常计入，只核对末日顺延。使用当年官方放假调休安排，同时识别调休工作日；缺少年份/跨年日历时保留待核验。不得按执行机工作日库或普通周末推算。

2026年示例仅用于复核算术：若已确认9月30日为适用的送达日且10日期间成立，初算10月10日为调休上班日，不因周六顺延；若已确认某7日期间适用相同末日顺延规则，初算10月7日则顺延至10月8日。这不是对任何真实案件的期限结论。

## 输出与历史记录

- 记录 `service.status`、`service.served_on`、`service.evidence_refs`；`sent_at/received_at` 保留发送/收到这一事件本身，禁止再作为通用送达日起算字段。
- 记录 `deadline_status`：`pending`（默认）、`confirmed`（事实、适用规则、日历均已核对）、`not_applicable`（确认无该项上诉权）。附 `deadline_basis`，包含救济告知定位、法律依据、日数、日历来源、核对日期及受送达人。
- 非 confirmed 时，`appeal_deadline` 和 `appeal_days_remaining` 均为 null，报告仍显示“待核验”和原因；不得默默隐藏，亦不得把空值当“不存在期限”。
- 多文书/多受送达人分别记录，不将第一份结果复制到整批。重复运行如证据失效，必须撤下当前确定期限，保留旧值和原来源在本地更正历史中；禁止继续展示旧倒计时。
- v1.5.2 及更早记录缺少本证据结构的，不能默认 confirmed。只在用户授权处理的记录范围内标记待复核，保留原始证据及历史值，核验后更新；不自动批量改写其他案件档案。

## 法律与日历依据（2026-09-30核对）

1. [民事诉讼法（2023修正）](https://www.gzhzcourt.gov.cn/upload/editor/file/2025/08/04/6388989731436328121054632.pdf)：第85条第2、3款的起算/末日规则，第90条电子送达，第157、171、286条的裁定/上诉/特别期间。注意末日顺延在第85条第3款，旧版所引第4款为在途时间。
2. [民诉法司法解释（2022修正）](https://www.court.gov.cn/zixun/xiangqing/353651.html)：第135条系统显示发送成功日期及受送达人证明的例外。
3. [人民法院在线诉讼规则](https://www.court.gov.cn/fabu/xiangqing/309551.html)：第29至32条电子送达条件、地址和生效时间。
4. [行政诉讼法](https://www.sdcourt.gov.cn/zbzcqfy/378182/flfg9/5880507/index.html)：第85条一审上诉期间、第101条相关程序准用。
5. [刑事诉讼法](https://www.npc.gov.cn/c2/c12435/201905/t20190521_276591.html)：第105条期间、第230条上诉/抗诉期间。每次实际适用仍应核对现行文本和特殊规定。
6. [国务院办公厅2026年放假安排](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)：国庆10月1日至7日放假，10月10日上班。

## 验收边界

自动测试只验证证据契约：二维码/落款/短信/下载时间不升级、文书与受送达人绑定、冲突、缺证、格式、CLI退出码及合法凭证正例。它不证明模型已正确读懂真实PDF、没有漏读救济告知，亦不证明真实案件期限正确。完整技能端到端和跨模型稳定性仍为 `NOT_VERIFIED`。
