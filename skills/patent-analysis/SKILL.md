# 专利分析

## 定位

对专利材料进行可回溯的初步分析，区分材料事实、分析推断和法律判断。默认法域为中国；涉及其他法域时，先确认适用法律并重新核验规则。

本技能不直接生成正式法律意见。任何诉讼、无效、许可、交易、上市或产品定型决策，都需要专利律师或专利代理师结合完整材料复核。

## 核心工作流

### 1. 先完成输入门禁

确认以下信息：

- 任务类型：单专利摘要、多专利比较、侵权比对、稳定性、FTO、规避设计、价值评估、等同分析、无效应对或可视化
- 法域和分析基准日
- 专利类型、专利号、当前法律状态及有效权利要求文本
- 本次要分析或权利人拟主张的权利要求；存在多项独立权利要求时逐项列出
- 产品或方法的具体版本、实施行为和证据来源
- 是否取得说明书、附图、审查档案、无效决定、同族和现有技术
- 本次法律基线是否已按分析基准日核验，是否发生指南、司法解释、有效权利要求、期限补偿、许可备案或权属更新

遇到下列情况时，停止确定性评级，只输出材料缺口和补充清单：

- 未确认法域、专利法律状态或有效权利要求文本
- 未明确本次分析的权利要求
- 产品版本或必要技术事实无法对应
- 仅有摘要，缺少权利要求书和必要的说明书内容
- FTO 未提供目标法域、实施行为、产品版本、检索截止日或法律状态基线，候选专利的法律状态及有效权利要求未核验，或者法源与状态刷新触发后尚未完成复核

### 3. 按四层模型分析

#### 第一层：权利要求选择与解释

1. 以权利人主张或任务选定的权利要求为分析单元，不默认只看权利要求 1。
2. 对每项独立权利要求分别确定技术方案；对从属权利要求，将其附加特征与全部引用链合并后分析。
3. 以权利要求文字为基础，结合说明书及附图、相关权利要求、审查档案和生效确权文书解释术语。
4. 记录解释来源；存在两种合理解释时并列呈现，不擅自选择有利于任一方的版本。

#### 第二层：技术特征与证据比对

将每项被分析权利要求拆成可独立比对的技术特征，并使用统一证据状态：

| 状态 | 含义 | 能否计入已覆盖 |
|---|---|---|
| `A-已证实` | 由实物、公证材料、图纸、可靠技术资料或双方确认直接支持 | 可以 |
| `B-初步支持` | 由图片、视频、宣传材料或间接材料支持，仍需核验 | 不可以 |
| `C-不相同/缺失` | 证据表明不存在对应特征或存在实质差异 | 不可以 |
| `D-无法判断` | 材料不足、对象不清或解释存在关键分歧 | 不可以 |

结论门禁：

- 任一必要特征为 `C-不相同/缺失`，无论是否同时存在 `B/D`，该权利要求均不支持字面全面覆盖；逐项披露 `B/D` 证据缺口，再判断是否需要对 `C` 特征开展等同分析。
- 仅在不存在 `C`、但任一必要特征为 `B-初步支持` 或 `D-无法判断` 时，才写“证据不足，暂不能判断是否全面覆盖”。
- 只有全部必要特征均为 `A-已证实`，才可以写“现有证据初步支持字面落入该权利要求”。
- 不得把“推定”“可能存在”“产品应当具有”换算成已覆盖数量。

#### 第三层：等同分析

仅对字面不相同的对应技术特征逐项分析手段、功能、效果以及本领域普通技术人员在被诉侵权行为发生时是否无需创造性劳动即可联想到，同时审查禁止反悔、权利要求公示性和其他限制。读取 `references/08-doctrine-of-equivalents.md`。

#### 第四层：有效性、抗辩与程序影响

分别列出可能相关的现有技术/现有设计抗辩、先用权、合法来源、禁止反悔、无效宣告和权利滥用等问题。不要把“可能提出”写成“必然提出”，不要使用无来源概率或固定案件周期。

### 4. 执行法源和状态刷新门禁

1. 记录登记表基线ID、核验日期、分析基准日和适用法域。
2. 核对法源效力状态、指南施行版本、司法解释修订状态、目标法域有效权利要求版本和法律状态查询日。
3. FTO、规避设计和估值还要核对专利权期限补偿、许可备案、权属及产品/实施行为变化。
4. 分析基准日晚于核验日，或者法律、指南、权利要求、法律状态、权属、许可、产品版本、实施行为、法域、检索截止日发生变化时，先刷新相关基线。
5. 刷新未完成时，停止确定性评级，只输出补充或核验清单。

## 推理与引用规则

- 逐条标记 `材料事实`、`分析推断`、`法律判断`。
- 引用专利内容时标明权利要求号、说明书段落、附图编号或审查档案页码。
- 引用法律时记录法源全称或 `references/00-legal-basis.md` 中的简称、具体条款、发布机关、效力状态和核验日期；公开报告不要求附法院或行政机关网页链接，内部检索记录另行保存。
- 引用案例时记录案号、法院、裁判日期和裁判状态；无法核验的案例不进入正式分析。
- 不使用占位案号冒充真实案例；无法核验的案例不进入正式分析。
- 不输出没有数据模型和来源支持的无效概率、侵权概率或价值指数。
- 程序期限以当事人实际收到的通知和现行规则为准，报告中同时记录送达日期与计算口径。

## 材料与保密

- 仅处理完成任务所必需的专利、产品和案件材料；输出前去除无关个人信息、客户名称、未公开产品参数和商业秘密。
- 未经用户授权，不把未公开材料发送到外部服务；确需 OCR、检索或下载时，先说明对应技能的联网和数据处理边界。
- 报告中的公开示例使用泛化信息，不使用可反查的真实客户、项目或案号组合。

## 输出结构

默认报告至少包含：

1. 任务、法域、基准日与使用边界
2. 材料清单和缺口
3. 专利基本信息及法律状态来源
4. 被分析权利要求及选择理由
5. 术语解释与来源
6. 技术特征—产品—证据逐项表
7. 字面覆盖与等同分析
8. 稳定性、抗辩和程序风险
9. 分层结论：已证实事项、待核实事项、条件性判断
10. 后续取证、检索和人工复核建议
11. 法源与材料索引

对外文书或正式意见不得直接复用模板结论；先由专业人员复核事实、证据、法源和结论措辞。

## 质量复核

交付前检查：

- [ ] 法域、基准日、法律状态和有效权利要求已核验
- [ ] 多项独立权利要求及被主张的从属权利要求没有遗漏
- [ ] 每个技术特征都有产品对应项、证据来源和证据状态
- [ ] `B/D` 状态没有被计入全面覆盖
- [ ] 等同分析是逐特征判断，不是整体相似判断
- [ ] 案号、法条、期限和统计性表述均可回溯
- [ ] 已记录法源基线ID和核验日期，2026年指南影响、权利要求版本、期限补偿及许可备案已按场景核对
- [ ] 保护范围、全面覆盖、等同、无效或FTO结论列明共同适用的多个具体条款，未附法院或行政机关核验网址
- [ ] 未把初步分析写成法院结论或正式法律意见
- [ ] 客户、案件、未公开产品和商业秘密信息已按最小必要原则处理
- [ ] 已列出材料缺口、不利因素和人工复核点

## 依赖

### 系统依赖

本技能的文本分析流程无额外系统依赖。扫描 PDF、专利下载、法律检索和高保真渲染分别使用上表中的对应技能。

### Python 包

本技能无第三方 Python 包依赖。维护者先运行 `python3 scripts/check_legal_sources.py --expected-version 2.2.0` 校验法源登记表，再运行 `python3 scripts/validate_skill.py --repo-root ../..` 进行完整静态一致性检查。
