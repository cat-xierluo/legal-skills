# Changelog

All notable changes to this skill will be documented in this file.

## [2.1.2] - 2026-07-30

### 新增

- 新增 `evals/evals.json`，以十个虚构、自包含提示词逐一覆盖单专利摘要、多专利比较、侵权、稳定性、FTO、规避设计、估值、等同、无效应对和可视化。
- 新增 `evals/assertions.json` 与 `scripts/check_evals.py`，为每个场景设置至少两项 hard 正向断言、一项 hard 禁止性断言和 soft 质量断言，并支持检查外部回答。

### 技术优化

- 将评测契约纳入 `validate_skill.py`；新增缺场景、弱 hard 断言、未知断言类型和场景关键门禁缺失的故障注入测试。
- 禁止性断言改为分句识别肯定结论、否定句和当事人主张，增加“正向词堆叠 + 错误结论”、正确否定句、转折污染、全称/简称法源及产品证据 URL 的故障注入，避免关键词拼接假通过和合规表达误杀。
- 侵权、规避、等同和无效场景的硬断言要求列明共同适用的多条款法源；只禁止把法院或行政机关网页作为法源链接，不误伤产品或专利证据 URL。

### 修复

- 无效宣告转送答复补入《专利法实施细则》第七十二条，权利要求修改范围补入第七十三条；区分当前答复/修改规则与《专利法》第四十六条规定的决定后救济。
- 纳入自2026年1月1日起施行的《专利审查指南》第四部分第三章第4.6.4节，要求修改权利要求书时提交全文替换页和修改对照表。
- 补齐侵权等同分析的手段、功能、效果、可联想到性和主要限制因素硬断言，以及功能性特征对应的司法解释（一）第四条、司法解释（二）第八条。

### 文档完善

- 在技能 README 中补充样本校验和外部回答检查命令，明确静态断言不能证明法律正确性、跨模型一致性或长期稳定性。

## [2.1.1] - 2026-07-30

### 改进

- 将保护范围、权利要求解释、全面覆盖、等同原则、实施行为和常见抗辩重构为“子问题—共同适用条款—适用要点”矩阵，避免以单一条款概括复合判断。
- 细化功能性特征、封闭式组合物、使用环境、制备方法、步骤顺序、数值边界、说明书捐献和禁止反悔等特殊规则。

### 修复

- 删除等同原则模板中的法院网页链接；公开法源只记录规范全称或统一简称、具体条款、效力状态和核验日期。
- 区分《专利法》第十一条规定的实施行为与第六十五条规定的纠纷处理路径，避免把不同功能的条款合并为同一依据。

### 技术优化

- 扩展静态校验和回归测试：禁止共用法源及等同模板出现网页链接，并检查保护范围、全面覆盖和等同原则的必需条款组合。

### 文档完善

- 同步 `SKILL.md`、技能 README、根 README 和 Marketplace 的 v2.1.1 标识。

## [2.1.0] - 2026-07-30

### 修复

- 删除不可核验的占位案号、类案比例、无效概率和固定案件周期，禁止用伪精确数据替代证据分析。
- 将无效程序答复期限修正为通常一个月且以实际通知为准；将无效决定行政起诉期限修正为三个月，并明确行政判决十五日、裁定十日的上诉期限。
- 修正无效程序修改规则：“进一步限定”只能补入其他权利要求记载的技术特征，不能从说明书或附图任意抽取，也不承诺可在口头审理现场任意修改。
- 修复可视化模板将“推定/待核实”计入全面覆盖并据此输出侵权结论的问题。
- 明确混合证据状态优先级：`C` 与 `B/D` 同时存在时，先判定不支持字面全面覆盖，同时完整披露 `B/D` 证据缺口。

### 改进

- 从默认分析权利要求 1 改为逐项分析权利人主张或任务选定的权利要求，覆盖多项独立权利要求和从属引用链。
- 新增 `A-已证实`、`B-初步支持`、`C-不相同/缺失`、`D-无法判断` 四级证据门禁；`B/D` 不得计入已覆盖。
- 将 FTO 的目标法域、产品版本、实施行为和检索截止日设为必需输入，缺失时停止风险评级。
- 重写十个场景模板，收紧正式意见、价值评估、规避设计和对外文书的专业复核边界。

### 新增

- 新增 `references/00-legal-basis.md`，集中维护保护范围、全面覆盖、等同、无效程序期限和修改规则的可回溯法源。
- 新增无第三方依赖的 `scripts/validate_skill.py`，检查元数据、相对引用、危险旧规则、FTO 门禁和发布版本同步。

### 技术优化

- 新增 10 个校验器回归测试，覆盖错误期限、占位案号、无来源比例、混合证据状态、FTO 门禁反转、追加冲突规则和下载版本错配，并包含合法近似正例防误报。

### 文档完善

- 同步 `SKILL.md`、技能 README、许可证、根 README 和 Marketplace 的 v2.1.0 标识。
- 根 README 在 v2.1.0 发布包尚未生成时显示“待发布”，不再将新版本入口指向旧包。
- 原 v1.1.0/v1.2.0 中“默认只看权利要求 1”和“落入从属权利要求越多越稳定”的方法已由 v2.1.0 取代；旧版本记录仅保留历史追溯用途。

## [v1.2.0] - 2026-03-02

### 重构

- **输出模板拆分**：将单一模板文件拆分为7个独立场景文件
  - `references/01-single-patent-summary.md` - 单专利技术要点提取
  - `references/02-multi-patent-comparison.md` - 多专利比对分析
  - `references/03-infringement-comparison.md` - 产品-专利侵权比对
  - `references/04-validity-analysis.md` - 专利稳定性/无效分析
  - `references/05-fto-analysis.md` - FTO分析
  - `references/06-design-around.md` - 规避设计分析
  - `references/07-patent-valuation.md` - 专利价值评估
- **SKILL.md 精简**：从689行精简至185行，保持核心内容
- **更新引用**：SKILL.md 中的模板引用更新为指向独立文件

### 修正

- **从属权利要求的作用**：修正理解，从属权利要求不是"不重要"
  - 落入的从属权利要求越多 → 侵权稳定性越大
  - 原因：权1可能被无效限缩，从属权利要求作为后备阵地
  - 新增分析流程：先判断权1侵权 → 再评估落入哪些从属权利要求 → 评估稳定性

### 新增

- **核对专利权人**：注意事项新增第6条，强调产出法律文书前必须核实权利人名称
  - 多个专利可能有不同权利人
  - 名称必须与专利登记信息完全一致
  - 名称错误可能导致法律文书无效

### 文档完善

- 2026-04-22：按独立仓库 README 新规范重写首页，补充目标用户、典型侵权比对场景、7 类分析产物、安装方式、使用边界、核心设计、许可证一致性、Legal Skills 关联项目导流、作者联系入口和微信二维码
