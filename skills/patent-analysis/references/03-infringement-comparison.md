# 场景三：产品—专利侵权比对

## 适用边界

用于中国发明或实用新型专利的初步技术特征比对，不替代法院认定或正式侵权法律意见。开始前读取 [共用法源与结论门禁](00-legal-basis.md)；涉及等同时同时读取 [等同原则分析](08-doctrine-of-equivalents.md)。

## 输入门禁

- 法域、分析基准日、专利法律状态及来源
- 当前有效的权利要求、说明书、附图及可取得的审查/确权档案
- 权利人已经主张或任务选定的具体权利要求
- 被分析产品/方法的准确版本、实施行为和发生时间
- 实物、公证材料、图纸、检测结果、网页、视频等证据及取得方式

任一核心输入缺失时，只输出材料缺口和取证清单，不得输出“全面覆盖”或“侵权成立”。

### 2. 解释权利要求

对每项选定权利要求分别记录：

- 权利要求原文和完整引用链
- 必要技术特征分解
- 关键术语的权利要求、说明书、附图、审查档案或确权文书依据
- 可能的替代解释及其影响

不要默认只分析权利要求 1。权利人主张多项独立权利要求或从属权利要求时，逐项建立独立比对表。

### 3. 逐项比对并分级证据

| 权利要求/特征 | 权利要求内容 | 产品对应内容 | 证据及位置 | 状态 | 事实/推断说明 |
|---|---|---|---|---|---|
|  |  |  |  | `A/B/C/D` |  |

状态必须使用 `A-已证实`、`B-初步支持`、`C-不相同/缺失`、`D-无法判断`。宣传材料、图片外观或功能推测通常只能形成 `B`，不能自动升级为 `A`。

### 4. 执行字面覆盖门禁

对每项权利要求分别输出：

- 存在 `C`：无论是否同时存在 `B/D`，写“现有证据不支持字面全面覆盖”；逐项披露 `B/D` 缺口，再决定是否对 `C` 特征开展等同分析。
- 不存在 `C`、但存在 `B` 或 `D`：只能写“证据不足，暂不能判断是否全面覆盖”，并列出具体补证方式。
- 全部必要特征为 `A`：可写“现有证据初步支持字面落入该权利要求”。

不得把 `B/D` 计入“覆盖特征数”，也不得用“产品要实现该功能必然具有该结构”等推断代替证据。

### 5. 等同、抗辩与有效性

- 等同：仅对 `C` 对应特征逐项适用三项比对及“无需创造性劳动即可联想到”要件，并审查禁止反悔。
- 抗辩：区分现有技术抗辩、先用权、合法来源等适用前提和证据。
- 有效性：有效性风险与侵权比对分开呈现，不使用无来源概率；权利要求被修改后重新比对。

## 输出结论模板

### 分权利要求结论

| 权利要求 | 字面覆盖 | 等同分析 | 证据门禁 | 初步结论 |
|---|---|---|---|---|
|  | 支持/不支持/无法判断 | 需要/不需要/待补充 | 通过/未通过 |  |

### 分层结论

1. **已证实事项**：仅列 `A` 状态和可回查材料事实。
2. **待核实事项**：列 `B/D` 状态、影响和补证方式。
3. **条件性法律判断**：写明适用法源、术语解释与前提。
4. **不利因素和抗辩**：不得只列支持一方的事实。
5. **人工复核点**：包括权利要求选择、法律状态、术语解释、等同和证据资格。

推荐结论措辞：

> 本报告是基于列明材料和基准日的初步分析。对权利要求〔编号〕，〔全部必要特征已由 A 级证据支持 / 因特征〔编号〕为 B 或 D 状态而证据不足 / 因特征〔编号〕为 C 状态而不支持字面全面覆盖〕。是否最终落入保护范围仍取决于证据审查、权利要求解释、等同限制及专业人员复核。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 默认只比对权利要求 1 | 比对权利人主张或任务选定的每项权利要求 |
| 把其他从属权利要求的附加特征混入当前权利要求 | 只使用当前权利要求的完整引用链 |
| 把图片推测计为已覆盖 | 标为 `B` 或 `D`，停止全面覆盖结论 |
| 整体外观或功能相似即认定侵权 | 逐项适用全面覆盖和等同规则 |
| 用不存在或未核验的案例支持结论 | 只引用可回查的法源、裁判文书和材料 |
| 以落入从属权利要求数量计算“稳定性” | 单独分析各项权利要求的有效性证据和修改后影响 |
