# 场景六：规避设计

## 适用边界

用于围绕已识别专利权利要求提出技术替代方向，不承诺“不侵权”或可制造性。开始前读取 [共用法源与结论门禁](00-legal-basis.md)，并以已经完成证据门禁的侵权/FTO 分析为输入。

## 必需输入

- 目标法域、产品版本、实施行为和计划实施时间
- 候选专利的当前法律状态、有效权利要求及同族情况
- 法源基线ID、核验日期及无效程序最后有效修改文本
- 已选定的全部相关独立/从属权利要求及逐特征比对表
- 产品性能、成本、安全、法规、供应链和工期约束

缺少有效权利要求或当前产品技术事实时，只能输出待澄清问题，不能给出规避结论。

|---|---|---|---|---|---|
|  |  |  | `A/B/C/D` |  |  |

### 2. 生成候选方案

对每个候选方案说明：

- 删除、替换或重构的具体特征及其权利要求位置
- 新技术手段、功能和效果
- 设计动机、技术可行性证据和工程副作用
- 对其他专利、法规、安全和产品需求的影响

不要只写“去掉一个特征即可规避”。即使不存在字面相同特征，也可能涉及等同；一个改动还可能落入其他独立或从属权利要求。

### 3. 重新执行法律比对

每个候选方案必须重新进行：

1. 目标专利全部相关权利要求的字面比对
2. 对差异特征的手段—功能—效果及可联想到性分析
3. 禁止反悔、现有技术和其他等同限制检查
4. 目标法域 FTO 补充检索和法律状态更新

若指南、司法解释、权利要求、法律状态、期限补偿、许可备案、产品版本或实施行为发生变化，先按 [2026年《专利审查指南》十场景影响与更新门禁](11-2026-guideline-impact.md) 刷新FTO基线，再评价候选方案。

存在 `B` 或 `D` 状态时，方案结论只能是“待工程验证/待取证”，不能标为“已规避”。
