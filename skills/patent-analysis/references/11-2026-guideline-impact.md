# 2026年《专利审查指南》十场景影响与更新门禁

> 核验基线：国家知识产权局令第八十四号《国家知识产权局关于修改〈专利审查指南〉的决定》，2025年11月10日发布，自2026年1月1日起施行；核验日期为2026年8月1日。本文不保存法院或行政机关网页链接。机器可读权威数据见 `../config/legal-source-register.json`。

## 一、状态含义

- `直接影响`：修改改变该场景需要核对的实体标准、程序规则、权利要求形态或法律状态字段。
- `条件影响`：该场景的一般判断规则未变，但在特定技术领域、申请路径、权利要求版本或状态事件出现时必须启用新规则。
- `范围外`：修改属于代理执业、费用或其他手续管理，不改变本 Skill 十场景的输出规则；具体代理业务仍应另行核验。

不得把《专利审查指南》的审查标准替代《专利法》或专利侵权司法解释。侵权、全面覆盖和等同判断继续适用 [共用法源、条款组合与结论门禁](00-legal-basis.md) 中的多条款组合。

## 三、十场景影响结论

| 场景 | 状态 | 必须增加或更新的检查 |
|---|---|---|
| 1. 单专利技术要点提取 | 直接影响 | 识别AI、大数据、比特流、植物等技术领域；核对优先权、同日双申、期限补偿、许可备案和证书记载。 |
| 2. 多专利比对 | 直接影响 | 统一同族、优先权、权利类型、有效期、许可状态和权利要求形态的比较基准。 |
| 3. 产品—专利侵权比对 | 条件影响 | 侵权司法规则未变；比特流权利要求及无效修改后的最后有效文本须纳入比对。 |
| 4. 稳定性与无效风险分析 | 直接影响 | 增加植物、AI、大数据、比特流、创造性技术贡献规则，并核对无效受理、重复请求和修改文本。 |
| 5. 自由实施（FTO）分析 | 直接影响 | 刷新权利要求版本、保护期限补偿、许可备案、法律状态和稳定性基线；旧基线不得直接沿用。 |
| 6. 规避设计 | 条件影响 | 法律判定规则未变；规避前后均须使用最新权利要求、无效修改文本和FTO状态重新比对。 |
| 7. 专利价值评估 | 直接影响 | 将期限补偿、许可备案、权属线索、审查速度和稳定性纳入估值基准日。 |
| 8. 等同原则分析 | 条件影响 | 等同司法规则未变；比特流权利要求和无效修改记录可能影响解释、说明书捐献和禁止反悔。 |
| 9. 无效宣告应对 | 直接影响 | 同时适用新的实体审查标准、受理规则、一事不再理和第4.6.4节提交要求。 |
| 10. 可视化输出 | 条件影响 | 图表逻辑不变；时间线和状态节点必须反映最后有效权利要求、期限补偿及许可备案。 |

## 四、复合问题的多条款门禁

### 1. 保护范围

共同适用《专利法》第六十四条、《专利纠纷若干规定》第十三条、《专利侵权司法解释（一）》第一条至第五条及《专利侵权司法解释（二）》第三条至第五条。先固定被主张的有效权利要求及完整引用链，再解释术语、功能性特征和公示边界。

### 2. 全面覆盖

共同适用《专利侵权司法解释（一）》第七条、《专利纠纷若干规定》第十三条及《专利侵权司法解释（二）》第五条、第七条至第十二条。一般规则与前序部分、封闭式组合物、功能性特征、使用环境、制备方法、步骤顺序和数值边界必须合并审查。

### 3. 等同原则

共同适用《专利纠纷若干规定》第十三条、《专利侵权司法解释（一）》第四条至第七条、第十四条、《专利侵权司法解释（二）》第七条至第十三条、第二十二条及《专利法》第六十七条。逐特征核对手段、功能、效果、可联想到性，并审查功能性特征、捐献、禁止反悔、数值边界和现有技术。

### 4. 无效宣告

共同适用《专利法》第三十三条、第四十五条、第四十六条，《专利法实施细则》第七十二条、第七十三条，以及《专利审查指南》第四部分第三章第2.1节、第3.2节、第3.3节、第4.6.1节至第4.6.4节。实体理由还应结合《专利法》第五条、第九条、第二十二条、第二十五条、第二十六条及相应指南章节。

### 5. FTO

共同适用《专利法》第十一条、第六十四条、第六十七条、第七十五条、第七十七条，《专利侵权司法解释（一）》第七条、第十四条及《专利侵权司法解释（二）》第二十一条至第二十五条。指南负责核验权利要求形成、修改和状态字段，不能替代侵权行为、保护范围和抗辩规则。

## 五、FTO法源与状态刷新门禁

每次FTO至少记录：目标法域、产品版本、实施行为、检索截止日和法律状态基线。然后逐项核验：

1. 法源效力状态、指南施行版本和司法解释修订状态；
2. 目标法域同族、最后有效权利要求版本及无效修改文本；
3. 法律状态查询日、专利权期限补偿和许可备案状态；
4. 产品、供应链行为、目标法域和检索截止日是否发生变化。

出现下列任一情形时必须刷新：分析基准日晚于法源核验日；法律或指南修改；权利要求经授权确权程序修改；法律状态、权属或许可变化；产品版本、实施行为、目标法域或检索截止日变化。

刷新未完成时，停止风险评级，只输出补充或核验清单。不得把旧检索、旧登记簿状态或旧权利要求直接迁移为当前“低风险”结论。

## 六、维护步骤

1. 先人工核对正式法源名称、条款、发布日、施行日和效力状态；内部检索记录只作复核底稿。
2. 更新 `../config/legal-source-register.json` 的法源、条款组、修改项、十场景影响和FTO触发条件。
3. 运行 `python3 scripts/check_legal_sources.py --expected-version <版本号>`；任何URL、未知状态、无效日期、缺场景或复合问题退化为单条款均应失败。
4. 同步本文件、受影响场景模板、评测断言、`CHANGELOG.md` 和发布版本。
5. 对具体案件重新核对正式文本、分析基准日、权利要求版本和法律状态；登记表通过不等于案件法律结论正确。
