# 轻量检索场景

以下是路由示例，不是每次必须执行的步骤。普通检索无需填写矩阵／JSON。2026-09-22 的 API 观察只说明这些样本中的行为，不代表稳定召回率。

## 明确法条

“民法典第692条是什么？”直接详情获取法名＋条号。核对文本及效力信息即可，不先生成案例研究计划，不为凑案例再查询。

## 员工离职与客户名单

“员工离职后带走客户名单并联系原客户，如何认定商业秘密侵权？”适合案例语义检索。检查客户信息具体内容、保密措施、取得和使用方式；不能将劳动关系、竞业限制、商业秘密侵权混作同一问题。

本轮一次语义返回已包含否定和支持侵权的候选；不必为了“正反各一条”机械再检索。只有准备引用的裁判要旨缺少原文支持时，才针对该来源核验；不宣称已完成全文核验。

## 房屋过户与尾款

“合同约定过户与付尾款同时进行，卖方能否因未付尾款拒绝过户？”先比较每份候选的履行顺序。

本轮语义高排名候选中有“先过户后支付余款”，还有“迁户口后付尾款”，都不能直接回答同一问题。需要更对位裁判时可试“房屋买卖 过户 尾款 同时履行”的关键词；仍须阅读法院理由，不能用关键词命中代替对位审查。历史案例引用旧法不等于旧法当然可用于当前事实。

## 房屋租赁保证金

“租赁合同提前解除能否不退全部保证金？”先确认是什么租赁；未知时可以明确以普通房屋租赁为假设，不能静默补成已知事实。

本轮宽泛表述召回融资租赁、海商法和行业指引；补入普通房屋租赁、违约金性质及调减争点后得到更对位候选，但第一名仍是商品房买卖特别规则。应核对规范适用范围，再按需要精确取得民法典和合同编通则解释，不能把商品房买卖规则直接用在租赁上。

保证金是否具有违约金性质、是否还承担其他担保功能，需结合条款和实际结算；查询表达中的法律假设不能直接变成报告结论。

## 多争点深度研究

仅当确需比较多条请求权路径、决定性证据缺口或相互冲突的规则时加载 [深度研究](07-research-middleware.md)。已有分析报告就复用相关部分。简单问题多写几段事实，不是升级理由。
