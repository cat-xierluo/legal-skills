# 只在有缺口时修正查询

先判断问题出在哪里，再改词。不要默认扩展同义词、固定凑 4–6 个词，或把每个问题同时跑语义与关键词。

## 按机制表达

- 语义：一句自然语言，保留主体关系、决定性行为／顺序和要判断的法律后果。不要粘贴全案材料。
- 关键词：少量必须共同出现的词；词过多的 AND 可能漏检。普通 CLI 默认 AND，`--expand` 会在未指定模式时切成 OR，可能增加噪声，按需使用。
- 详情：已有法名条号／案号就精确定位，不再次宽泛语义搜索。
- 筛选字段：只使用当前工具支持的字段。未知地域、时期或案由不要猜填。

## 修正动作与风险

| 首轮表现 | 可以尝试 | 必须注意 |
|---|---|---|
| 只有同主题近邻 | 加入决定性事实／排除歧义 | 不虚构用户未提供的事实 |
| 没找到文字表述不同的规则 | 替换一个法律概念或选语义检索 | 不堆叠整个同义词表 |
| 关键词零命中 | 去掉一个过窄词，或改语义检索 | 零命中不等于无依据 |
| 宽泛规范太多 | 定位法名条号或采用已知效力筛选 | 有案涉旧事实时不能仅保留现行法 |
| 案例事实相似但裁判理由不同 | 用裁判用语／援引法条字段复检 | 当事人主张不等于法院认可 |

法律术语与行业术语没有固定优先关系，以能表达当前争点为准。更新法律概念是待验证的假设，不是提前作出有利于一方的定性。一次返回已足够时停止；不要为了执行这些技巧而追加查询。
