## 法律检索报告 · 7 节设计原理（"结论先行"规约）

> 本文件仅适用于 schema 1.0 深度报告。普通报告使用 focused 四节简版，见 [报告生成](03-report-consolidation.md)，不要为遵守本篇升级普通任务。
> 注意：`templates/legal-research-report.md` 是可维护的模板参考；`yd_search.py` 当前用代码内 f-string 渲染。
> 本文件描述的是**结构与设计动机**，与运行时具体格式解耦。

### 设计原则

- 用户最想知道最终结论 → 结论提前到第 3 节
- 法条和案例只是核实材料 → 只有经 Agent 精选的依据才放到第 6 节
- 原始召回是数据底稿 → 只保留归档和调用轨迹，不复制正文
- 节号从 1 重新编号（案情=1，结论=3，精选依据=6，轨迹=7），
  体现"结论在第 3 节"的视觉位置

### 反例（曾出现过的旧版结构，避免回退）

- 案情 → 目的 → 思路 → 检索结果 → 分析 → 结论
- 用户反馈：检索结果（法条案例）全是"核实材料"，要翻到最后才看到结论 → 太累
- 新版：结论放到第 3 节，用户看完 3.1-3.4 就能得到 80% 答案

### 7 节标准骨架

#### 1. 案情简介

当事人 / 争议焦点 / 当前阶段（最少必要）

#### 2. 检索目的与问题

本次检索要回答的法律问题（1-3 个核心 Q）

#### 3. 检索结论 ⭐

**用户最先读到的内容**：

- 3.1 一句话定性（"能做/不能做" + 法律依据）
- 3.2 核心论点的判例支撑速查（表格，30 秒内 get）
- 3.3 风险点（诚实告知，不要只说好的）
- 3.4 后续行动（具体可执行的步骤）

#### 4. 分析与判断

涵摄矩阵摘要 / 抗辩应对 / 法条适用 / 诉讼请求结构 / 证据缺口

#### 5. 检索思路与方法

命题—检索缺口—查询矩阵 / 筛选条件 / 复检顺序 / 纳入门槛

#### 6. 精选法律依据与案例

- 6.1 规范性法律依据（按核心／补充和法律位阶排序）
- 6.2 精选司法案例（指导性／典型／普通案例）
- 6.3 其他核实材料

第六节只读取 `selected-sources.json`。案例不得混入规范性法律依据；`LOW/MISMATCH`、未核验、无命题映射的来源不得进入。

#### 7. 未解决问题、排除统计与原始轨迹

披露未解决命题、排除数量和每条 per-call 报告链接；不复制其检索结果正文，也不在报告中重列无关候选标题。

### 质量要求

- 结论区必须能独立阅读：3.1-3.4 应先回答问题，再引导读者看底稿
- 核心依据用表格速查：避免把法条和案例堆给读者自行归纳
- 方法区保留检索痕迹：写清关键词、筛选条件、平台、时间、纳入规则
- 精选区只放支撑材料：每条必须说明对应命题、本案适用理由、核验说明和溯源信息
- 原始召回不得直出：向量结果、endpoint 分组和后端分数都不能替代 Agent 法律相关性审查
- 风险必须明示：包括不利类案、法律适用分歧、地域差异、时效或证据缺口
