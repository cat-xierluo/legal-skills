# legal-case-analysis

通用法律分析 Skill。用于把零散案件材料整理成可验证、可检索、可论证、可复用的法律分析结果。

本技能首先是法律分析引擎，其次才按需要生成报告、咨询答复、客户说明或检索任务清单。法律分析可以作为其他 Skill 的前置步骤使用。

本技能不绑定具体案由。具体领域规则通过案件材料、法律检索结果和用户目标动态补足。

## 核心原则

1. 先整理事实，再适用法律。
2. 先区分证据与陈述，再形成判断。
3. 先用 `yuandian-law-search` 完成基础法律检索，再基于检索结果进行法律分析。
4. 先提出检索问题，再引用法律依据。
5. 诉讼场景优先使用要件式分析：请求权基础、构成要件、事实、证据、证明责任和抗辩逐项对应。
6. 每个重要结论都应对应事实来源、证据来源或检索依据。
7. 材料未提及的信息，标注“未提及”或“待补充”，不得自行补全。
8. 对争议材料同时评价真实性、关联性、合法性和证明目的。
9. 对涉及时效、期间、新旧法、司法解释变化的问题，必须单独校验。
10. **不得凭记忆写出具体法条条号、司法解释全称或案号**。条号必须来自本次检索结果或用户提供的材料；未经检索时只写规则内容与法律名称（如「著作权法关于法定赔偿的规定」），并标注「条号待检索」。这条适用于报告全文，不限于管辖章节——凭记忆的条号看起来最专业，却是最危险的错误。

## 输入

可接受以下一种或多种输入：

- 案件概述、咨询记录、委托人陈述。
- 合同、函件、付款凭证、登记资料、裁判文书、执行材料。
- 证据目录、聊天记录、录音转写、会议纪要。
- 法条检索结果、案例检索结果、法律研究报告。
- 用户指定的分析目标，例如“评估是否起诉”“生成法律分析报告”“形成客户说明”。

如果材料是 PDF、图片或扫描件，先使用 MinerU OCR、PaddleOCR 或其他文档转换工具转为 Markdown 后再分析。

## 输出

默认输出 Markdown。是否生成正式报告取决于用户目标；很多场景只需要分析底稿、咨询答复或供其他 Skill 使用的分析结论。

### 脱敏输出模式（场景化可选）

**默认不做强制脱敏。** 本 Skill 面向真实办案：材料本就要提交法院、仲裁或客户，原样使用真实主体与地名是分析准确性的前提，强行脱敏反而会失真、丢失连接点与管辖判断所需的地域信息。因此**除非用户明确要求，否则直接用真实信息输出**。

仅当用户声明用于**课程、竞赛、公开演示、案例分享、内部培训或对外公开**时，才开启脱敏输出模式（先读 `references/anonymization-output.md` 再动笔）：

- 匿名化当事人姓名、公司名、联系方式、住址、住所地/经营地、行政区划等可直接识别或可组合识别主体的字段。
- 地域抽象到「某市」或「A 地」；区/县及以下颗粒度（含「某区」「某县」「某街道」）一律不出。
- 保留法律关系、事实结构与争议焦点——这些是分析价值所在，不得因脱敏丢失。
- 脱敏不改变"材料未提及信息标注未提及/待补充"与"事实与陈述区分"的核心原则（见核心原则第 2、6、7 条）。

### 安全底线（任何场景都适用，与脱敏模式无关）

以下**不可逆敏感字段**无论是否开启脱敏模式，都不应原样输出到对外可见内容：身份证号、银行账号、私密个人联系方式（私人手机号/私人邮箱）、支付密码类凭证。若材料含有此类字段且输出面向外部，做掩码或留空标注「已隐去」；纯内部办案底稿可由用户自行决定是否保留。此底线不等于"全案脱敏"，仅针对极少数一旦泄露即不可逆的字段。

根据使用场景选择输出：

- 分析底稿：面向后续写作、方案生成、诉讼准备或内部讨论，突出事实、要件、证据、检索和风险。
- 简版咨询答复：面向事实较少、目标单一的日常法律咨询，突出结论、主要理由、风险和下一步。
- 内部分析报告：面向律师团队，重事实、证据、法理、风险和策略。
- 客户说明版：面向非法律专业客户，表达更通俗，突出结论和行动建议。
- 检索任务清单：面向 `yuandian-law-search` 或 `zhihe-legal-research`。

## 工作方法

分析过程和工作方法放在 `references/` 中，按任务需要读取：

- `references/iteration-context.md`：长期迭代上下文，包括定位、边界、资源分层和后续演进方向。
- `references/analysis-engine-boundary.md`：法律分析引擎定位，以及与 `legal-proposal-generator` 等 Skill 的协作边界。
- `references/workflow.md`：完整工作流，包括目标识别、案件阶段、材料处理、检索、论证和交付检查。
- `references/report-depth-control.md`：按案件复杂度选择简版咨询、标准分析或复杂案件分阶段报告。
- `references/element-litigation-nine-step.md`：要件式诉讼分析九步法，用于**民事/民商事**诉讼和争议解决场景的分析支架。
- `references/criminal-case-analysis.md`：刑事案件分析法（**不法—有责二阶层为主干**，审查起诉骨架 + 辩护对抗检验），用于刑事案件研判、审查起诉/审查逮捕底稿、定性与量刑分析；先客观不法后主观有责，层层递进、任一层不过即出罪。
- `references/fact-evidence-extraction.md`：事实与证据抽取规则。
- `references/civil-commercial-analysis-workflow.md`：复杂民商事案件法律分析步骤。
- `references/issue-spotting.md`：法律问题识别和问题树拆解规则，含权利束型案由的权项穷尽规则（人身权项/财产权项分列）、程序路径（主/并行/后续）识别规则与管辖分析衔接。
- `references/legal-research-bridge.md`：法律检索衔接规则。
- `references/legal-research-result-ingestion.md`：用户已提供检索存档时的回填规则（状态标记、来源等级、过时拦截）。
- `references/time-effectiveness-check.md`：多时间基准下的新旧法切换与时效检查固定输出表。
- `references/argument-risk-assessment.md`：论证和风险评估规则。
- `references/anonymization-output.md`：脱敏输出模式的触发、字段清单（含地域/住所地与组合识别风险）、保留项与边界（用于课程/竞赛/公开演示）。

## 输出模板

最终交付模板放在 `templates/` 中：

- `templates/simple-consultation-answer.md`：简版咨询答复模板。
- `templates/legal-analysis-report.md`：通用法律分析报告模板，含固定落点：六之一时间效力检查（多基准 T1/T2/T3 必填）、八之三请求与金额台账（按 damages-calculation-table.md，无金钱请求写明不适用）、附录分析过程工作簿（按 analysis-workbook.md，须写实质底稿而非指针）。
- `templates/legal-research-query-list.md`：法律检索任务清单模板。
- `templates/damages-calculation-table.md`：多类别款项金额台账与重复计算风险模板（合同解除、损害赔偿场景）。
- `templates/analysis-workbook.md`：分析过程工作簿（材料清单→事实台账→问题树→检索→回填→时间效力→论证→金额→程序路径），供教学/竞赛/复盘展示过程。
- `templates/client-summary.md`：客户说明模板。
