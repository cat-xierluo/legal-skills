# 单项争点备忘录

适合用户只问一个会改变办案决定的法律问题，例如合同条款是否适用、某一抗辩是否有证据支持、某一程序条件是否具备。把足以改变答案的前置问题并入同一备忘录。用户要综合研判多个请求、多个独立争点或全案救济路径时，走[综合研判流程](workflow.md)。

## 分析顺序

1. 写明要回答的问题、使用对象及预期决策。只确认会影响本争点的法域、时间、程序阶段和当事人立场。
2. 区分已证实、仅有陈述、存在冲突和缺少材料的事实。逐项注明文件及页码、条款或段落定位。诉讼中进一步区分证明对象、证明责任和现有证据能证明的范围。
3. 按[检索成果回填](legal-research-result-ingestion.md)复用已校准的法源和类案，对决定性缺口定向补核。分别说明规范效力、时间适用与类案的参考限度。摘要和转述用来定位原文。标明核验范围，必要时按[时间效力规则](time-effectiveness-check.md)核对生效与适用时间。
4. 对每个决定性规则写出哪些事实支持或欠缺该条件。对照最有力的相反解释或抗辩，并说明哪份材料、哪条规则或哪个时间点会区分两种判断。
5. 按可使用程度收口。可用于**文书草稿**的结论应有可核事实与法源。依赖条件的判断把条件与结论写在一起。存在决定性缺口时，标为内部判断或待核，给出具体补证或检索动作。未能核验法源原文时保留检索命题，沿用主流程的条号与引用纪律。

## 建议交付结构

| 部分 | 内容 |
|---|---|
| 问题与短答 | 一句可回答的问题、当前判断及关键限制 |
| 决定性事实与依据 | 事实状态、原件定位和可回查的规则或类案 |
| 适用与反方论证 | 关键条件如何对应证据，什么情况会改变判断 |
| 使用边界与下一步 | 可进入草稿的句子、所带条件、待核事项及优先动作 |

主文应可独立审阅。用户需要交接给文书或服务方案时，可在末尾附一段摘要，沿用事实和法源定位，并保留原有条件。
