# 多类型材料处理清单

## 处理原则

1. 先建材料清单，再做预处理，避免边看边丢来源。
2. 先处理容器类输入，再处理其中的实际材料文件。
3. 先识别内容和命名依据，再用内部命名工作表执行整理。
4. 不在本 skill 内做案件事实、争议焦点或证明目的的分析。
5. 文件名无法确认时标注 `待识别 / 待人工确认`。
6. **能力中立**：只说明材料需要什么处理能力，不绑定具体 Skill、模型、服务或命令。
7. **按需注解**：自解释文件只保留可回溯的提取文本，需上下文文件再追加注解。
8. **三层存储**：源材料目录放人工交付物；运行时 archive 只放结构化元数据；解压结果等真实材料副本进入独立 work 目录。Skill 包内 archive 永远保持空骨架。
9. **局部 registry**：元数据 manifest 同时维护 `materials`、`material_sets`、`variants`、`processing_runs`、`follow_up_candidates`，源目录 Markdown 只展示 `display_code`。

## 工具中立的处理路由

本 Skill 不检测 PDF 文字层，也不执行 OCR、ASR、视觉理解、网页读取或办公文档解析。把待处理材料交给当前环境中合适的可用能力，由该能力自行判断直接提取、文字识别、视觉补充或其他处理方法。

外链或网页任务只有在执行能力能证明满足以下边界时才可联网：用户已确认、仅公网 HTTP/HTTPS、DNS 结果全部公网、连接固定到已校验 IP、每跳重定向复核、单资源大小受限、仅写入显式授权目录、失败和拒绝留痕。否则导出 `need_web_capture` 任务并保持人工复核，不得降级为任意网页读取。

| 文件类型 | 所需能力方向 | 结果要求 |
|----------|--------------|----------|
| 图片 / 截图 / 扫描件 | 文字识别；必要时补充视觉理解 | 可回溯文本或视觉摘要 |
| PDF | 文档读取；不能直接读取时使用文字识别或视觉理解 | 可读文本，并记录采用的能力类型 |
| Word / WPS / 演示文稿 | 办公文档正文提取；图片型页面按需补充识别 | 可读文本或页面摘要 |
| 音频 / 视频 | 音视频转写；必要时补充关键画面理解 | 转写稿或关键画面说明 |
| 表格 / 结构化导出 | 表格或结构化数据读取 | 字段、工作表和数据说明 |
| URL / 网页 | 满足统一网络边界的网页读取或留痕 | 来源、时间、指纹和可读正文或快照说明 |
| 已有文本 | 直接读取 | 不重复处理 |

调用方式：先用 `material_processing_handoff.py export` 取得待处理任务，再调用当前环境中能满足所需能力的工具。不要引用其他能力的内部脚本路径，也不要把具体工具名称固化进本 Skill。

结果合并原则：
1. 可直接提取的原文优先于识别文本。
2. 视觉理解只补充版面、场景和非文本信息，并明确标识来源类型。
3. 不同通道冲突时保留差异并转人工复核，不自行消除冲突。
4. 处理文件写入 `work_dir`，用 `material_processing_handoff.py record` 回写结果。

失败回退策略：
- 当前能力失败时，可改用同类或替代能力重试。
- 只有部分结果时登记为 `partial`，同时进入人工复核。
- 没有生成可读结果时登记 `failed` 或 `needs_review`，记录失败原因；不得标记为完成。

## 注解判断表

| 文件类型 | 是否需要注解 | 原因 |
|----------|-------------|------|
| 版权证书、登记证 | 否 | OCR 原文已是结构化信息 |
| 合同正文 | 否 | OCR 原文自解释 |
| 判决书、裁定书 | 否 | OCR 原文自解释 |
| 投诉/举报截图 | **是** | 需要说明是谁在投诉、投诉谁、投诉什么 |
| 社交媒体帖子截图 | **是** | 需要说明帖子内容、发布者、与案件的关联 |
| 聊天记录截图 | **是** | 需要说明聊天双方、讨论主题、与案件的关联 |
| 现场或产品照片 | 视情况 | 可能需要说明可见对象和拍摄背景，不推断证明目的 |

## 材料类型处理表

| 材料类型 | 预处理动作 | 重点提取信息 | 建议产物 | 风险提示 |
|----------|------------|--------------|----------|----------|
| 音频 / 视频 | 转写或识别关键画面 | 文件主题、录制对象、可确认日期 | 命名依据 + 整理后文件名 | 不在本阶段深入分析发言内容 |
| 录屏 / 画面视频 | 转写音轨，必要时识别关键画面 | 页面标题、操作对象、系统名称 | 画面说明 + 整理后文件名 | 只听音频可能漏掉画面内容 |
| 聊天记录 | 识别聊天对象、导出格式、时间范围 | 会话类型、聊天对象、时间段 | 命名依据 + 待确认项 | 截图不完整时，不应自行补全文义 |
| 图片 / 截图 | OCR + 视觉理解，失败时互相回退 | 画面类型、可见文字、主体、金额、日期 | 图片说明 + 整理后文件名 | 看不清就标待识别 |
| 文本型 PDF | OCR 或文本提取 | 标题、首页、目录、落款 | PDF 命名依据 | 注意页眉页脚不要误判为标题 |
| 扫描件 PDF | OCR | 首页标题、抬头、落款、页数 | OCR + 整理后文件名 | 大 PDF 不宜逐页视觉识别 |
| Word / WPS | OCR 或文档正文提取 | 标题、首段、落款 | 文档说明 + 整理后文件名 | `.doc` 兼容性可能较差 |
| 表格 / 清单 | Python 直接读取 | 工作表名和列名 | 表格说明 + 整理后文件名 | 不要只看首个工作表 |
| 邮件材料 | 提取邮件头、主题、附件关系 | 邮件主题、发件人、日期、附件 | 邮件说明 + 整理后文件名 | 附件与正文关系不能丢失 |
| 演示文稿 | OCR 或文稿提取 | 页标题与封面 | 页面说明 + 整理后文件名 | 图片型页面可能仍需视觉识别 |
| URL / 网页 | 读取页面标题、域名、必要时截图 | 页面标题、来源网站、访问主题 | 网页说明 + 整理后文件名 | 网页内容可能变化，需留痕 |
| Markdown / txt | 读取标题和首段 | 文本主题、来源说明 | 文本说明 + 整理后文件名 | 链接和附件可能失效 |
| JSON / XML / CSV 导出 | 识别字段结构 | 导出来源、数据类型、时间字段 | 字段说明 + 整理后文件名 | 字段名不直观时要先解释含义 |

## 容器类材料处理表

| 容器类型 | 首步动作 | 重点记录信息 | 风险提示 |
|----------|----------|--------------|----------|
| 案件目录 / 文件夹 | 扫描目录树并建立相对路径 | 原始路径、目录层级、文件总数 | 多案件混放时要先分案 |
| 压缩包 | 解压后保留原包文件 | 压缩包文件名、解压目录、内部文件数量 | 不要解压覆盖原文件 |
| 多层压缩包 | 逐层展开 | 父包 -> 子包 -> 文件来源链 | 容易丢失内部文件出处 |
| 导出包 / 下载包 | 识别内部结构 | 导出来源、导出时间、附件关系 | 常出现重名文件或残缺导出 |

RAR/7z 需要本机外部解压器；只有用户确认后才传入 `--allow-external-extractor`。zip/tar 在解压前检查成员数量、展开体积、路径穿越和特殊文件。

## 统一识别字段

处理任何材料时，优先关注以下字段：

- 材料类型
- 可见标题 / 文件标题
- 可确认主体
- 可确认日期或时间范围
- 可确认金额或编号
- 来源容器或导出包
- 整理后文件名
- 是否需要人工确认

## 聊天记录专项提醒

对于微信、飞书、短信等聊天材料，本 skill 只做整理命名，不做对话事实分析。建议至少识别：

- 发言人
- 发言时间
- 聊天对象
- 截图 / 导出时间范围
- 是否截图不完整
- 是否含语音、图片、文件等附件线索

如果只有截图，没有完整导出记录，应在报告中明确：

- 是否缺少聊天前后文
- 是否缺少头像 / 名称 / 时间条信息
- 是否存在拼接图或裁切图风险

> 对挂外链的 Cubox / 微信 / 企微 / 钉钉聊天 HTML 导出件，跳到下一节「chat-html 导出件专项提醒」。

## chat-html 导出件专项提醒

对于 Cubox Pro / 微信 / 企微 / 钉钉等导出的聊天 HTML（`<a href>` 挂外链下载、`<img>` 挂图床、`<video>` 挂视频）走 chat-html 子路径：

Step 1：用 `recognize_chat_html()` 判断是否进入 chat-html 子路径。
Step 2：用 `extract_external_resources()` 抽取外链下载/图片/视频三类。
Step 3：**先走 dry-run**：显式传入 `--chat-html-dry-run`，输出运行时元数据 `archive/<run>/dryrun_manifest.json`，人工核对清单。
Step 4：律师确认后用 `--chat-html-download` 真下载到源目录 `外部资源/`。
Step 5：材料清单末尾自动追加"外部资源抽取对账"小节。

## 网页材料专项提醒

网页材料通常用于文件命名和留痕，应识别：

- 页面标题
- 域名 / 平台
- 页面主题
- 访问或截图时间
- 是否需要保存截图

本 skill 不判断网页内容的证据效力。
