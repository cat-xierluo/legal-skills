# 材料来源矩阵

## 使用目的

本表用于回答两个问题：

1. 这个 skill 现在能接哪些材料
2. 每类材料进入后，第一步应该怎么处理

在案件材料整理中，先区分**容器类输入**与**文件类输入**。容器类输入先拆包，文件类输入再按格式分流。

## 一、容器类输入

| 来源类型 | 常见形式 | 首步动作 | 备注 |
|----------|----------|----------|------|
| 案件目录 | 单个文件夹、项目目录、桌面材料目录 | 扫描目录树，按相对路径编目 | 适合直接建立材料清单 |
| 压缩包 | `zip`、`rar`、`7z`、`tar`、`tar.gz` | 先解压，再记录父子来源关系 | 保留原包，不覆盖 |
| 多层压缩包 | 压缩包内套压缩包 | 逐层展开并记录来源链 | 防止内部材料失去出处 |
| 导出包 | 微信导出、飞书导出、邮件归档、网盘打包 | 先识别内部结构，再分类处理 | 通常含截图、JSON、HTML、附件 |
| 混合下载包 | 从云盘、聊天软件批量下载的附件集合 | 先按案件 / 来源 / 日期拆分 | 常出现重名文件，需要保留原路径 |

## 二、文件类输入

### 1. 音视频类

| 材料类型 | 常见格式 | 主要处理方式 | 输出方向 |
|----------|----------|--------------|----------|
| 语音文件 | `mp3`、`wav`、`m4a`、`aac` | 转写或识别基本主题 | 命名依据、归类依据 |
| 视频文件 | `mp4`、`mov`、`mkv` | 先识别音轨或关键画面摘要 | 命名依据、归类依据 |
| 录屏文件 | 屏幕录制、操作录屏 | 转写音频 + 摘录关键画面节点 | 页面对象、操作对象、命名依据 |
| 在线视频链接 | 短视频、网课片段、直播回放 | 先按统一网络边界下载，再识别内容主题；能力不满足时保留人工复核任务 | 与链接来源、下载状态和失败原因绑定记录 |

### 2. 聊天与通信类

| 材料类型 | 常见格式 | 主要处理方式 | 输出方向 |
|----------|----------|--------------|----------|
| 聊天截图 | `jpg`、`png` | 视觉识别 / OCR，补充聊天对象和时间范围 | 命名依据、待确认项 |
| 聊天导出文本 | `txt`、`html`、`json`、`xml` | 识别聊天对象、导出范围和附件结构（**对挂外链的 chat-html 导出件，跳到下一行 chat-html 子路径**） | 命名依据、归类依据 |
| chat-html 导出件 | html（Cubox/微信），json | 识别输入形态后进入 chat-html 抽取子路径：抽取三类外链资源、干跑清单、再真下载到 `外部资源/` 子目录 | 命名依据、归档依据、对账依据 |
| 短信 / 通话记录导出 | 文本、截图、CSV | 识别字段和时间范围 | 命名依据、归类依据 |
| 邮件 | `eml`、`msg`、导出 PDF、截图 | 提取邮件头、主题、附件关系 | 命名依据、附件对应关系 |

### 3. 文档与证据文件类

| 材料类型 | 常见格式 | 主要处理方式 | 输出方向 |
|----------|----------|--------------|----------|
| 文本型 PDF | `pdf` | 读取标题、首页、目录、落款 | 命名依据、归类依据 |
| 扫描件 PDF | `pdf` | 视觉识别或 OCR 后确认标题 / 首页 | 命名依据、待确认项 |
| Word / WPS | `doc`、`docx`、`wps` | 读取标题、目录、首段、落款 | 命名依据、归类依据 |
| 纯文本说明 | `md`、`txt`、`rtf` | 读取标题和首段 | 命名依据、归类依据 |
| 表格 | `xls`、`xlsx`、`csv` | 提取工作表名、列名和数据主题 | 命名依据、归类依据 |
| 演示文稿 | `ppt`、`pptx` | 提取封面、页标题、图表主题 | 命名依据、归类依据 |
| 结构化导出 | `json`、`xml`、`csv` | 识别字段含义和导出来源 | 命名依据、归类依据 |

### 4. 图像与网页类

| 材料类型 | 常见格式 | 主要处理方式 | 输出方向 |
|----------|----------|--------------|----------|
| 图片 / 照片 | `jpg`、`png`、`heic` | 视觉识别 / OCR | 命名依据、归类依据 |
| 网页链接 | URL | 在满足统一网络边界的前提下读取标题、域名、必要时截图；否则导出待处理任务 | 命名依据、页面留痕、访问状态 |
| 小程序 / H5 页面留痕 | 截图、录屏、分享链接 | 截图 + 页面主题 + 访问来源记录 | 命名依据、页面留痕 |

## 三、推荐处理顺序

1. 先处理容器：目录、压缩包、导出包
2. 再处理难命名材料：图片、截图、扫描件、PDF、音视频
3. 最后基于内容理解执行归类整理，回更新所有文档引用

## 四、容易遗漏但应纳入的材料

- 压缩包内部的附件目录
- 邮件附件与正文之间的对应关系
- 聊天记录中的语音消息
- Excel 中的多工作表数据
- 视频中的静态画面证据
- 导出包中的 `json` / `xml` 元数据文件
- chat-html 导出件里的外链文件（PDF/图片/视频）

## 五、风险提示

- 容器类输入保留原始来源关系，否则后续无法追溯
- 表格、结构化导出和邮件头常常比正文更有整理价值，不应忽略
- 视频和录屏不能只看音频，必要时要记录关键画面节点
- 压缩包内文件重名很常见，整理时保留相对路径或父级展示编号
